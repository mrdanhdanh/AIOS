# TASK-223 — N5 Learning Website built THROUGH AIOS (proof of philosophy)

Demonstrates-AIOS: true

## Objective
Prove the AIOS philosophy — *"even a weak model must still do the job accurately,
because AIOS (not the model) does the real work"* — by building the N5 Japanese
learning website **through the AIOS Runtime/Tool/Capability path**, not by hand.

This task is the corrected successor to TASK-222, which was a "system test" that
explicitly stated *"No AIOS runtime dependency"* and still reached DONE. TASK-223
closes that loophole: it declares `Demonstrates-AIOS: true`, which activates the
new `runtime_utilization` gate (fail-closed).

## Scope
- **In scope:**
  - An AIOS **tool** `aios.tool.website.n5_builder` that *generates* the site
    (index.html, css, js/data.js, js/app.js) and writes `build_evidence.json`
    (producer=`aios.*`, content_hash) — real AIOS-produced provenance.
  - A generator script `implementation/build_n5_site.py` that invokes the AIOS tool.
  - A **real behavior harness** `implementation/harness_n5.js` (Node) that executes
    the generated JS logic (quiz scoring, vocab filtering, deterministic quiz
    generation) — not just string presence.
  - `implementation/test_website.py` (pytest) that runs the AIOS build + Node harness.
- **Out of scope:** user accounts, audio, server, persistence.

## Deliverables
- `aios/tool/website/n5_builder.py` (AIOS tool)
- `aios/governance/runtime_utilization/` (new gate)
- `aios/progress/tasks/TASK-223/implementation/` (generated site + harness + tests)
- `implementation/design-system/n5-japanese-learning/MASTER.md` (persisted via `ui-ux-pro-max` skill)

## Acceptance Criteria
1. Site is generated by an AIOS tool (not hand-written); `build_evidence.json` present.
2. `build_evidence.json.producer` starts with `aios`; `content_hash` present.
3. Node harness verifies behavior: VOCAB>=100, GRAMMAR>=10, filter/quiz logic correct.
4. `pytest` for TASK-223 passes; `runtime_utilization` gate PASSES.
5. No architecture violations in `implementation/`.

## Dependencies
TASK-222 (baseline it corrects). Builds on TASK-009 (capability), TASK-014 (tool),
TASK-029..034 (harness/verification), TASK-078 (verification integrity).
