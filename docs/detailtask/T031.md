### TASK-031 — Test Harness + Scenario + Simulation

## 1. Metadata

* **Milestone:** M6 — AIOS Harness
* **Task ID:** TASK-031
* **Tên:** Test Harness + Scenario + Simulation
* **Mục tiêu canonical:** Chạy scenario deterministic và simulation.
* **Dependency trực tiếp:** TASK-030 — Execution Verification + Evidence + Replay
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


**1. Mục tiêu**

Xây lớp Test Harness của AIOS để:

* chạy test theo `Scenario Definition`;
* hỗ trợ Simulation Mode, không tạo side effect thật;
* tái sử dụng Harness Kernel của TASK-029;
* sử dụng Verification/Evidence của TASK-030;
* biến các scenario quan trọng thành **Golden Scenario** có thể chạy lặp lại;
* hỗ trợ failure injection để kiểm tra Retry / Fallback / Recovery / Policy.

Theo master plan, Harness điều phối các loại test nhưng **không thay thế pytest/vitest**.

**2. Phạm vi**

#### 2.1 Test Harness

Cung cấp một entry point thống nhất:

```text
Harness
  → Load Scenario
  → Prepare Environment
  → Execute
  → Capture Trace
  → Verify
  → Produce Evidence
  → Report
```

Các test level cần hỗ trợ:

```text
Unit
Contract
Architecture
Integration
Workflow
Agent
Capability
Tool
Policy
Permission
E2E
Regression
```

Harness chỉ **orchestrate**, còn runner cụ thể vẫn là pytest/vitest/architecture test hoặc simulation engine.

#### 2.2 Scenario Definition

Scenario phải declarative, không hard-code logic test vào Harness.

Ví dụ:

```yaml
scenario:
  id: coding-review-001
  input:
    request: "review authentication module"

  environment:
    mode: simulation

  expect:
    intent: coding
    agent: coder
    policy: allow
    required_capabilities:
      - filesystem
      - python

  verification:
    tests_pass: true
    no_policy_bypass: true
```

Scenario phải có identity/version để có thể lưu, replay và regression.

#### 2.3 Simulation Mode

Flow:

```text
Scenario
   ↓
Orchestrator
   ↓
Planning
   ↓
Execution Graph
   ↓
Fake Runtime
   ↓
Fake Tool
   ↓
Verification
   ↓
Evidence
   ↓
Expected Result
```

Simulation **không được gọi Tool thật** và không tạo side effect ngoài phạm vi sandbox/test artifact.

Đặc biệt, simulation phải chạy được **offline và không cần LLM** khi scenario đã xác định deterministic path. Master plan xác định đây là mục tiêu trực tiếp của H3. 

#### 2.4 Golden Scenario

Scenario đạt trạng thái golden khi:

* deterministic;
* expectation rõ ràng;
* evidence đầy đủ;
* verification PASS;
* được dùng làm regression baseline.

Golden Scenario trở thành contract hành vi cho AIOS.

#### 2.5 Failure Injection

Hỗ trợ tối thiểu:

```yaml
faults:
  - target: model
    type: timeout

  - target: tool.python
    type: failure

  - target: resource
    type: exhausted
```

Dùng để xác minh:

```text
Retry
Fallback
Recovery
Policy
State transition
Final Verdict
```

**5. Acceptance Criteria**

**AC-01 — Scenario loading**

Scenario hợp lệ được parse/validate; scenario sai schema bị reject fail-closed.

**AC-02 — Deterministic simulation**

Một Golden Scenario deterministic chạy nhiều lần phải cho cùng outcome và cùng logical trace.

**AC-03 — No real side effect**

Simulation không gọi tool thật, không ghi/xóa filesystem thật ngoài test sandbox.

**AC-04 — Offline**

Scenario deterministic chạy được khi không có LLM/provider bên ngoài.

**AC-05 — Verification integration**

Mỗi Test Run phải đi qua Verification của TASK-030 và tạo Evidence Package.

**AC-06 — Failure injection**

Model timeout/tool failure/resource exhaustion phải kích hoạt đúng failure path tương ứng.

**AC-07 — Golden regression**

Golden Scenario fail → Test Harness trả `FAIL`, không được tự động chuyển thành PASS.

**AC-08 — UNKNOWN**

Scenario không đủ evidence hoặc verification không kết luận được phải trả `INCONCLUSIVE/UNKNOWN`, không promote thành PASS. Điều này phù hợp nguyên tắc Evidence-First của roadmap. 

**AC-09 — Architecture**

Không tạo Runtime implementation mới bên trong Harness; Harness chỉ gọi Runtime/Orchestrator qua contract/API.

**AC-10 — Regression**

Toàn bộ regression của M0–M5 phải PASS trước khi đóng TASK-031.

**6. Architecture Boundary**

TASK-031 phải giữ boundary:

```text
                 AIOS
                  │
          ┌───────┴───────┐
          │               │
      Runtime        Orchestrator
          │               │
          └───────┬───────┘
                  │ API/Contract
                  ▼
              Harness
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
     Test       Simulation  Evaluation
```

Harness **không được**:

```text
Harness → Runtime internal implementation
Harness → Tool trực tiếp
Harness → bypass Policy
Harness → bypass Permission
Harness → sửa State trực tiếp
```

Đây là tiền đề để giữ **INV-017 Harness Isolation** và **INV-018 Evidence First** của M6.
