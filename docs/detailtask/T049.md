**Milestone:** M8 — Ecosystem
**Mục tiêu:** Xây dựng hệ thống **Certification + Trust** cho ecosystem extension/plugin của AIOS, để phân biệt rõ extension chưa kiểm chứng, đã kiểm chứng và được AIOS tin cậy. TASK-049 kế thừa Plugin Runtime, Extension Contracts, Ecosystem Registry và Ecosystem Hub; không tạo trust/control plane song song. 

### 1. Mục tiêu chi tiết

TASK-049 phải biến:

`Extension → Registry → Hub`

thành:

`Extension → Validate → Verify → Certify → Trust State → Registry/Hub`

Certification không đồng nghĩa "extension an toàn tuyệt đối". Nó là **evidence-backed trust decision** dựa trên contract, policy, security checks, test, provenance và certification profile.

Nguyên tắc:

* **Fail-closed**
* Không có evidence → không Certification
* `UNKNOWN` không được nâng thành `PASS`
* Certification phải có provenance
* Certification có version và expiry/revalidation
* Extension không được bypass Runtime/Capability/Permission/Policy
* Certification không cấp thêm runtime permission
* Certification là trust metadata, **không phải authorization**

### 2. Phạm vi

#### 2.1 Certification Contract

Định nghĩa contract chuẩn:

```text
Certification
├── certification_id
├── extension_id
├── extension_version
├── certification_version
├── profile
├── status
├── issued_at
├── expires_at
├── issuer
├── evidence_refs[]
├── checks[]
├── policy_result
├── security_result
├── compatibility_result
├── test_result
├── provenance
└── signature
```

Trạng thái tối thiểu:

```text
UNVERIFIED
→ VERIFYING
→ CERTIFIED
→ EXPIRED
→ REVOKED
```

Nếu verification thất bại:

```text
VERIFYING → REJECTED
```

#### 2.2 Certification Profiles

Không dùng một mức trust duy nhất.

Ví dụ:

```text
UNVERIFIED
COMMUNITY
VERIFIED
CERTIFIED
CORE_TRUSTED
```

Profile phải có policy rõ ràng về:

* required checks
* required evidence
* allowed permissions
* compatibility requirements
* security requirements
* expiry/revalidation

#### 2.3 Certification Checks

Certification pipeline nên deterministic-first:

```text
Load Extension
      ↓
Manifest Validation
      ↓
Contract Validation
      ↓
Dependency Validation
      ↓
Compatibility Check
      ↓
Permission/Policy Check
      ↓
Static Security Check
      ↓
Sandbox Test
      ↓
Conformance Test
      ↓
Evidence Collection
      ↓
Certification Decision
```

LLM **không được là authority** để cấp Certification.

#### 2.4 Evidence

Mọi Certification phải truy ngược được:

```text
Certification
    ↓
Evidence Package
    ↓
Verification Run
    ↓
Extension Artifact
    ↓
Extension Version
    ↓
Source / Provenance
```

Evidence tối thiểu:

* artifact checksum
* manifest
* contract version
* dependency resolution
* permission declaration
* policy evaluation
* test results
* security scan result
* sandbox result
* compatibility result
* timestamp
* environment
* verifier version

#### 2.5 Trust Decision

Trust engine chỉ quyết định:

```text
CERTIFIED
CERTIFIED_WITH_WARNING
REJECTED
UNKNOWN
EXPIRED
REVOKED
```

`UNKNOWN` phải giữ nguyên nếu evidence không đủ.

Không được:

```text
missing evidence → assume PASS
```

### 3. Certification Boundary

Certification **không thay thế**:

* Policy Engine
* Permission Service
* Credential Broker
* Sandbox
* Runtime enforcement

Ngay cả extension đã `CERTIFIED`:

```text
Certified Extension
       ↓
Capability
       ↓
Policy
       ↓
Permission
       ↓
Sandbox
       ↓
Runtime
```

Certification chỉ là một input của trust/policy evaluation.

Ví dụ:

```text
CERTIFIED ≠ unrestricted
CERTIFIED ≠ trusted forever
CERTIFIED ≠ bypass policy
CERTIFIED ≠ bypass sandbox
```

---

### 4. Revocation

Phải hỗ trợ revoke khi:

* phát hiện security vulnerability
* artifact checksum thay đổi
* certificate hết hạn
* dependency bị compromise
* contract bị invalidate
* certification evidence bị phát hiện không hợp lệ
* extension vi phạm policy sau certification

Flow:

```text
CERTIFIED
   ↓
Security/Trust Event
   ↓
Revalidation
   ↓
REVOKED
```

Hub/Registry phải không tiếp tục quảng bá extension đã revoked như một extension trusted.

### 7. Security Requirements

Certification phải kiểm tra ít nhất:

* manifest integrity
* artifact checksum
* dependency integrity
* permission declarations
* forbidden imports/capabilities
* contract compatibility
* sandbox behavior
* policy compliance
* provenance completeness

Extension có hành vi bypass:

```text
Extension → subprocess
Extension → raw filesystem
Extension → credential
Extension → Runtime internals
```

phải bị reject hoặc đưa vào trạng thái không được certify tùy policy.

### 8. Tests

Bắt buộc:

**Unit**

* certification state machine
* profile evaluation
* expiry
* revocation
* evidence validation

**Contract**

* certification schema
* extension version compatibility
* registry/hub integration

**Security**

* modified artifact → reject
* invalid checksum → reject
* missing provenance → reject/unknown
* forbidden capability → reject
* policy violation → reject

**Evidence**

* certification → evidence → run → artifact provenance chain

**Regression**

* certification không phá Plugin Runtime
* certification không bypass Policy
* certification không bypass Permission
* certified extension vẫn bị sandbox/policy enforce

### 9. Acceptance Criteria

TASK-049 chỉ PASS khi:

1. Extension có thể trải qua verification → certification.
2. Certification có version, profile, status và expiry.
3. Certification decision chỉ dựa trên valid evidence.
4. Thiếu evidence không được tự động thành PASS.
5. Artifact thay đổi làm certification invalid/revalidation bắt buộc.
6. Revocation hoạt động và được Registry/Hub phản ánh.
7. Certification không cấp runtime permission.
8. Certified extension vẫn chịu Policy/Permission/Sandbox.
9. Certification provenance có thể replay/audit.
10. Unit + Contract + Security + Integration + Regression tests PASS.
11. Không vi phạm architecture invariants hiện có.
12. Không tạo control plane song song.

Master specification xác định TASK-049 là **Certification — Certification và trust cho ecosystem**, với yêu cầu chung phải tích hợp Runtime/Harness hiện có, có implementation/tests/docs khi cần, PASS AC + regression + invariant.
