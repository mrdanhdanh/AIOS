# TASK-015 — Plugin / Skill Execution

## 1. Mục tiêu

Hoàn thiện lớp Plugin/Skill Execution của AIOS trong M2, biến Skill thành một component có lifecycle đầy đủ, có dependency resolution, có trạng thái persistent và có khả năng chạy trong Sandbox Pool.

TASK-015 phải bảo đảm:

* Skill là extension, không phải một phần của Core.
* Skill không được bypass Runtime, Capability, Permission hoặc Policy.
* Lifecycle của Skill có thể quản lý deterministic.
* Dependency của Skill được resolve trước khi enable/execution.
* Install/Upgrade/Remove không làm hỏng certified state.
* Rollback phải đưa Skill về version/state đã được xác nhận trước đó.
* Sandbox được tái sử dụng nhưng phải reset state giữa các execution.
* Offline-first: các thao tác lifecycle cơ bản không phụ thuộc LLM hoặc Internet.
* State của Skill phải persist qua restart.

Task này là phần hoàn thiện P4 của M2, sau Tool + Capability Layer (TASK-014) và trước Architecture Hardening (TASK-016).

## 2. Phạm vi

### 2.1 Skill Contract

Skill phải có metadata/manifest tối thiểu:

* `id`
* `name`
* `version`
* `description`
* `author`
* `dependencies`
* `required_capabilities`
* `permissions`
* `resources`
* `runtime`
* `entrypoint`
* `checksum`
* `status`

Skill không được tự quyết định quyền thực thi. Các permission/resource/network requirements chỉ là declaration để Runtime/Policy xử lý.

---

### 2.2 Skill Lifecycle

Lifecycle canonical:

```text
RESOLVE
   ↓
VALIDATE
   ↓
INSTALL
   ↓
ENABLE
   ↓
[READY]
   ↓
DISABLE
   ↓
UNLOAD
   ↓
RELOAD
   ↓
UPGRADE
   ↓
ROLLBACK
   ↓
REMOVE
```

Không coi mọi trạng thái là một đường tuyến tính bắt buộc.

Các transition phải được validate theo state hiện tại.

Ví dụ:

```text
DISABLED → ENABLE
ENABLED → DISABLE
ENABLED → UNLOAD
UNLOADED → RELOAD
ENABLED(v1) → UPGRADE(v2)
FAILED(v2) → ROLLBACK(v1)
DISABLED → REMOVE
```

Transition không hợp lệ phải bị reject deterministic.

---

### 2.3 Resolve

Skill Manager phải xác định:

* Skill cần cài.
* Version phù hợp.
* Dependency trực tiếp.
* Dependency transitive.
* Version constraint.
* Conflict giữa các dependency.
* Capability requirement.
* Permission requirement.

Ví dụ:

```text
Skill A
 ├── Skill B >= 1.2
 └── Skill C ~= 2.0

Skill B
 └── Skill D >= 3.0
```

Resolver phải tạo dependency graph:

```text
A → B → D
A → C
```

Nếu graph có cycle:

```text
A → B → C → A
```

thì resolution phải `FAIL`, không được cố enable một phần.

---

### 2.4 Validate

Trước Install/Enable phải validate:

1. Manifest schema.
2. Skill ID/version.
3. Checksum/integrity.
4. Dependency compatibility.
5. Runtime compatibility.
6. Capability requirements.
7. Permission requirements.
8. Resource requirements.
9. Entrypoint.
10. Policy constraints.

`UNKNOWN` không được coi là `PASS`.

Skill thiếu checksum/integrity evidence khi policy yêu cầu phải bị reject.

---

### 2.5 Install

Nguồn Skill trong M2:

* local package/archive;
* Git;
* pip/package source.

Install phải tạo artifact/state có thể truy xuất.

Không install trực tiếp vào Core Python environment.

Nguyên tắc:

```text
Skill Package
      ↓
Validate
      ↓
Install Target
      ↓
Register
      ↓
Persist State
```

Install failure phải cleanup phần state tạm và không được làm hỏng version đang hoạt động.

---

### 2.6 Enable / Disable

`Enable`:

```text
Validate
→ Resolve dependencies
→ Check Policy
→ Check Permission
→ Prepare runtime
→ Register capabilities
→ Mark ENABLED
```

`Disable`:

```text
Stop new execution
→ Drain active execution nếu cần
→ Unregister active skill capabilities
→ Persist DISABLED
```

Disable không đồng nghĩa Remove.

Mục đích là cho phép tắt Skill tạm thời mà không mất package/state.

---

### 2.7 Unload / Reload

`Unload` phải giải phóng runtime resources của Skill nhưng giữ installation metadata.

`Reload` phải:

```text
Validate persisted state
→ Load package
→ Resolve dependencies
→ Register runtime
→ Reconnect capabilities
→ Health check
→ READY
```

Reload phải idempotent trong cùng một certified state.

---

### 2.8 Upgrade

Upgrade phải giữ version hiện tại cho đến khi version mới được validate.

Flow:

```text
Current Certified State
        ↓
Resolve New Version
        ↓
Validate
        ↓
Backup Certified State
        ↓
Install New Version
        ↓
Run Compatibility Checks
        ↓
Health Check
        ↓
Enable New Version
        ↓
Certified State v2
```

Không được:

```text
Remove v1
→ Install v2
→ phát hiện lỗi
```

mà không còn khả năng phục hồi v1.

---

### 2.9 Rollback

Rollback là capability bắt buộc của TASK-015.

Rollback phải phục hồi:

* Skill version.
* Manifest.
* Dependency resolution.
* Runtime state.
* Capability registration.
* Configuration.
* Relevant artifacts/state.

Ví dụ:

```text
Certified v1
     ↓
Upgrade
     ↓
v2 enabled
     ↓
health check FAIL
     ↓
ROLLBACK
     ↓
v1 restored
     ↓
health check PASS
     ↓
Certified v1
```

Nếu rollback cũng thất bại:

```text
ROLLBACK FAILED
→ state = FAILED / BLOCKED
→ không tự động giả định system healthy
```

---

### 2.10 Remove

Remove chỉ được thực hiện khi:

* Skill không còn active execution.
* Không có dependency còn yêu cầu Skill.
* Policy cho phép.
* State/artifact cần giữ đã được xử lý.

Remove phải không để lại registry entry "mồ côi" gây false discovery.

Evidence/audit cần thiết không được xóa chỉ vì Skill bị remove.

## 3. Sandbox Pool

### 3.1 Mục tiêu

Sandbox Pool cung cấp môi trường execution tái sử dụng cho Skill/Tool thay vì tạo container mới cho mọi lần chạy.

Kiến trúc:

```text
Skill Execution
      ↓
Sandbox Manager
      ↓
Sandbox Pool
 ┌────┼────┐
 ▼    ▼    ▼
Pool-1 Pool-2 Pool-3
```

Sandbox Pool phải hỗ trợ:

* warm-start;
* health check;
* acquire/release;
* reset state;
* idle eviction;
* resource limits;
* execution timeout;
* isolation boundary.

---

### 3.2 Sandbox Lifecycle

```text
CREATED
   ↓
INITIALIZING
   ↓
READY
   ↓
ACQUIRED
   ↓
RUNNING
   ↓
RESETTING
   ↓
READY
```

Failure:

```text
RUNNING
   ↓
FAILED
   ↓
DESTROY / RECREATE
```

Sandbox unhealthy không được quay lại pool ở trạng thái `READY`.

---

### 3.3 Reset State

Sau mỗi execution phải reset các state không được phép tồn tại giữa hai execution:

* filesystem temporary state;
* process state;
* environment changes;
* temporary artifacts;
* execution-specific variables;
* network/session state nếu sandbox hỗ trợ.

Không được để execution trước ảnh hưởng execution sau.

---

### 3.4 Resource Boundary

Sandbox phải tuân Resource/Policy hiện có:

* CPU;
* RAM;
* Disk;
* timeout;
* concurrent execution;
* network;
* filesystem scope.

TASK-015 không tạo Resource Service mới.

## 4. Plugin Isolation

Invariant chính:

```text
Plugin / Skill
      ↓
Capability
      ↓
Runtime
      ↓
Policy / Permission
      ↓
Tool / Sandbox
```

Không được phép:

```text
Plugin → Core internals
Plugin → subprocess trực tiếp
Plugin → filesystem unrestricted
Plugin → provider trực tiếp
Plugin → Runtime service implementation
Plugin → bypass Policy
Plugin → bypass Permission
```

Plugin chỉ tương tác với AIOS thông qua public contract/API được phép.

## 5. Persistent State

Skill Manager phải persist tối thiểu:

```text
skill_id
version
status
enabled
dependencies
checksum
install_source
install_location
configuration
last_transition
last_health
previous_certified_version
```

Restart AIOS phải khôi phục được trạng thái Skill.

Ví dụ:

```text
Before restart:
  coding-skill = ENABLED
  version = 1.4.0

After restart:
  coding-skill = ENABLED
  version = 1.4.0
```

Không được mặc định chuyển mọi Skill về `ENABLED` nếu persisted state là `DISABLED`.

## 6. Capability Integration

TASK-014 cung cấp Capability Layer; TASK-015 phải sử dụng layer đó thay vì tạo routing riêng.

Ví dụ:

```text
Skill
  declares:
    capabilities:
      - execute_code
      - run_tests

Capability Registry
  ↓
Capability Router
  ↓
Healthy Tool
```

Một Skill không được hard-code:

```text
execute_code → python_tool_impl
```

mà phải yêu cầu capability.

---

## 7. Policy / Permission Integration

Skill manifest có thể khai báo:

```yaml
permissions:
  - filesystem.read
  - filesystem.write

resources:
  cpu: 2
  memory_mb: 1024

network:
  enabled: false
```

Nhưng declaration không đồng nghĩa được cấp quyền.

Flow:

```text
Skill Requirement
       ↓
Policy Service
       ↓
Permission Service
       ↓
ALLOW / DENY / ASK
       ↓
Execution
```

Nếu Policy deny:

```text
Skill execution = BLOCKED
```

không được fallback sang execution bypass.

## 10. Acceptance Criteria

### AC-015-01 — Lifecycle

Tất cả lifecycle transition hợp lệ phải thực hiện được deterministic.

Transition không hợp lệ phải bị reject.

### AC-015-02 — Dependency

Skill dependency phải được resolve trước Enable.

Dependency conflict hoặc cycle → `FAIL`.

### AC-015-03 — Persistence

Skill state survive restart và phản ánh đúng trạng thái trước restart.

### AC-015-04 — Isolation

Plugin không import hoặc truy cập trực tiếp Core/Runtime implementation.

Architecture test phải phát hiện violation.

### AC-015-05 — Capability Boundary

Skill chỉ sử dụng capability contract, không hard-code implementation của Tool.

### AC-015-06 — Policy Boundary

Skill không thể execution khi Policy/Permission deny.

### AC-015-07 — Sandbox

Sandbox được acquire trước execution, release/reset sau execution.

Sandbox unhealthy không được tái sử dụng.

### AC-015-08 — Isolation Between Runs

Execution A không để lại state ảnh hưởng Execution B.

### AC-015-09 — Upgrade Safety

Upgrade failure không làm mất certified version hiện tại.

### AC-015-10 — Rollback

Rollback failure của version mới phải phục hồi được certified version trước đó.

### AC-015-11 — Offline-first

Lifecycle management cơ bản phải chạy được không cần LLM.

### AC-015-12 — Evidence

Lifecycle transition quan trọng phải có state/evidence/audit tương ứng để truy nguyên:

```text
Skill
→ Version
→ Transition
→ Run
→ Artifact
→ Result
```

### AC-015-13 — Regression

Toàn bộ test của dependency closure phải PASS trước khi TASK-015 được đóng.

## 12. Architecture Constraints

TASK-015 không được tạo:

* Runtime service mới để thay thế Runtime hiện tại.
* Permission system riêng.
* Policy engine riêng.
* Capability router riêng.
* Resource manager riêng.
* Tool registry song song.
* Plugin control plane độc lập với Orchestrator/Runtime.

Skill Manager là orchestration/lifecycle layer; enforcement vẫn thuộc Runtime + Capability + Permission + Policy.

## 14. Definition of Done

TASK-015 chỉ được `DONE` khi:

* Skill lifecycle đầy đủ và được test.
* Dependency resolution hoạt động.
* Persistent state hoạt động.
* Sandbox Pool hoạt động.
* Sandbox reset/isolation được chứng minh.
* Upgrade + rollback được chứng minh.
* Capability boundary không bị bypass.
* Policy/Permission không bị bypass.
* Plugin không chạm Core.
* Evidence/audit có provenance.
* Unit + integration + architecture + regression tests PASS.
* Không còn violation của architecture gate.
* `PROGRESS.md` và `LOG.md` được cập nhật.
* Task artifacts đầy đủ.
* Commit hoàn tất.

**Gate cuối:** `PASS` chỉ khi có evidence; `UNKNOWN` không được nâng thành `PASS`.
