## TASK-052 — World Model

**Milestone:** M9 — Autonomous
**Trạng thái:** Tiếp tục triển khai theo roadmap
**Dependency:** TASK-050 → TASK-051 → **TASK-052** → TASK-053. Nguồn master spec xác định TASK-052 có mục tiêu **“Tách world state khỏi memory”**; các deliverables/AC trong master specification hiện ở mức khung, nên phần dưới giữ đúng framing đó và mở rộng thành spec thực thi, không thay đổi mục tiêu gốc. 

### 1. Mục tiêu

Xây **World Model** như một subsystem biểu diễn trạng thái của thế giới/hệ thống mà AIOS đang tác động, **tách biệt với Memory**.

Phân biệt:

* **Memory:** AIOS nhớ những gì đã xảy ra / thông tin đã lưu.
* **World Model:** AIOS biểu diễn **trạng thái hiện tại**, quan hệ giữa các entity, trạng thái resource, goal, execution và các thay đổi quan sát được.
* World Model không trở thành một memory store thứ hai.
* World Model phải được cập nhật thông qua observation/evidence có provenance.

Mục tiêu cuối:

```text
Observation / Evidence
        ↓
World State Update
        ↓
World Model
        ↓
Current State / Relation / Constraint
        ↓
Autonomous Planner
```

### 2. Phạm vi

#### 2.1 World State Contract

Định nghĩa contract chuẩn cho:

```text
WorldState
WorldEntity
WorldRelation
WorldObservation
WorldTransition
WorldSnapshot
```

Mỗi state/observation phải có tối thiểu:

* `id`
* `type`
* `version`
* `timestamp`
* `source`
* `provenance`
* `confidence`
* `status`
* `tenant/scope` nếu execution context yêu cầu.

Không cho phép một observation không có provenance trở thành canonical world state.

#### 2.2 Entity Model

World Model phải biểu diễn các entity mà autonomous system cần biết, ví dụ:

```text
Goal
Task
Workflow
Execution
Agent
Capability
Resource
Artifact
Workspace
Project
Runtime Node
Environment
External System
```

Entity có lifecycle/state riêng và có thể liên kết với entity khác.

Ví dụ:

```text
Goal
 ├── owns → Task
 ├── depends_on → Resource
 └── produces → Artifact

Execution
 ├── executes → Task
 ├── runs_on → RuntimeNode
 └── produces → Observation
```

#### 2.3 State vs Memory Boundary

Đây là boundary quan trọng nhất của TASK-052:

```text
Memory
  = historical knowledge / recalled information

World Model
  = current modeled state + relations + transitions
```

Không được:

```text
WorldModel → VectorStore trực tiếp
WorldModel → ConversationMemory trực tiếp
Agent → World DB trực tiếp
```

Thay vào đó:

```text
Agent
  ↓
Orchestrator / World Model API
  ↓
World Model
```

Memory có thể cung cấp historical evidence cho World Model, nhưng **không đồng nghĩa Memory = World State**.

#### 2.4 Observation → State Transition

World Model phải hỗ trợ:

```text
Observation
    ↓
Validate
    ↓
Resolve Entity
    ↓
Compare Current State
    ↓
Generate Transition
    ↓
Validate Transition
    ↓
Commit New State
```

Ví dụ:

```text
Observation:
Runtime-02 heartbeat failed

Current:
Runtime-02 = HEALTHY

Transition:
HEALTHY → UNHEALTHY

New World State:
Runtime-02 = UNHEALTHY
```

Mọi transition phải truy được về observation/evidence nguồn.

#### 2.5 Snapshot

Hỗ trợ snapshot world state để:

* replay;
* debugging;
* autonomous planning;
* recovery;
* comparison giữa hai thời điểm.

```text
WorldSnapshot(t1)
WorldSnapshot(t2)

        ↓

State Diff
```

Snapshot không thay thế Execution Snapshot của Runtime.

### 3. Deterministic-first

World Model **không dùng LLM làm source of truth**.

Ưu tiên:

```text
Structured Event
→ deterministic state transition
→ validated world state
```

LLM chỉ có thể hỗ trợ:

* semantic interpretation;
* entity resolution;
* inference khi dữ liệu cấu trúc không đủ.

Nếu LLM suy luận một state mới:

```text
LLM inference
    ↓
Candidate observation
    ↓
Validation / policy / evidence
    ↓
World State
```

Không được:

```text
LLM → World State trực tiếp
```

### 4. Consistency & Conflict Handling

Khi có hai observation mâu thuẫn:

```text
Observation A:
Runtime-01 = HEALTHY

Observation B:
Runtime-01 = UNHEALTHY
```

World Model không tự động chọn giá trị chỉ vì observation mới hơn.

Phải đánh giá:

* timestamp;
* source;
* provenance;
* confidence;
* version;
* authority;
* policy.

Kết quả có thể là:

```text
RESOLVED
CONFLICTED
UNKNOWN
STALE
```

**UNKNOWN không được nâng thành CONFIRMED.**

### 5. World Model API

Contract tối thiểu:

```text
get_entity()
list_entities()
get_state()
get_relations()
apply_observation()
apply_transition()
get_snapshot()
diff_snapshots()
query_world()
```

Query phải hỗ trợ deterministic lookup trước semantic reasoning.

Ví dụ:

```text
"What runtime is executing Goal X?"
```

→ query World Model.

Không cần truy vấn toàn bộ Memory.

### 6. Integration

TASK-052 phải tích hợp với:

```text
TASK-050 Autonomous Goal Engine
TASK-051 Autonomous Planner
M5 Execution Graph
M6 Evidence/Harness
Runtime State Service
Event Service
Artifact Service

```

Flow:

```text
Execution
   ↓

   ↓

   ↓

   ↓
Autonomous Planner
   ↓
New Plan
```

World Model **không bypass Runtime, Policy, Capability hoặc Evidence**.

### 7. Deliverables

* World Model contracts.
* Entity/relation model.
* World State store/interface.
* Observation ingestion.
* State transition engine.
* Conflict/staleness handling.
* Snapshot + diff.

Master specification yêu cầu task phải có implementation, tests và docs/ADR khi cần. 

### 8. Acceptance Criteria

**AC-01 — Memory Isolation**

World Model không biến Memory thành canonical world state và không truy cập Memory implementation trực tiếp.

**AC-02 — Provenance**

Mọi world-state mutation phải truy được:

```text
World State
→ Transition
→ Observation
→ Evidence/Event
→ Source
```

**AC-03 — Deterministic Transition**

Cùng một state + cùng một observation hợp lệ phải tạo cùng transition.

**AC-04 — Conflict**

Observation mâu thuẫn không được silently overwrite state; phải tạo trạng thái conflict/unknown hoặc resolution có policy.

**AC-05 — Stale Observation**

Observation cũ không được ghi đè state mới hơn nếu policy/version rules không cho phép.

**AC-06 — Snapshot**

Có thể tạo snapshot và tính diff giữa hai world state.

**AC-07 — Query**

Planner có thể truy vấn current world state mà không cần quét Memory.

**AC-08 — Evidence**

Mọi mutation quan trọng đều tạo evidence/audit tương ứng.

**AC-09 — Architecture**

Không vi phạm Runtime-First, Capability-First, Policy-First, Evidence-First hoặc các invariant hiện hành.

**AC-10 — Regression**

Regression của toàn bộ dependency closure phải PASS trước khi task được DONE.

Master specification quy định task chỉ hoàn tất khi AC PASS, regression các milestone trước PASS và không vi phạm invariant.

### 10. Test Strategy

```text
Unit
 ↓
Contract
 ↓
Architecture
 ↓
Integration
 ↓
Harness Verification
 ↓
Regression
```

Các case bắt buộc:

1. Observation → state transition.
2. Hai observation cùng timestamp → deterministic resolution.
3. Stale observation → không overwrite state mới.
4. Conflicting observations → `CONFLICTED/UNKNOWN`.
5. Snapshot → diff chính xác.
6. Missing provenance → mutation bị reject.
7. Planner query current state.
8. Agent cố truy cập implementation → architecture gate FAIL.
9. Replay observation sequence → tái tạo cùng world state.
