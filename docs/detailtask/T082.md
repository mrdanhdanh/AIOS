## TASK-082 — Creative Domain + Vendor Integrity + Reference Asset

**Mục tiêu**

Mở rộng AIOS sang **Creative Domain** — xử lý asset sáng tạo (hình ảnh, âm thanh, video, design) với **Vendor Integrity** (xác thực nguồn vendor / model sinh asset) và **Reference Asset** (asset tham chiếu chuẩn để so sánh). TASK-082 là **creative-domain extension, không phải runtime rewrite** (dựa trên Asset Pipeline T081 + Evidence T001).

TASK-082 thuộc **M11**, ngay sau T081 (Asset Pipeline). Trọng tâm canonical: **Creative Domain + Vendor Integrity + Reference Asset**.

### 1. Phạm vi — Creative domain, không replace asset pipeline

```text
Creative Domain
├── Creative Asset Types   (image/audio/video/design)
├── Vendor Integrity       (verify vendor/model provenance)
├── Reference Asset        (golden baseline for comparison)
└── Creative Capability    (via Asset Capability Registry T081)
```

* **Creative Asset Types** — định nghĩa schema cho asset sáng tạo.
* **Vendor Integrity** — mỗi asset sinh bởi vendor/model phải có provenance (ai sinh, version, license).
* **Reference Asset** — asset tham chiếu chuẩn để so sánh quality/regression.
* **Creative Capability** — đăng ký qua Asset Capability Registry (T081).

### 2. Creative Contract

```text
CreativeAsset
├── asset_id
├── creative_type
├── vendor_id
├── vendor_provenance (signed)
├── reference_asset_id
├── license
└── evidence_ref
```

Quy tắc:

* Asset không có vendor provenance → không accept (fail-closed, Vendor Integrity).
* Reference Asset phải được duyệt (evidence) trước khi dùng so sánh.
* Mọi creative asset có provenance (T001 Rule 5).

### 3. Creative Safety

* **Vendor integrity fail-closed** — thiếu provenance → reject.
* **Reference integrity** — reference thay đổi qua evidence/approval.
* **License check** — asset vi phạm license → reject.
* **Evidence required** — mọi creative asset có provenance.
* **Deterministic verify** — cùng asset + cùng reference → cùng so sánh.
* **No parallel creative system** — dùng Asset Pipeline (T081) + Evidence (T001).
