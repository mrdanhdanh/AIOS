# TASK-027 — Execution Graph

Nguồn canonical xác định TASK-027 có mục tiêu: **biên dịch Execution Plan thành DAG acyclic**; task thuộc M5 và đứng sau TASK-026, trước TASK-028 Parallel Scheduler. 

## 1. Mục tiêu

Xây **Execution Graph Compiler** chuyển:

```text
ExecutionPlan
      ↓
Dependency Resolution
      ↓
Graph Construction
      ↓
Cycle Detection
      ↓
Graph Validation
      ↓
ExecutionGraph / DAG
```

Output phải là một graph **acyclic, deterministic, policy-aware và executable bởi Scheduler**, nhưng TASK-027 **không thực hiện scheduling**.

# 3. Execution Graph Contract

Graph tối thiểu:

```yaml
execution_graph:
  graph_id: ...
  plan_id: ...
  version: 1

  nodes:
    - node_id: T1
      task_ref: ...
      state: PENDING

    - node_id: T2
      task_ref: ...

  edges:
    - from: T1
      to: T2

  entry_nodes:
    - T1

  terminal_nodes:
    - T3
```

### Node

Mỗi node phải tham chiếu tới task trong `ExecutionPlan`.

```text
GraphNode
- node_id
- task_ref
- dependencies
- dependents
- state
- resource_requirements
- capability_requirements
- policy_requirements
```

### Edge

```text
GraphEdge
- source
- target
- dependency_type
- condition
```

Không được tạo edge trùng hoặc self-loop.

---

# 4. Graph State

TASK-027 cần định nghĩa lifecycle state để TASK-028 sử dụng:

```text
PENDING
READY
RUNNING
SUCCEEDED
FAILED
BLOCKED
CANCELLED
SKIPPED
```

Nhưng Graph Compiler **không tự chuyển state execution**.

Sau compile:

```text
all nodes = PENDING
```

Scheduler mới quyết định node nào chuyển `READY`.

---

# 5. Graph Compilation

Pipeline:

```text
ExecutionPlan
      ↓
Schema Validation
      ↓
Node Materialization
      ↓
Edge Materialization
      ↓
Reference Validation
      ↓
Duplicate Detection
      ↓
Self-loop Detection
      ↓
Cycle Detection
      ↓
Entry/Terminal Detection
      ↓
Graph Invariants
      ↓
ExecutionGraph
```

Nếu validation fail:

```text
GRAPH_INVALID
```

và không được chuyển Scheduler.

---

# 6. Dependency Compilation

Ví dụ Plan:

```text
T1
T2 depends on T1
T3 depends on T1
T4 depends on T2 + T3
```

Graph:

```text
       T1
      /  \
     T2  T3
      \  /
       T4
```

Edges:

```text
T1 → T2
T1 → T3
T2 → T4
T3 → T4
```

TASK-027 phải giữ nguyên semantics dependency từ Plan, không tự ý thay đổi dependency để "tối ưu".

---

# 7. Cycle Detection

Graph bắt buộc acyclic.

Ví dụ:

```text
T1 → T2
T2 → T3
T3 → T1
```

phải reject:

```text
GRAPH_INVALID
reason = CYCLE_DETECTED
```

Algorithm có thể dùng:

* DFS;
* Kahn's algorithm;
* hoặc implementation tương đương.

Acceptance quan trọng là:

```text
cycle → deterministic detection → fail-closed
```

---

# 8. Self-loop

```text
T1 → T1
```

phải reject ngay:

```text
SELF_DEPENDENCY
```

Không chuyển thành dependency hợp lệ.

---

# 9. Missing Node

Nếu Plan chứa:

```text
T1 → T99
```

nhưng `T99` không tồn tại:

```text
MISSING_NODE_REFERENCE
```

Graph không được compile.

---

# 10. Duplicate Node

Nếu có:

```text
T1
T1
```

phải reject:

```text
DUPLICATE_NODE
```

Không tự overwrite node cũ.

---

# 11. Duplicate Edge

Nếu input chứa:

```text
T1 → T2
T1 → T2
```

Graph compiler phải normalize hoặc reject theo contract.

Khuyến nghị:

```text
duplicate edge
→ deterministic normalization
→ một edge duy nhất
```

nhưng phải ghi nhận trong validation/evidence.

---

# 12. Entry Nodes

Entry node là node không có incoming edge.

Ví dụ:

```text
T1 → T3
T2 → T3
```

thì:

```text
entry_nodes = [T1, T2]
```

Các entry node có thể trở thành candidate `READY` cho Scheduler.

---

# 13. Terminal Nodes

Terminal node là node không có outgoing edge.

Ví dụ:

```text
T1 → T2 → T3
```

thì:

```text
terminal_nodes = [T3]
```

Nếu graph có nhiều terminal nodes, tất cả phải được ghi nhận.

---

# 14. Topological Order

Graph phải có thể tạo topological ordering.

Ví dụ:

```text
T1 → T2
T1 → T3
T2 → T4
T3 → T4
```

Một ordering hợp lệ:

```text
T1
T2
T3
T4
```

Nhưng không được yêu cầu duy nhất một ordering nếu graph cho phép parallelism.

Điểm quan trọng:

```text
Dependency correctness
>
Ordering preference
```

Scheduler TASK-028 mới quyết định execution order thực tế.

---

# 15. Parallelism Boundary

TASK-027 **phát hiện dependency**, không chạy parallel.

Ví dụ:

```text
T1
├── T2
└── T3
```

Graph chỉ thể hiện:

```text
T1 → T2
T1 → T3
```

TASK-028 mới quyết định:

```text
T2 || T3
```

nếu resource/policy cho phép.

---

# 16. Conditional Dependency

Nếu Plan hỗ trợ condition:

```text
T1 → T2 when success
T1 → T3 when failure
```

Graph phải biểu diễn condition thay vì nhúng logic vào Scheduler.

Ví dụ:

```yaml
edge:
  from: T1
  to: T2
  condition: success
```

và:

```yaml
edge:
  from: T1
  to: T3
  condition: failure
```

Condition phải là structured contract, không phải arbitrary code.

---

# 17. Resource Information

Graph node giữ resource requirement từ Plan:

```yaml
node:
  task_ref: T1
  resources:
    cpu: 2
    memory_mb: 1024
```

Nhưng Graph Compiler không:

* grant resource;
* reserve resource;
* queue resource.

Boundary:

```text
Graph
 = describes requirement

Scheduler
 = coordinates execution

Resource Service
 = grants/rejects resource
```

---

# 18. Policy Information

Graph không được làm mất policy metadata từ Plan.

Ví dụ:

```yaml
node:
  policy:
    network: deny
    filesystem_write: approval_required
```

Graph compiler phải preserve metadata để Scheduler/Runtime tiếp tục enforce.

Không được:

```text
Plan policy
→ compile
→ policy lost
```

---

# 19. Capability Information

Tương tự:

```text
Plan
required_capabilities
       ↓
Graph Node
required_capabilities
```

Graph chỉ giữ requirement.

Capability Router/Runtime mới resolve capability khi execution diễn ra.

---

# 20. Graph Immutability

Sau khi compile:

```text
ExecutionGraph v1
```

không được Scheduler tùy tiện mutate dependency topology.

Nếu plan thay đổi:

```text
ExecutionPlan v2
 ↓
ExecutionGraph v2
```

Không sửa graph v1 thành graph v2 mà không tạo version.

Điều này giúp:

* replay;
* audit;
* debugging;
* deterministic evidence.

---

# 21. Graph Identity

Mỗi graph:

```text
graph_id
plan_id
plan_version
compiler_version
created_at
```

Nếu cùng một Plan và compiler version tạo graph nhiều lần, kết quả topology phải deterministic.

# 22. Graph Hash

Nên có canonical representation:

```text
canonical_graph
      ↓
hash
```

Hash giúp phát hiện:

* topology thay đổi;
* node thay đổi;
* edge thay đổi.

Ví dụ:

```yaml
graph_integrity:
  algorithm: sha256
  hash: ...
```

Hash không thay thế provenance.
