## TASK-058 — Autonomous Experimentation

**Mục tiêu**

Xây dựng một **capability để thử nghiệm cải tiến dưới Harness** — cho phép hệ thống tự đề xuất và chạy các **thử nghiệm cải tiến** (plan thay thế, model khác, prompt tối ưu, capability thay thế) nhằm cải thiện outcome, nhưng **bắt buộc chạy dưới Harness hiện có** (TASK-029–TASK-034) với verification + evaluation, **reversible và fail-closed**.

> **TASK-058 không tự sở hữu deployment/change mechanism.** Canonical master spec chỉ yêu cầu *"Thử nghiệm cải tiến có harness"*. Do đó bản spec này **thu hẹp**: Experiment Controller chỉ tạo `PromotionDecision` (artifact chờ approve), **không tự triển khai production change**, không tạo sandbox/control-plane mới, reuse Harness T029–T034.

TASK-058 thuộc **M9 – Autonomous**. Liên quan chặt chẽ đến invariant **INV-034 (Autonomous Memory No Unverified Promote)** và nguyên tắc **no parallel control plane** chung của mọi task M9.

### 1. Phạm vi — reuse Harness, không tạo sandbox riêng

**Experiment Controller** là một capability trên Runtime, **compose** các artifact Harness hiện có:

```text
Autonomous Loop / Planner
          │
          ▼
   Experiment Controller
          │
          ├── Governor / Policy (T054)
          │
          ▼
   Existing Harness (T029–T034)
   ├── Scenario / Simulation (T031)
   ├── Execution Verification (T030)
   ├── Evaluation (T032)
   └── Benchmark / Regression (T033)
          │
          ▼
     Experiment Result
          │
          ├── Promotion Decision (artifact, chờ approve)
          │
          └── Memory (T057, chỉ verified)
```

**Không có** (để giữ invariant no-parallel-control-plane):

```text
Experiment Runtime
Experiment Sandbox Engine
Experiment Evaluation Engine
Experiment DB
Experiment Control Plane
```

Các thành phần (tất cả là capability/interface, không phải subsystem mới):

* **Experiment Proposer** — nhận hypothesis candidate từ Planner/Loop, **validate** metric_spec against experiment contract (không để LLM tự định nghĩa tiêu chí thành công tùy ý — chống evaluation manipulation).
* **Harness Runner** — chạy experiment trong **Harness execution context** (T029–T034), không chạm production.
* **Result Evaluator** — so sánh vs baseline qua Harness Evaluation (T032) + Benchmark (T033).
* **Promotion Decision** — tạo artifact `PROMOTION_READY` (không tự apply).

### 2. Experiment Contract (đã thu gọn + versioned)

```text
Experiment
├── experiment_id
├── hypothesis
├── baseline_ref
├── baseline_version       # immutable, resolve thành version cụ thể
├── candidate_ref
├── candidate_version      # immutable, resolve thành version cụ thể
├── scenario_ref
├── metric_spec            # validated bởi Controller, không do LLM tự đặt
├── policy_scope
├── evidence_ref
├── evaluation_ref
├── status
└── created_at
```

Quy tắc:

* **Baseline/candidate/scenario phải immutable/versioned** — resolve thành artifact/version cụ thể trước khi execution; evaluation **không dùng "current/latest" động**. Nếu baseline thay đổi giữa run và evaluate → **BLOCK** (A/B mất ý nghĩa).
* `metric_spec` phải qua validation của Controller; hypothesis mơ hồ (vd "plan này tốt hơn" không có metric đo lường) → **REJECT**.

### 3. Experiment Lifecycle

```text
PROPOSED
   ↓ (policy authorize — T054)
AUTHORIZED
   ↓ (harness run)
RUNNING
   ↓
EVALUATED
   ↓
┌────────────────────┬─────────────────────┐
│ VERIFIED IMPROVEMENT│ NOT VERIFIED        │
↓                     ↓
PROMOTION_READY       REJECTED / ROLLED_BACK
```

* `PROMOTION_READY` (tốt hơn `PROMOTED`) — Experiment Controller **không tự thay đổi production**; artifact chờ capability/policy/runtime contract tương ứng apply.
* Evaluation dùng `EvalVerdict` (PASS/FAIL/WARNING/INCONCLUSIVE) từ T032; INCONCLUSIVE/UNKNOWN **không auto-promote** (quy tắc chung AIOS).

### 4. Promotion Gate — đa chiều, không chỉ một hard metric

Promotion chỉ khi **tất cả** thỏa mãn (theo T033: quality / cost / latency / token / failure / policy):

```text
verified improvement (quality)
AND
no prohibited regression (cost / latency / failure)
AND
policy PASS
```

* Quality +10% nhưng cost +300% hoặc policy violation +1 → **NOT_PROMOTED**.
* Cost vượt hard limit → **NOT_PROMOTED**.
* Chỉ `metric > threshold` là **không đủ**.

### 5. INCONCLUSIVE / UNKNOWN handling

* `INCONCLUSIVE` → **NOT_PROMOTED** → return decision cho Governor/Loop quyết định bước tiếp (không tự escalate/safe-stop).
* `UNKNOWN` evidence → **NOT_PROMOTED** (quy tắc chung: UNKNOWN không nâng thành PASS).

### 6. Anti-Poisoning & Memory Feedback

```text
Experiment Result
├── raw_result
├── evaluation_verdict
├── evidence_ref
└── trust_status
```

* Chỉ **verified result** mới được đưa vào **trusted memory** (T057, INV-034).
* Unverified result → Memory `NOT_TRUSTED` (không tạo feedback loop: Experiment → Memory → Planner → Experiment).

### 7. Experiment Safety

* **No production side effect** — experiment chỉ chạy Harness context; apply change là trách nhiệm của capability/policy/runtime contract khác (không thuộc T058).
* **Rollback on regression** — candidate tệ hơn baseline (theo gate §4) → `ROLLED_BACK`, không promote.
* **Governor limits scope** — autonomy level giới hạn phạm vi experiment (model/provider/capability nào được thử); Governor deny → **BLOCK** (không persist decision).
* **No parallel control plane** — Experiment Controller là capability trên Runtime, reuse Harness.
* **Fail-closed** — evaluation thiếu provenance → FAIL-CLOSED; production capability bị experiment gọi trực tiếp → BLOCK.

### 8. Deliverables

* Experiment Controller (propose → authorize → run → evaluate → decision).
* `Experiment` contract (immutable/versioned baseline/candidate/scenario).
* Harness integration (reuse T029–T034, không tạo sandbox riêng).
* Result Evaluator (A/B vs baseline, EvalVerdict + Benchmark T033).
* Promotion Gate (đa chiều: quality+cost+latency+failure+policy).
* `PromotionDecision` artifact (PROMOTION_READY, không tự deploy).
* Anti-poisoning guard (verified-only → trusted memory T057).
* Autonomy-gated experiment scope (T054).
* Unit + Contract + Integration + Architecture + E2E + Regression tests.
* ADR/docs nếu implementation tạo architectural decision mới.

### 9. Acceptance Criteria

TASK-058 chỉ PASS khi:

* Experiment định nghĩa rõ hypothesis + metric_spec (validated, không do LLM tự đặt).
* Baseline/candidate/scenario **immutable/versioned**; baseline thay đổi giữa run/evaluate → BLOCK.
* Experiment chạy trong **Harness context** (T029–T034), không production side-effect.
* Evaluation so sánh đúng vs baseline qua T032/T033.
* Promotion chỉ khi **verified improvement AND no prohibited regression AND policy PASS**.
* Quality tăng nhưng policy/cost regression → NOT_PROMOTED.
* INCONCLUSIVE/UNKNOWN → NOT_PROMOTED, return cho Governor/Loop.
* Unverified result → Memory `NOT_TRUSTED` (INV-034).
* Promotion tạo `PromotionDecision` artifact, **không tự triển khai production change**.
* Governor deny → BLOCK (không persist).
* Production capability bị experiment gọi trực tiếp → BLOCK.
* Không tạo Experiment Runtime/Sandbox/Evaluation Engine/DB/Control Plane.
* Regression của các milestone trước PASS.
* Không vi phạm architecture invariants.

### 12. Definition of Done

```text
PLAN
→ SPEC
→ CRITIQUE ×2
→ BREAKDOWN
→ REVIEW
→ IMPLEMENT
→ TEST
→ EVALUATE
→ REGRESSION
→ READY_TO_CLOSE
→ DONE
```

Không được đánh dấu `DONE` nếu thiếu artifact của lifecycle hoặc regression gate. Governance của AIOS quy định task chỉ được chuyển sang `DONE` khi toàn bộ Registry, Dependency, Architecture, Lifecycle, Evidence, Test/Evaluate và Regression gates đều PASS.

**Kết quả cuối TASK-058:** AIOS có **capability thử nghiệm cải tiến an toàn dưới Harness** — evaluation/evidence qua T032/T033, bị Governor giới hạn, promotion đa chiều fail-closed, chỉ tạo `PromotionDecision` (không tự deploy), và không biến thành deployment/control-plane mới.
