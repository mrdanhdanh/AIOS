# TASK-045 — Extension Contracts

## 1. Metadata

* **Milestone:** M8 — Ecosystem + Autonomy
* **Task ID:** TASK-045
* **Tên:** Extension Contracts
* **Mục tiêu canonical:** Extension Contracts (public interface chuẩn hóa).
* **Dependency trực tiếp:** TASK-044 — Plugin Runtime
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


## 1. Mục tiêu

Thiết lập **public extension contracts** ổn định để extension/plugin có thể mở rộng AIOS mà không phụ thuộc trực tiếp vào implementation nội bộ của Core.

TASK-045 tạo ranh giới chính thức:

```text
Extension
   ↓
Public Extension Contract
   ↓
AIOS SDK / Capability / Runtime API
   ↓
AIOS Core
```

Extension chỉ được phụ thuộc vào **public contract**, không được import hoặc thao tác trực tiếp với Runtime Service, Registry implementation, database, filesystem adapter hoặc internal control-plane implementation.

Mục tiêu cuối cùng:

> Có thể thay đổi implementation bên trong AIOS Core mà không phá extension đã tuân thủ public contract.

Nguồn roadmap chỉ định trực tiếp mục tiêu này; phần chi tiết dưới đây là structured expansion để biến mục tiêu thành specification có thể implement và verify.

## 2. Phạm vi

### 2.1 Public Extension Contract

Định nghĩa contract chung cho extension:

```text
ExtensionContract
├── metadata
├── contract_version
├── api_version
├── capabilities
├── dependencies
├── permissions
├── lifecycle
├── configuration
└── compatibility
```

Metadata tối thiểu:

```yaml
id: example.extension
name: Example Extension
version: 1.0.0
contract_version: 1.0
api_version: 1
type: plugin
capabilities:
  - example.capability
dependencies: []
permissions: []
compatibility:
  aios: ">=1.0,<2.0"
```

### 2.2 Extension Types

Contract phải đủ tổng quát để hỗ trợ các loại extension đã tồn tại trong AIOS:

* Tool extension
* Capability extension
* Skill extension
* Workflow extension
* Prompt extension
* Agent extension
* Integration extension

Không tạo một runtime riêng cho từng loại.

### 2.3 Lifecycle Contract

Extension phải tuân lifecycle đã được thiết kế ở Plugin Runtime:

```text
DISCOVERED
   ↓
VALIDATED
   ↓
INSTALLED
   ↓
ENABLED
   ↓
LOADED
   ↓
RUNNING
   ↓
UNLOADED / DISABLED
   ↓
REMOVED
```

Contract phải định nghĩa rõ:

* initialization
* activation
* deactivation
* unload
* cleanup
* failure handling

Implementation lifecycle thuộc TASK-044; TASK-045 chuẩn hóa **public interface** mà lifecycle đó expose. TASK-044 là dependency trực tiếp theo thứ tự M8.

## 3. Contract Boundary

### 3.1 Extension được phép truy cập

Extension chỉ được truy cập:

```text
Public SDK
Public Extension Contract
Capability API
Runtime API
Event API
Artifact API
Configuration API
```

và các API public khác được contract công bố.

### 3.2 Extension không được truy cập

Extension không được:

```text
→ import Runtime Service implementation
→ truy cập database trực tiếp
→ bypass Permission Service
→ bypass Policy Service
→ gọi Tool implementation trực tiếp
→ sửa Registry nội bộ
→ truy cập Event Bus implementation
→ truy cập filesystem ngoài capability/runtime boundary
→ giữ reference tới internal service để bypass contract
```

Nguyên tắc:

```text
Extension → Public Contract → Runtime
```

không phải:

```text
Extension → Internal Runtime Implementation
```

## 4. Versioning

Extension Contract phải có version độc lập với implementation.

### 4.1 Contract Version

Sử dụng semantic compatibility:

```text
MAJOR.MINOR
```

Quy tắc:

* `MINOR`: backward-compatible addition
* `MAJOR`: breaking change
* Extension khai báo version contract mà nó yêu cầu.
* Runtime phải kiểm tra compatibility trước khi enable/load.

Ví dụ:

```text
Extension requires contract 1.0
Runtime exposes 1.2
→ compatible

Extension requires contract 2.0
Runtime exposes 1.x
→ incompatible → BLOCK
```

### 4.2 Không silently downgrade

Nếu contract không tương thích:

```text
VALIDATION
    ↓
INCOMPATIBLE
    ↓
BLOCK
```

Không tự động ép extension chạy bằng contract cũ nếu compatibility chưa được xác nhận.

## 5. Capability Declaration

Extension không được tự nhận quyền bằng implementation.

Extension khai báo:

```yaml
capabilities:
  - filesystem.read
  - execute_code
  - git.read
```

Runtime/Capability Registry quyết định capability thực tế.

Luồng:

```text
Extension Manifest
      ↓
Capability Declaration
      ↓
Validation
      ↓
Capability Registry
      ↓
Policy / Permission
      ↓
Runtime
```

Do đó:

> Contract khai báo **nhu cầu**, không tự cấp **quyền**.

---

## 6. Permission Boundary

Extension manifest có thể khai báo:

```yaml
permissions:
  - filesystem.read
  - network.api
```

nhưng không được coi declaration này là authorization.

Authorization vẫn đi qua:

```text
Extension
 → Capability
 → Permission Service
 → Policy Service
 → Runtime
```

Extension không thể:

```python
runtime.permission_service.allow(...)
```

hoặc trực tiếp gọi implementation để tự cấp quyền.

## 7. Compatibility Model

Contract validator phải kiểm tra ít nhất:

```text
Extension ID
Version
Contract Version
API Version
Required Capabilities
Required Permissions
Dependencies
AIOS Compatibility Range
```

Kết quả:

```text
COMPATIBLE
INCOMPATIBLE
UNKNOWN
```

Nguyên tắc fail-closed:

```text
UNKNOWN compatibility
        ↓
       BLOCK
```

Không được chuyển `UNKNOWN` thành `PASS`.

## 8. Public vs Internal API

Phân chia rõ:

```text
public/
├── contracts/
├── sdk/
└── api/

internal/
├── kernel/
├── registry/
├── persistence/
├── orchestration/
└── implementation/
```

Public API phải:

* documented
* versioned
* tested
* compatibility-checked

Internal API:

* không được extension phụ thuộc
* có thể thay đổi trong phạm vi compatibility policy
* phải được architecture test bảo vệ khỏi external import

## 9. Extension Contract Objects

Tối thiểu cần các abstraction:

### `ExtensionManifest`

Mô tả extension và requirements.

### `ExtensionContract`

Định nghĩa API/lifecycle contract.

### `ExtensionContext`

Context được cấp cho extension sau khi policy/permission validation thành công.

### `ExtensionDependency`

Khai báo dependency giữa extension.

### `ExtensionCompatibility`

Kết quả compatibility check.

### `ExtensionResult`

Chuẩn hóa output/error/evidence của extension.

### `ExtensionEvent`

Chuẩn hóa event mà extension phát hoặc nhận.

## 10. Dependency Model

Extension có thể khai báo:

```yaml
dependencies:
  - id: aios.python
    version: ">=1.0,<2.0"
```

Resolver phải phân biệt:

```text
dependency exists
dependency compatible
dependency enabled
dependency healthy
dependency authorized
```

Thiếu hoặc incompatible dependency:

```text
BLOCK
```

Không load extension ở trạng thái partial nếu dependency bắt buộc chưa đạt.

## 11. Error Contract

Extension không được trả exception implementation tùy ý xuyên qua public API.

Chuẩn hóa:

```text
ExtensionError
├── validation_error
├── compatibility_error
├── dependency_error
├── permission_error
├── policy_error
├── lifecycle_error
├── execution_error
└── timeout_error
```

Error phải có:

```text
error_code
message
extension_id
contract_version
retryable
cause
evidence_ref
```

Không expose secret hoặc internal stack trace ra public response mặc định.

## 12. Evidence Contract

Mọi lifecycle/execution quan trọng của extension phải có evidence tương thích với Harness.

Ví dụ:

```text
Extension Load
    ↓
Validation Evidence
    ↓
Compatibility Evidence
    ↓
Permission/Policy Evidence
    ↓
Lifecycle Evidence
    ↓
Execution Evidence
```

Evidence phải giữ provenance.

Extension không được tự tuyên bố:

```text
success = true
```

để bypass verification.

## 15. Acceptance Criteria

### AC-01 — Public Contract

Extension có thể implement dựa trên public contract mà không cần import Core internal implementation.

**Expected: PASS**

### AC-02 — Version Compatibility

Compatible contract được chấp nhận; breaking/incompatible contract bị block.

```text
compatible   → ALLOW
incompatible → BLOCK
unknown      → BLOCK
```

### AC-03 — Lifecycle

Extension lifecycle chạy qua contract thống nhất:

```text
discover → validate → install → enable → load → run → unload
```

Failure phải chuyển sang trạng thái lỗi xác định và không để extension ở trạng thái giả `RUNNING`.

### AC-04 — Dependency

Extension thiếu hoặc có dependency incompatible:

```text
LOAD = BLOCK
```

### AC-05 — Capability

Extension chỉ sử dụng capability đã khai báo và được Runtime/Registry resolve.

### AC-06 — Permission

Permission declaration không tự cấp quyền.

Mọi execution nhạy cảm phải đi qua Permission + Policy.

### AC-07 — Architecture Boundary

Extension import trực tiếp internal Runtime/Core implementation:

```text
ARCHITECTURE TEST = FAIL
```

### AC-08 — Fail-Closed

Các trường hợp:

```text
unknown contract
unknown compatibility
invalid manifest
missing dependency
unauthorized permission
invalid capability
```

đều không được `PASS`.

### AC-09 — Evidence

Lifecycle và execution quan trọng tạo evidence có provenance, có thể truy ngược từ extension run tới contract/version.

### AC-10 — Regression

Toàn bộ regression của dependency closure PASS; không được phá:

```text
M1 Runtime
M2 Plugin/Skill
M5 Intelligence
M6 Harness
M7 Enterprise
M8 TASK-043
M8 TASK-044
```

## 17. Security Requirements

Extension được xem là **untrusted by default**.

Không được:

* tự cấp permission
* tự truy cập credential
* tự bypass sandbox
* tự mở network
* tự ghi filesystem ngoài capability
* tự sửa policy
* tự sửa registry authority

Security boundary vẫn thuộc:

```text
Policy → Permission → Capability → Runtime
```

## 21. Definition of Done

TASK-045 đạt DONE khi:

1. Public extension contract được version hóa.
2. Extension không cần phụ thuộc Core internal implementation.
3. Compatibility được kiểm tra deterministic.
4. Dependency được validate trước activation.
5. Capability/Permission/Policy boundary không bị bypass.
6. Lifecycle contract tương thích TASK-044.
7. Architecture tests enforce public/internal boundary.
8. Harness có thể verify extension contract và lifecycle.
9. Evidence có provenance.
10. Regression của dependency closure PASS.
11. Không tạo control plane hoặc runtime song song.
12. Contract đủ ổn định để **TASK-046 Ecosystem Registry** có thể discovery/index extension dựa trên contract này.
