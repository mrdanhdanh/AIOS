### TASK-030 — SPEC

## 1. Metadata

* **Milestone:** M6 — AIOS Harness
* **Task ID:** TASK-030
* **Tên:** Execution Verification + Evidence + Replay
* **Mục tiêu canonical:** Xác minh execution và tạo evidence có thể replay.
* **Dependency trực tiếp:** TASK-029 — Harness Kernel + Contract + Registry + Run
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


**1. Mục tiêu**

Xây subsystem Verification cho Harness để AIOS không đồng nhất:

> `Execution succeeded` ≠ `Task succeeded`

Verification phải kiểm tra **post-condition, invariant, policy và evidence**, sau đó mới đưa ra verdict.

Pipeline canonical:

```text
Execution
  ↓
Collect Evidence
  ↓
Deterministic Checks
  ↓
Policy Checks
  ↓
Tests
  ↓
Evaluation
  ↓
Verdict
```

Verdict:

```text
PASS
PASS_WITH_WARNING
FAIL
INCONCLUSIVE
```

Không được mặc định `PASS` chỉ vì execution không exception. Điều này trực tiếp thực thi **INV-019 — Verification Before Verdict** và **INV-018 — Evidence First** của M6.

### 2. Phạm vi

**Verification Contract**

Mỗi execution cần có:

```text
Preconditions
Execution
Postconditions
Invariants
Evidence
```

Ví dụ:

```yaml
verification:
  preconditions:
    - module_exists

  postconditions:
    - test_file_exists
    - tests_pass
    - coverage_gte: 0.90

  invariants:
    - no_policy_bypass
    - no_unapproved_tool
```

**Evidence Package**

Tối thiểu:

```text
Evidence Package
├── request.json
├── normalized-request.json
├── plan.json
├── execution-graph.json
├── events.json
├── tool-results/
├── test-results/
├── evaluation.json
├── artifacts/
└── verdict.json
```

Evidence phải có provenance và liên kết được về execution/run.

### 3. Replay

Replay **không chạy lại tool thật**.

Canonical flow:

```text
Production Run
      ↓
Execution Trace
      ↓
Evidence Package
      ↓
Replay
      ↓
Simulation
      ↓
Debug
```

Replay phải cho phép tái dựng execution state đủ để kiểm tra:

* decision
* execution graph
* event sequence
* tool result
* test result
* artifact reference
* verification result
* final verdict

Mục tiêu là debug/audit mà không tạo side effect mới.

### 5. Acceptance Criteria

**AC-030-01 — Verification**

Execution không exception nhưng post-condition fail:

```text
→ FAIL
```

Không được `PASS`.

**AC-030-02 — Preconditions**

Precondition fail:

```text
→ verification không được chạy execution verification bình thường
→ verdict = FAIL hoặc INCONCLUSIVE theo policy
```

**AC-030-03 — Postconditions**

Kiểm tra được deterministic post-condition.

Ví dụ:

```text
file exists
test passed
artifact checksum
coverage threshold
expected state
```

**AC-030-04 — Invariants**

Violation invariant:

```text
→ FAIL
```

**AC-030-05 — Evidence First**

Mọi Harness Run phải tạo Evidence Package truy xuất được.

**AC-030-06 — Provenance**

Mọi evidence phải truy được:

```text
Evidence
 → Run
 → Execution
 → Task/Request
```

**AC-030-07 — Replay**

Replay từ Evidence Package không gọi tool thật và không tạo side effect.

**AC-030-08 — Verdict**

Không được suy luận:

```text
exit_code == 0 → PASS
```

Verdict phải dựa trên verification evidence.

**AC-030-09 — Fail-closed**

Evidence thiếu hoặc không đủ để chứng minh post-condition:

```text
→ INCONCLUSIVE
```

Không được nâng `UNKNOWN` thành `PASS`.

**AC-030-10 — Regression**

Toàn bộ regression của dependency phải PASS trước khi TASK-030 được DONE. Master specification quy định task chỉ được đóng khi workflow gate và regression gate đầy đủ.
