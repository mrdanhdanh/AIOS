# TASK-025 — Model Router

## 1. Metadata

* **Milestone:** M5 — Core Intelligence
* **Task ID:** TASK-025
* **Tên:** Model Router
* **Mục tiêu canonical:** Chọn model theo policy, capability, cost và health.
* **Dependency trực tiếp:** TASK-024 — Context Optimizer
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


## 1. Mục tiêu

Xây dựng **Model Router** chịu trách nhiệm quyết định model phù hợp cho từng request/execution dựa trên:

* Model capability.
* Routing policy.
* Cost.
* Latency.
* Availability/health.
* Context window.
* Yêu cầu reasoning/coding/vision/tool-calling/structured-output.
* Fallback policy.

Model Router phải hoạt động theo nguyên tắc:

> **Deterministic First → Policy First → LLM Last**

Router không tự suy luận bằng LLM để chọn model. Việc lựa chọn phải có thể giải thích, kiểm thử và tái lập.

TASK-025 kế thừa `ModelContract + Provider Registry` của TASK-006 và bổ sung tầng **decision/routing** cho Model Intelligence của M5. TASK-025 không thay thế Provider Registry.

## 3. Phạm vi

### 3.1 Model capability metadata

Model Registry/Contract phải cung cấp đủ metadata để Router có thể deterministic-filter:

```yaml
model:
  model_id: ...
  provider: ...
  context_window: ...
  input_cost: ...
  output_cost: ...
  latency_class: ...
  reasoning: true|false
  coding: true|false
  vision: true|false
  tool_calling: true|false
  structured_output: true|false
  availability: ...
```

Router không được chọn model nếu model không đáp ứng capability bắt buộc.

---

### 3.2 Routing Policy

Hỗ trợ policy dạng declarative:

```yaml
routing:
  default: balanced

  policies:
    cheap:
      max_cost: 0.01

    fast:
      max_latency_ms: 2000

    quality:
      min_quality: 0.9

    local:
      providers:
        - ollama
```

Policy phải được evaluate trước khi model được chọn.

Các policy có thể kiểm soát:

* provider;
* model;
* cost;
* latency;
* quality;
* locality;
* capability;
* availability;
* context window;
* network requirement;
* fallback permission.

---

### 3.3 Deterministic model selection

Pipeline tối thiểu:

```text
Request
 ↓
Extract Requirements
 ↓
Policy Filter
 ↓
Capability Filter
 ↓
Availability Filter
 ↓
Cost/Latency Filter
 ↓
Rank Candidates
 ↓
Select Model
```

Nếu chỉ có một candidate hợp lệ → chọn trực tiếp.

Nếu có nhiều candidate → deterministic ranking.

Nếu không có candidate → `NO_ELIGIBLE_MODEL`, không tự ý bypass policy.

---

### 3.4 Model selection criteria

Candidate có thể được đánh giá theo:

```text
Capability Match
Policy Compliance
Availability
Context Window
Quality
Cost
Latency
Priority
Health
```

Không được dùng similarity đơn thuần.

Model có score cao nhưng vi phạm Policy vẫn phải bị loại trước khi ranking.

---

### 3.5 Fallback

Fallback phải được khai báo hoặc được policy cho phép.

Ví dụ:

```text
GPT
 ↓ timeout
DeepSeek
 ↓ rate limit
Ollama
```

Fallback không phải là:

```text
Model A fail
→ Router tự chọn bất kỳ model nào
```

Mà là:

```text
Failure
 ↓
FallbackResolver
 ↓
Policy Check
 ↓
Eligible Candidates
 ↓
Next Model
```

Nếu policy không cho fallback:

```text
FAIL_CLOSED
```

---

### 3.6 Health và availability

Router phải phân biệt:

```text
registered
available
healthy
eligible
selected
```

Ví dụ:

```text
Model tồn tại
≠
Model đang available
≠
Model được Policy cho phép
≠
Model phù hợp request
```

Health information có thể gồm:

* provider reachable;
* model available;
* recent failure rate;
* timeout;
* rate-limit state;
* circuit state.

Health chỉ là một input của Router, không được override Policy.

## 4. Ranh giới trách nhiệm

### Model Router

Chịu trách nhiệm:

* orchestration của routing;
* gọi các component chuyên trách;
* trả về `ModelSelection`;
* quyết định fallback theo policy.

### ModelSelector

Chịu trách nhiệm:

* filter;
* rank;
* deterministic selection.

### RoutingPolicy

Chịu trách nhiệm:

* parse/evaluate routing policy;
* allow/deny candidate;
* giới hạn cost/latency/provider/model.

### CostEstimator

Chịu trách nhiệm:

* estimate input/output cost;
* estimate execution cost;
* so sánh với budget nếu được cung cấp.

### AvailabilityChecker

Chịu trách nhiệm:

* kiểm tra availability;
* health;
* temporary failure state.

### FallbackResolver

Chịu trách nhiệm:

* xác định candidate fallback;
* kiểm tra thứ tự fallback;
* không bypass Policy.

### ModelHealth

Chịu trách nhiệm:

* health state;
* failure/latency signals;
* circuit/bad-state information.

Router chỉ điều phối các component trên.

**Không được đưa toàn bộ logic vào `ModelRouter`.**


## 7. Offline-first

Router phải hoạt động không cần LLM.

Các trường hợp deterministic:

```text
routing policy = local
→ Ollama

max_cost = 0.01
→ lọc candidate

coding = required
→ capability filter

model unavailable
→ fallback resolver
```

Không gọi Planner/LLM chỉ để chọn model.

Điều này phù hợp nguyên tắc của AIOS rằng deterministic path phải đi trước và LLM không trở thành control plane mặc định.

## 9. Fallback Flow

```text
Selected Model
      ↓
Execution Failure
      ↓
Classify Failure
      ↓
FallbackResolver
      ↓
Policy Check
      ↓
Candidate Filter
      ↓
Select Fallback
      ↓
Execution Retry
```

Không fallback đối với lỗi mà policy yêu cầu fail-closed.

Ví dụ:

```text
timeout       → có thể fallback
rate_limit    → có thể fallback
provider_down → có thể fallback

policy_denied → KHÔNG fallback để bypass policy
capability    → chỉ fallback nếu candidate đáp ứng capability
budget_denied → chỉ fallback nếu candidate nằm trong budget
```

## 13. Architecture Constraints

TASK-025 bắt buộc giữ:

### INV-013 — Model Routing Policy

**Mọi model selection phải đi qua Routing Policy.**

Không cho phép:

```text
Agent → Provider → Model
```

hoặc:

```text
Planner → hardcoded model
```

### Không tạo God Object

Không cho phép `ModelRouter` trực tiếp sở hữu:

* provider implementation;
* HTTP client;
* tokenization implementation;
* health database;
* billing database;
* policy storage.

Router chỉ phụ thuộc contract/interface.

### Không bypass Runtime

Model selection không được trực tiếp execute model.

```text
Model Router
    ↓
Model Selection
    ↓
Runtime / Execution
```

### Không bypass Policy

```text
Routing Policy
    ↓
Selection
```

không được:

```text
Selection
    ↓
Policy bypass
    ↓
Execution
```

## 15. Acceptance Criteria

TASK-025 chỉ PASS khi:

1. Model được chọn dựa trên **policy + capability + cost + health/availability**.
2. Routing deterministic cho các trường hợp đã biết.
3. Không cần LLM để thực hiện routing thông thường.
4. Model không đáp ứng capability bắt buộc bị loại.
5. Model vi phạm policy bị loại.
6. Cost/latency constraint được enforce.
7. Context-window constraint được enforce.
8. Fallback hoạt động khi policy cho phép.
9. Fallback không thể bypass Policy.
10. Không có eligible model → fail-closed.
11. Selection có explanation và provenance.
12. Router không trở thành God Object.
13. Agent không truy cập Provider/Model trực tiếp.
14. Unit + Contract + Integration + Architecture + E2E + Regression đều PASS.
15. INV-013 được enforce bằng automated architecture/contract test.
16. Routing decision có observability đầy đủ.
17. Offline Mock/Ollama path hoạt động không cần external LLM.
