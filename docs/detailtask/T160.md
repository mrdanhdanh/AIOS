## TASK-160 — Security Verifier

**Mục tiêu**

Triển khai **Security Verifier** như một năng lực có contract, evidence và harness riêng — xác minh không có lỗ hổng bảo mật trong output, fail-closed. TASK-160 là **security verifier, không phải scanner mới** (dựa trên Requirement→Evidence Mapping T155 + Security/Replay Harness T143 + Security Baseline T070 + Verification Engine T142 + Evidence T001).

TASK-160 thuộc **M22**, ngay sau T159. Trọng tâm canonical: **Security Verifier**.

### 1. Phạm vi — Security verifier, không scanner mới

```text
Security Verifier
├── Policy Check         (check policy bảo mật, T070)
├── Vulnerability Scan   (quét lỗ hổng)
├── Secret Leak          (phát hiện lộ secret, T040)
└── Policy Boundary      (T113)
```

* **Policy Check** — check output qua policy bảo mật (T070).
* **Vulnerability Scan** — quét lỗ hổng trong output.
* **Secret Leak** — phát hiện lộ secret (T040/T113).
* **Policy Boundary** — verification qua policy (T113).

### 2. Security Verifier Contract

```text
SecurityResult
├── result_id            (immutable, T001 Rule 1)
├── map_ref              (T155)
├── policy_ref           (T070)
├── verdict              (PASS/FAIL/INCONCLUSIVE)
├── evidence_ref         (T001)
└── authority: aios
```

Quy tắc:

* Lỗ hổng/secret leak phát hiện → FAIL (fail-closed, T078/T070).
* Mọi result có provenance (T001 Rule 5).
* Verification deterministic: cùng input → cùng verdict.
* Verification không lộ secret (T040/T113).

### 3. Security Verifier Safety

* **Fail-closed** — lỗ hổng/leak → FAIL (T078/T070).
* **Immutable id** — `result_id` không tái sử dụng (T001 Rule 1).
* **Evidence required** — mọi result có provenance (T001 Rule 5).
* **Deterministic** — cùng input → cùng verdict.
* **No parallel verifier** — dùng Requirement→Evidence (T155) + Security/Replay (T143) + Security Baseline (T070) + Verification Engine (T142) + Evidence (T001).

### 4. Deliverables
