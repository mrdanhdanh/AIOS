Để thỏa mãn 7 quy tắc này, bạn cần biến chúng từ **“nguyên tắc trên giấy” thành một hệ thống kiểm soát có thể tự kiểm chứng**.

Nói ngắn gọn:

> **Không chỉ viết task → code → test.**
> Bạn cần xây một **Task Governance System** ngay từ TASK-001, rồi mọi task sau đó bắt buộc chạy qua hệ thống này.

### Việc cần làm thực tế

| Quy tắc                         | Bạn phải xây                 | Cách chứng minh                                        |
| ------------------------------- | ---------------------------- | ------------------------------------------------------ |
| 1. TASK ID immutable            | `Task Registry`              | Không cho sửa/xóa/reuse ID                             |
| 2. Dependency quyết định thứ tự | `Dependency Graph`           | Task chỉ được RUN khi dependency PASS                  |
| 3. Agent không bypass Runtime   | `Architecture Guard`         | AST/import tests + integration tests                   |
| 4. LLM không làm control plane  | `Deterministic Control Path` | Test chứng minh rule/workflow chạy trước LLM           |
| 5. Evidence có provenance       | `Evidence Store`             | Mỗi evidence có ID, source, timestamp, hash, producer  |
| 6. Task phải qua lifecycle      | `Task State Machine`         | Không cho chuyển DONE nếu thiếu artifact bắt buộc      |
| 7. Regression dependency        | `Regression Gate`            | Mỗi task chạy test của dependency chain trước khi PASS |

# 2. TASK Registry — giải quyết Rule #1

Bạn cần một registry duy nhất:

```yaml
task_id: TASK-001
milestone: M0
title: Project Governance Foundation
status: PLANNED
created_at: ...
dependencies: []
```

Registry phải có các invariant:

```text
TASK ID:
- unique
- immutable
- never reused
- never deleted
```

Ví dụ:

```text
TASK-001 → tồn tại vĩnh viễn
TASK-002 → tồn tại vĩnh viễn
```

Nếu task sai:

```text
TASK-002
status = DEPRECATED
```

**Không được xóa TASK-002 rồi tạo task khác mang ID TASK-002.**

### Gate cần có

```text
create_task()
      ↓
check ID exists?
      ↓
YES → REJECT
NO  → CREATE
```

Đây phải là **automated test**, không phải quy ước bằng lời.

# 3. Dependency Graph — giải quyết Rule #2

Mỗi task phải khai báo:

```yaml
task_id: TASK-025

dependencies:
  - TASK-023
  - TASK-024
```

Sau đó tạo graph:

```text
TASK-023
    ↓
TASK-024
    ↓
TASK-025
```

Task Runner không được phép chạy TASK-025 nếu:

```text
TASK-023 != PASS
OR
TASK-024 != PASS
```

Điều này tạo ra:

```text
PLANNED
   ↓
READY
   ↓
RUNNING
```

`READY` chỉ được phép khi dependency đã thỏa mãn.

### Cần test

```text
dependency_missing → BLOCK
dependency_failed  → BLOCK
dependency_passed  → READY
cyclic_dependency  → BLOCK
```

# 4. Architecture Guard — giải quyết Rule #3

Đây là phần rất quan trọng đối với AIOS.

Bạn cần enforce kiến trúc:

```text
Agent
  ↓
Orchestrator
  ↓
Runtime
  ↓
Capability
  ↓
Tool
```

Không được:

```text
Agent ─────────→ Tool
Agent ─────────→ Provider
Agent ─────────→ Filesystem
Agent ─────────→ Database
```

Ví dụ Coder Agent **không được**:

```python
subprocess.run(...)
```

hoặc:

```python
open(...)
```

trực tiếp nếu kiến trúc yêu cầu mọi filesystem access phải qua Capability/Runtime.

### Cần xây

```text
Architecture Rules
        ↓
AST Scanner
        ↓
Import Scanner
        ↓
Dependency Checker
        ↓
Architecture Test
```

Ví dụ:

```text
RULE-ARCH-001
Agent cannot import subprocess

RULE-ARCH-002
Agent cannot import filesystem adapter

RULE-ARCH-003
Agent cannot call provider directly

RULE-ARCH-004
Workflow cannot depend on Engine implementation
```

Nếu vi phạm:

```text
ARCHITECTURE GATE = FAIL
TASK = BLOCKED
```

# 5. Deterministic Control Path — giải quyết Rule #4

Bạn phải biến câu:

> LLM không phải control plane

thành một execution contract.

Ví dụ request:

```text
"Chạy workflow X"
```

phải đi:

```text
Request
 ↓
Normalizer
 ↓
Rule Engine
 ↓
Workflow Matcher
 ↓
Capability Resolver
 ↓
Policy
 ↓
Execution Plan
```

Chỉ khi deterministic path không giải quyết được:

```text
              ↓
          Planner LLM
```

Tức là:

```text
Deterministic
     ↓
  SUCCESS
     ↓
Execute

hoặc

Deterministic
     ↓
  INSUFFICIENT
     ↓
   LLM
```

### Cần test 2 trường hợp

**Case A**

```text
Rule có thể quyết định
→ LLM call count = 0
```

**Case B**

```text
Rule không đủ
→ LLM được gọi
→ output phải qua validator
→ mới được tiếp tục
```

Đây là bằng chứng thực tế rằng LLM không phải control plane.

# 6. Evidence Store — giải quyết Rule #5

Đây là nền tảng cực quan trọng cho các milestone sau.

Mỗi evidence phải có:

```yaml
evidence_id:
task_id:
run_id:
producer:
type:
source:
created_at:
content_hash:
parent_artifact:
environment:
status:
```

Ví dụ:

```yaml
evidence_id: EVD-000421
task_id: TASK-125
run_id: RUN-0092
producer: coder-harness
type: test-result
source: pytest
created_at: 2026-08-19T...
content_hash: sha256:...
status: PASS
```

Khi verifier nói:

```text
PASS
```

phải truy được:

```text
PASS
 ↓
Evidence
 ↓
Run
 ↓
Artifact
 ↓
Task
 ↓
Requirement
```

Đây chính là provenance chain.

# 7. Task State Machine — giải quyết Rule #6

Đây là phần tôi khuyên bạn ưu tiên rất cao.

Không cho developer tự sửa:

```text
status = DONE
```

Thay vào đó:

```text
PLANNED
   ↓
SPECIFIED
   ↓
CRITIQUED_1
   ↓
CRITIQUED_2
   ↓
BROKEN_DOWN
   ↓
REVIEWED
   ↓
IMPLEMENTING
   ↓
TESTING
   ↓
EVALUATING
   ↓
REGRESSION
   ↓
READY_TO_CLOSE
   ↓
DONE
```

Mỗi transition có điều kiện.

Ví dụ:

```text
SPECIFIED
```

chỉ hợp lệ nếu tồn tại:

```text
spec.md
```

`CRITIQUED_2`:

```text
critique-1.md
critique-2.md
```

`TESTING`:

```text
unit tests
integration tests
```

`DONE`:

```text
spec
+ critique1
+ critique2
+ breakdown
+ review
+ implementation
+ test
+ evaluation
+ regression
+ progress
+ log
+ commit
```

Thiếu **một** thứ:

```text
DONE = REJECTED
```

# 8. Regression Gate — giải quyết Rule #7

Đây là điểm rất dễ làm sai.

Ví dụ:

```text
TASK-023
TASK-024
TASK-025
```

TASK-025 không chỉ test code của TASK-025.

Nó phải chạy:

```text
TASK-023 tests
TASK-024 tests
TASK-025 tests
```

Tức:

```text
Dependency Closure
```

Ví dụ:

```text
TASK-100
   ↓
TASK-101
   ↓
TASK-102
   ↓
TASK-103
```

Khi TASK-103 chạy:

```text
Regression Set =
103
102
101
100
```

Nếu có failure:

```text
TASK-103 = BLOCKED
```

# 11. Một điểm rất quan trọng

**7 quy tắc trên không phải 7 task riêng biệt.**

Chúng là **7 invariant của toàn bộ AIOS development system**.

Có thể hình dung:

```text
                 AIOS DEVELOPMENT SYSTEM
                          │
              ┌───────────┴───────────┐
              │                       │
         TASK SYSTEM             CODE SYSTEM
              │                       │
      ┌───────┼───────┐               │
      ↓       ↓       ↓               ↓
   Registry Dependency Lifecycle   Architecture
      │       │       │               │
      └───────┼───────┴───────────────┘
              ↓
          Evidence
              ↓
        Test/Evaluation
              ↓
          Regression
              ↓
            GATE
```

**Nếu làm đúng, từ TASK-002 trở đi developer/agent không cần “nhớ” 7 quy tắc này. Hệ thống sẽ tự ép chúng phải tuân thủ.**

Và đây chính là lý do **TASK-001 nên được xem là Governance Foundation**, chứ không đơn thuần là tạo vài file documentation.
