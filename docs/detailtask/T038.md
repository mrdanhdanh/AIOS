## 1. Mục tiêu

Xây Distributed Scheduler có khả năng:

```text
Execution Graph
      ↓
Graph Scheduler
      ↓
Distributed Scheduler
      ↓
Runtime Node
```

Scheduler phải đảm bảo:

* một execution chỉ có **một active lease** tại một thời điểm;
* node được chọn phải phù hợp với capability, capacity, health và policy;
* execution có heartbeat để chứng minh node còn sống;
* lease hết hạn phải được phát hiện deterministic;
* node failure không làm mất execution;
* execution có snapshot/checkpoint thì được resume trên node khác;
* retry/reschedule không tạo duplicate execution ngoài policy cho phép.

Điều này trực tiếp phục vụ invariant **INV-026 — Distributed Execution Safety**.

# 4. Execution Lease

Lease là ownership tạm thời của một execution.

```yaml
lease:
  lease_id: lease-123
  execution_id: exec-456
  node_id: runtime-vn-01
  acquired_at: ...
  expires_at: ...
  heartbeat_at: ...
  epoch: 7
  status: ACTIVE
```

### Các trạng thái

```text
PENDING
  ↓
ACQUIRING
  ↓
ACTIVE
  ├── RENEWED
  ├── RELEASED
  └── EXPIRED
          ↓
       RESCHEDULE
          ↓
       ACQUIRING
```

`epoch`/fencing token rất quan trọng: node cũ dù phục hồi sau khi lease đã hết hạn **không được tiếp tục ghi kết quả như owner hiện tại**.

---

# 5. Lease lifecycle

### Acquire

```text
Execution READY
      ↓
Find eligible Runtime Nodes
      ↓
Acquire lease atomically
      ↓
Lease ACTIVE
      ↓
Dispatch execution
```

### Renew

Node phải gửi heartbeat định kỳ:

```text
Runtime Node
    ↓ heartbeat
Distributed Scheduler
    ↓
renew lease
```

### Release

Execution kết thúc:

```text
SUCCEEDED / FAILED / CANCELLED
        ↓
release lease
        ↓
Runtime Node available
```

### Expire

Nếu heartbeat không còn:

```text
ACTIVE
  ↓
heartbeat timeout
  ↓
LEASE EXPIRED
  ↓
verify node health
  ↓
mark execution STALE
  ↓
RESCHEDULE
```

# 6. Stale Execution

Không được coi:

> "Node không trả heartbeat" = execution chắc chắn đã chết.

Scheduler phải phân biệt:

* `NODE_UNHEALTHY`
* `LEASE_EXPIRED`
* `EXECUTION_UNKNOWN`
* `EXECUTION_STALE`
* `EXECUTION_RECOVERABLE`
* `EXECUTION_NON_RECOVERABLE`

Nếu execution có snapshot:

```text
Runtime-01 failure
      ↓
Lease expired
      ↓
Load latest snapshot
      ↓
Acquire Runtime-02 lease
      ↓
Resume
```

Nếu không có snapshot phù hợp, scheduler phải áp dụng retry/failure policy thay vì tự ý giả định execution có thể resume.

# 7. Failover flow

Scenario chuẩn:

```text
Execution E1
    ↓
Lease → Runtime-01
    ↓
RUNNING
    ↓
Runtime-01 failure
    ↓
Heartbeat timeout
    ↓
Lease expired
    ↓
Fence old lease
    ↓
Execution marked STALE
    ↓
Find Runtime-02
    ↓
Acquire new lease
    ↓
Load snapshot
    ↓
Resume E1
    ↓
RUNNING
    ↓
SUCCEEDED
```

Evidence phải thể hiện được toàn bộ chuỗi:

```text
E1
 ├── lease-01 → runtime-01
 ├── heartbeat events
 ├── lease expired
 ├── failure detected
 ├── lease-02 → runtime-02
 ├── snapshot loaded
 └── resumed
```

# 8. Scheduler decision

Distributed Scheduler chỉ được schedule node khi tất cả điều kiện cần thiết đạt:

```text
Node Registered
    AND
Node Healthy
    AND
Capability Compatible
    AND
Capacity Available
    AND
Tenant/Policy Allowed
    AND
No conflicting active lease
```

Resource availability vẫn thuộc **Resource Service**.

Do đó:

```text
Distributed Scheduler
        │
        ├── asks Runtime Registry → node candidates
        ├── asks Policy → allowed?
        ├── asks Resource Service → resources available?
        └── acquires Lease
```

Không được biến scheduler thành Resource Manager thứ hai.

# 9. Race-condition protection

Đây là phần bắt buộc.

### Race 1 — Hai scheduler cùng acquire

```text
Scheduler A ─┐
             ├── Execution E1
Scheduler B ─┘
```

Kết quả hợp lệ:

```text
ONLY ONE lease ACTIVE
```

### Race 2 — Node cũ gửi completion sau failover

```text
Runtime-01 → stale completion
Runtime-02 → current execution
```

Scheduler phải reject completion của lease/epoch cũ.

### Race 3 — Node hồi phục sau timeout

Node cũ không được tự động lấy lại execution.

### Race 4 — Retry đồng thời

Hai retry request cho cùng execution phải converge về một active lease.

# 10. Failure Policy

Distributed Scheduler không tự quyết định mọi failure.

Policy phải xác định khả năng:

```yaml
failure_policy:
  on_lease_expired: reschedule
  max_reschedule: 3
  resume_from_snapshot: true
  allow_duplicate_execution: false
  backoff: exponential
```

Nếu vượt giới hạn:

```text
RESCHEDULE
   ↓
max attempts reached
   ↓
FAILED
```

Không retry vô hạn.

# 14. Architecture Invariant

TASK-038 phải enforce:

### INV-026 — Distributed Execution Safety

> **Một execution chỉ được có một active lease tại một thời điểm.**

Hệ quả:

```text
execution_id
      ↓
active lease
      ↓
exactly one Runtime Node
```

Mọi đường bypass đều là **architecture failure**, không chỉ functional bug. Master Plan xác định INV-026 thuộc M7 và release architecture review phải kiểm tra invariant này.
