## 1. Mục tiêu

Xây dựng lớp **Security & Data Isolation** cho M7, bảo đảm mọi credential, network access và untrusted execution đều bị kiểm soát bởi **Identity → Tenant → Policy → Permission → Capability → Runtime**.

TASK-040 phải biến các nguyên tắc security của AIOS từ policy/contract thành enforcement thực tế:

```text
Agent
  ↓
Capability
  ↓
Credential Broker → Scoped Credential
  ↓
Policy / Permission
  ↓
Network Policy / Sandbox Policy
  ↓
Tool
  ↓
Runtime Node
```

Agent và Tool **không được tự giữ, tự resolve hoặc tự bypass credential, network policy hay sandbox**.

## 3. Phạm vi

### 3.1 Credential Broker

Triển khai contract và enforcement cho:

```text
Credential Request
    ↓
Identity / Principal
    ↓
Tenant Boundary
    ↓
Project Boundary
    ↓
Capability Scope
    ↓
Policy Evaluation
    ↓
Credential Broker
    ↓
Short-lived Scoped Credential
```

Credential model tối thiểu:

```yaml
credential:
  id: github-main
  tenant_id: tenant-a
  project_id: project-x
  capability: git.push
  scopes:
    - repo:write
  ttl: 300
  status: active
```

Credential không được truyền tự do vào Agent Context hoặc lưu trực tiếp trong Tool.

### 3.2 Credential Scope

Credential phải hỗ trợ tối thiểu:

* tenant scope
* project scope
* capability scope
* principal scope
* TTL / expiration
* allowed action
* revocation
* audit reference

Nếu scope không xác định hoặc không đủ evidence → **DENY**, không suy diễn.

### 3.3 Credential Resolution

Credential Broker phải kiểm tra:

1. Principal hợp lệ.
2. Tenant hợp lệ.
3. Project/workspace thuộc tenant.
4. Capability được phép.
5. Action được phép.
6. Policy cho phép credential.
7. Credential còn hiệu lực.
8. Credential scope tương thích với request.

Không đạt bất kỳ điều kiện bắt buộc nào → fail-closed.

# 4. Network Policy

## 4.1 Default Deny

Mọi network access mặc định:

```yaml
network:
  default: deny
```

Chỉ mở explicit allow.

Ví dụ:

```yaml
network:
  deny:
    - metadata-service
    - internal-admin
  allow:
    - github.com
    - api.openai.com
```

Network policy phải hỗ trợ ít nhất:

* destination
* protocol
* port
* direction
* tenant
* project
* capability
* environment
* runtime node
* allow/deny decision
* policy version

## 4.2 Network Enforcement

Phải kiểm soát các đường:

```text
Agent → Tool
Tool → Internet
Tool → Internal API
Runtime → Database
Runtime → Model Provider
```

Network rule không được chỉ kiểm tra ở UI/API.

Enforcement phải nằm tại boundary thực thi.

## 4.3 Policy Evaluation

Network access phải qua:

```text
Request
 → Identity
 → Tenant
 → Capability
 → Policy
 → Network Policy
 → Allow / Deny
```

Policy deny có precedence cao hơn allow.

Không có policy matching rõ ràng → **DENY**.

# 5. Sandbox Isolation

## 5.1 Sandbox Boundary

Mọi untrusted tool execution phải đi qua:

```text
Policy
 ↓
Permission
 ↓
Sandbox
 ↓
Tool
```

Không được:

```text
Agent → Tool
Agent → Docker
Agent → Host filesystem
Agent → Network
```

## 5.2 Sandbox Profile

Sandbox profile tối thiểu:

```yaml
sandbox:
  filesystem:
    read: [...]
    write: [...]
  network:
    enabled: false
    allow: [...]
  resources:
    cpu: ...
    memory: ...
    timeout: ...
  process:
    max_processes: ...
```

Phải hỗ trợ:

* filesystem scope
* network isolation
* CPU limit
* memory limit
* execution timeout
* process boundary
* environment isolation
* cleanup/reset

## 5.3 Tenant Isolation

Sandbox của Tenant A không được truy cập:

* filesystem của Tenant B
* credential của Tenant B
* artifact của Tenant B
* network policy của Tenant B
* workspace của Tenant B

Sandbox reuse phải reset state trước khi cấp cho execution khác.

# 7. Audit & Evidence

Mọi security-sensitive action phải tạo audit evidence.

Tối thiểu:

```text
Credential requested
Credential granted / denied
Credential revoked
Network allowed / denied
Sandbox created
Sandbox denied
Sandbox destroyed
Policy evaluated
Cross-tenant access denied
```

Audit phải trả lời được:

```text
Who?
What?
When?
Which tenant?
Which project?
Which capability?
Which credential?
Which policy?
Which network destination?
Which sandbox?
Result?
Reason?
```

Credential secret/token **không được ghi plaintext vào audit**.

Chỉ lưu:

* credential ID
* scope
* hash/fingerprint nếu cần
* grant/revoke event
* audit reference

# 11. Test Strategy

Bắt buộc:

```text
Unit
→ Contract
→ Security
→ Tenant Isolation
→ Integration
→ Architecture
→ E2E
→ Regression
```

Các scenario tối thiểu:

1. Tenant A resolve credential của A → PASS.
2. Tenant A resolve credential của B → DENY.
3. Credential hết TTL → DENY.
4. Capability không đúng scope → DENY.
5. Network chưa allow → DENY.
6. Network nằm trong allow-list → PASS.
7. Policy service unavailable → DENY.
8. Untrusted tool không có sandbox → DENY.
9. Sandbox A truy cập filesystem B → DENY.
10. Sandbox reset không để lại state từ execution trước.
11. Credential secret không xuất hiện trong log/evidence.
12. Security event tạo audit evidence.
13. Agent cố truy cập credential trực tiếp → architecture test FAIL.
14. Agent cố bypass sandbox → architecture test FAIL.
15. Tool cố bypass network policy → architecture test FAIL.
