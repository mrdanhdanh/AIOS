## 1. Mục tiêu

Đưa `Tenant` trở thành **security boundary thực sự** của AIOS.

Mô hình chuẩn:

```text
Organization
    │
    └── Tenant
          │
          ├── Project
          │     └── Workspace
          │            └── Execution
          │
          ├── Users / Agents / Services
          ├── Workflows
          ├── Memory
          ├── Artifacts
          ├── Skills
          ├── Credentials
          └── Harness Runs
```

Tenant không chỉ là một field `tenant_id` trong database.

Boundary phải được enforce xuyên:

```text
API
 ↓
Identity / Principal
 ↓
Tenant Context
 ↓
Policy
 ↓
Orchestrator
 ↓
Memory / Registry / Runtime / Tool
 ↓
Storage / Audit / Artifact
```

Nguồn master plan yêu cầu các object quan trọng như `Execution`, `Workflow`, `Agent`, `Memory`, `Artifact`, `Skill`, `Credential`, `Evaluation`, `Harness Run` đều phải có ownership theo tenant.

## 2. Scope

### 2.1 Tenant Model

Định nghĩa contract:

```text
Organization
Tenant
Project
Workspace
TenantContext
TenantResource
```

Ví dụ:

```yaml
organization:
  id: org-acme

tenant:
  id: tenant-acme
  organization_id: org-acme

project:
  id: project-aios
  tenant_id: tenant-acme

workspace:
  id: workspace-main
  project_id: project-aios
```

Mọi execution phải resolve được:

```text
Principal
→ Tenant
→ Project
→ Workspace
→ Execution
```

### 2.2 Tenant Context

Mỗi request/execution phải mang tenant context.

Context tối thiểu:

```text
tenant_id
organization_id
project_id
workspace_id
principal_id
```

Không cho phép component tự suy đoán tenant từ dữ liệu không đáng tin cậy.

### 2.3 Tenant Resource Ownership

Các resource sau phải tenant-scoped:

* Execution
* Workflow
* Agent
* Memory
* Artifact
* Skill
* Credential
* Evaluation
* Harness Run
* Prompt
* Knowledge
* Audit record
* Runtime allocation

### 2.4 Tenant Isolation

Default:

```text
Tenant A → Resource A       ALLOW
Tenant A → Resource B       DENY
Tenant B → Resource A       DENY
```

Cross-tenant access chỉ có thể xảy ra nếu có **explicit policy/delegation** hợp lệ.

Không có implicit trust chỉ vì cùng Organization.

# 3. Memory Isolation — critical path

Đây là phần quan trọng nhất của TASK-036.

Không được:

```text
Tenant A
   ↓
Global Retriever
   ↓
Tenant B Memory
```

Mà phải:

```text
Tenant A
   ↓
Memory Namespace A
   ↓
Retriever A
   ↓
Memory A
```

và:

```text
Tenant B
   ↓
Memory Namespace B
   ↓
Retriever B
   ↓
Memory B
```

Search/ranking/filtering đều phải giữ tenant boundary.

Đặc biệt phải test các trường hợp:

```text
semantic search
keyword search
hybrid search
metadata filtering
recency ranking
artifact retrieval
knowledge retrieval
```

không thể trả về dữ liệu tenant khác.

# 5. Tenant Boundary Enforcement

Boundary phải được enforce ở:

```text
API
Context
Memory
Registry
Runtime
Storage
Tool
Audit
```

### API

Request không có tenant hợp lệ:

```text
DENY
```

### Context

Không được overwrite tenant context bằng dữ liệu từ worker.

### Registry

Không cho:

```text
tenant-A workflow
→ resolve tenant-B skill
```

### Artifact

Artifact reference phải được kiểm tra ownership trước khi read/write.

### Audit

Audit event phải chứa tenant identity để truy nguyên.

### Tool

Tool execution phải nhận scoped tenant context.

### Runtime

Execution không được chạy với tenant context khác với authorization context.

# 8. Security invariants

TASK-036 phải enforce:

### INV-023 — Tenant Isolation

> Cross-tenant access bị DENY mặc định.

Đây là invariant M7 được master plan định nghĩa chính thức. 

Các invariant liên quan:

* `INV-022 Identity First` — mọi execution có Principal.
* `INV-023 Tenant Isolation` — cross-tenant access deny mặc định.
* `INV-024 Credential Isolation` — credential scope được bảo vệ.
* `INV-029 Control Plane Isolation` — tenant workload không truy cập Control Plane nội bộ ngoài API contract. 

TASK-036 đặc biệt chịu trách nhiệm chính cho `INV-023`.

# 10. Test matrix

| Scenario                   | Expected              |
| -------------------------- | --------------------- |
| A đọc resource A           | PASS                  |
| B đọc resource B           | PASS                  |
| A đọc resource B           | **DENY**              |
| B sửa resource A           | **DENY**              |
| A search memory A          | PASS                  |
| A search memory B          | **DENY**              |
| A query global memory      | **DENY/unsupported**  |
| Missing tenant             | **DENY**              |
| Fake tenant header         | **DENY**              |
| Artifact A → execution B   | **DENY**              |
| Workflow A → skill B       | **DENY**              |
| Harness Run A → tenant B   | **DENY**              |
| Audit cross-tenant attempt | **Evidence required** |

Đặc biệt cần negative test kiểu:

```text
Create Tenant A memory:
"SECRET-A"

Create Tenant B memory:
"SECRET-B"

Search as Tenant A:
"SECRET"

Expected:
SECRET-A
NOT SECRET-B
```

# 11. Acceptance Criteria

TASK-036 chỉ PASS khi:

1. Tenant model có contract rõ ràng.
2. Principal từ TASK-035 được bind vào TenantContext.
3. Resource ownership được xác định.
4. Cross-tenant access bị deny mặc định.
5. Missing/unknown tenant fail-closed.
6. Memory retrieval không leak cross-tenant.
7. Artifact/workflow/skill/evaluation/harness isolation được enforce.
8. Audit ghi nhận tenant boundary violations.
9. Policy vẫn là authority quyết định cuối.
10. Không tạo control plane mới song song.
11. `INV-023` được automated test enforce.
12. Regression của M0–M6 PASS.
13. Evidence có provenance đầy đủ.
14. Harness verification chứng minh cả positive và negative cases.

Roadmap tổng hợp cũng yêu cầu mọi task phải đạt AC, regression dependency và không vi phạm invariant trước khi hoàn thành.
