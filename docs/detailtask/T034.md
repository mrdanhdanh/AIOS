## TASK-034 — Doctor + Readiness

TASK-034 là task cuối của M6. Theo roadmap, mục tiêu là **nâng `aiagent doctor` + `aiagent arch-health` thành AIOS Doctor Harness**, đồng thời xây **Readiness** theo nguyên tắc fail-closed. 

### 1. Mục tiêu

Xây H5 để AIOS có thể tự trả lời:

* Hệ thống có khỏe không?
* Kiến trúc có vi phạm không?
* Contract có hợp lệ không?
* Runtime / Workflow / Agent / Capability / Tool có hoạt động không?
* Policy/Security có vấn đề không?
* Evidence có đủ và đáng tin không?
* AIOS có **READY để release/execute** hay phải BLOCK?

TASK-034 **không tạo một Doctor subsystem độc lập**; nó nâng cấp các khả năng doctor/architecture-health đã có và tích hợp vào Harness.

### 2. Scope

Doctor phải kiểm tra tối thiểu các domain:

```text

```

Mỗi check trả về đúng một verdict:


**Không được biến `UNKNOWN` thành `PASS`.** Đây là nguyên tắc Evidence-First / fail-closed của toàn bộ roadmap.

Doctor chỉ **quan sát và kiểm chứng**; không tự ý sửa Runtime hoặc bypass Policy. Điều này phù hợp với boundary của M6: Harness gọi qua API, không chui vào implementation của Runtime.

### 4. Doctor Check Contract

Mỗi check nên có cấu trúc tương đương:

```yaml
check:
  id: architecture.contracts
  domain: architecture
  target: runtime
  severity: critical
  evidence_required: true
  verdict: PASS
  evidence: [...]
  message: "All contracts are compatible"
```

Các trường quan trọng:

* `check_id`
* `domain`
* `target`
* `severity`
* `status`
* `verdict`
* `evidence_refs`
* `message`
* `started_at`
* `completed_at`
* `duration`
* `producer_version`

Doctor không được chỉ trả về boolean kiểu `healthy=true`.

### 5. Readiness Engine

Readiness tổng hợp nhiều dimension:

```text
Architecture
Contracts
Tests
Evaluation
Security
Performance
Observability
Evidence
```

Ví dụ:

```text
Architecture   100%
Contracts       98%
Tests           97%
Evaluation      91%
Security        95%
Performance     88%
Observability   96%
-------------------
Overall         94.1%
```

Nhưng **Overall Score không quyết định READY một mình**. 

### Hard Gate

Ví dụ:

```text
Policy violation > 0
        ↓
RELEASE BLOCKED
```

Ngay cả khi:

```text
Overall = 99%
```

vẫn phải `BLOCKED`.

Tương tự cần hard-block cho các failure nghiêm trọng như:

* Architecture invariant violation
* Contract incompatibility
* Security critical error
* Evidence integrity failure
* Regression gate failure
* Policy violation
* Required doctor check = `ERROR`
* Required check = `UNKNOWN` nếu policy yêu cầu evidence chắc chắn

Nên tách:

Trong đó `UNKNOWN` không được tự động nâng lên `READY`.

### 7. Evidence

Mỗi Doctor Run phải tạo Evidence Package, tận dụng H1/H2:

```text
Doctor Run
├── run.json
├── checks/
│   ├── architecture.json
│   ├── runtime.json
│   ├── policy.json
│   └── ...
├── evidence/
├── readiness.json
└── report.json
```

Nhờ vậy có thể truy ngược:

```text
Readiness
 → Doctor Run
 → Check
 → Evidence
 → Runtime/Event/Artifact
```

Điều này trực tiếp phục vụ `INV-018 Evidence First`.

### 10. Acceptance Criteria mở rộng

TASK-034 chỉ PASS khi:

1. Doctor kiểm tra đầy đủ các domain yêu cầu.
2. Mỗi check có verdict `PASS/WARNING/ERROR/UNKNOWN`.
3. Mỗi verdict quan trọng có evidence provenance.
4. `UNKNOWN` không được promote thành `PASS`.
5. Readiness có score **và** hard gates.
6. Critical policy violation có thể block readiness.
7. Architecture violation có thể block readiness.
8. Evidence failure có thể block readiness.
9. Doctor không bypass Runtime/Policy boundary.
10. CLI `doctor` và `readiness` hoạt động.
11. Regression M0–M5 + M6 PASS.
12. Enforcement của **INV-017 → INV-021** PASS. TASK-034 nằm trong M6 nên phải tuân thủ toàn bộ 5 invariant Harness. 
13. Evidence đủ để replay/audit Doctor Run.
14. Readiness result deterministic với cùng input/evidence.

Roadmap tổng hợp cũng quy định TASK-034 phải đạt AC, regression các milestone trước và không vi phạm invariant.
