## TASK-056 — Long-Horizon Goal Execution & Durable Resume

**Mục tiêu**

Xây dựng **goal-level durability layer** cho phép một autonomous goal tồn tại qua **nhiều execution, nhiều workflow, nhiều session/restart** — không chỉ resume một workflow. Khi hệ thống biến mất (process crash, machine restart, runtime failure, session interruption, dependency unavailable), goal phải còn nguyên và tiếp tục **chính xác** từ điểm an toàn gần nhất: khôi phục được trạng thái authoritative, **xác minh tính hợp lệ** của state/plan/policy, rồi tiếp tục mà **không duplicate side effect, không mất provenance, không chạy lại bước đã xong**.

> **TASK-056 không phải "Checkpoint/Resume" mới.** Master Plan đã có `State Service` (`StateStore`/`Checkpoint`/`Snapshot`/`ExecutionState` — TASK-005, M1) + `Execution Service` (`Executor` với checkpoint events) + `ExecutionGraph` + `AutonomousGoalEngine`. TASK-056 là **lớp durability ở mức goal** phủ trên nền hiện có — **không tạo Checkpoint Service mới, không tạo subsystem song song**, giữ nguyên tắc Runtime-first.

TASK-056 thuộc **M9 – Autonomous**, nằm sau TASK-055 (Autonomous Recovery) và trước TASK-057 (Autonomous Memory).

### 1. Phạm vi — phân biệt execution-level vs goal-level resume

| Khía cạnh | Execution-level (M1, đã có) | Goal-level (TASK-056, task này) |
|-----------|------------------------------|----------------------------------|
| Đơn vị | Một `ExecutionPlan` / một workflow | Một `Goal` kéo dài qua nhiều execution |
| Thời gian | Trong một process | Qua giờ / ngày / tuần, qua restart |
| State | `ExecutionState` snapshot | Goal state + subgoals + graph + world/memory/artifact/policy/evidence refs |
| Trigger | Step fail / cancel | Process crash, machine restart, session interruption, dependency unavailable |
| Owner | `Executor` / `StateStore` | **Goal Durability Layer** (mới, trên Runtime) |

**Goal Durability Layer** chịu trách nhiệm:

```text
Autonomous Goal
      │
      ▼
Goal State
      │
      ├── Subgoals / Tasks
      ├── Execution Graph State
      ├── World State Reference
      ├── Memory References
      ├── Artifact References
      ├── Policy / Autonomy State
      └── Evidence / Provenance
              │
              ▼
       Durable Checkpoint
              │
      ┌───────┴────────┐
      ▼                ▼
   Validate          Recover
      │                │
      └───────┬────────┘
              ▼
           Resume
              │
              ▼
      Re-plan if stale
              │
              ▼
          Continue
```

Các thành phần (tất cả là capability/interface trên Runtime, **không** là service độc lập):

* **Goal Checkpoint Coordinator** — gom `Goal State` thành `Durable Checkpoint` atomic, versioned, qua `StateStore` hiện có.
* **Resume Validator** — xác minh checkpoint trước khi tiếp tục (hash, provenance, plan-compat, policy).
* **Stale Detector** — phát hiện checkpoint/plan đã lỗi thời do world/skill/workflow/policy/model thay đổi.
* **Idempotency Guard** — đảm bảo bước đã `COMPLETED` không chạy lại, side effect không bị duplicate.
* **Re-plan Bridge** — khi state obsolete, gọi Autonomous Planner (TASK-051) để re-plan thay vì tiếp tục plan cũ.

### 2. Checkpoint Semantics

Mỗi `Durable Checkpoint` là snapshot **authoritative execution state + references** (KHÔNG phải memory store — xem §6). Nội dung tối thiểu:

```text
DurableCheckpoint
├── checkpoint_id
├── goal_id
├── sequence (monotonic, atomic commit)
├── created_at
├── interruption_cause      # graceful_pause | process_crash | machine_restart | runtime_failure | session_interrupt | dependency_unavailable
├── goal_state              # GoalStatus + objective
├── current_subgoal         # đang thực hiện
├── completed_tasks[]       # task/step đã COMPLETED (idempotency set)
├── pending_tasks[]         # task/step chưa xong
├── execution_graph_state   # ref/serialized ExecutionGraph (NodeState)
├── world_state_ref         # ref tới World Model (TASK-052)
├── memory_refs[]           # ref tới Memory Coordinator (TASK-023/007) — KHÔNG copy data
├── artifact_refs[]         # ref tới ArtifactStore
├── policy_autonomy_state   # autonomy level + policy version tại checkpoint
├── recovery_state          # circuit-breaker / recovery context (TASK-055)
├── evidence_refs[]         # ref tới Evidence store (Rule 5)
└── content_hash = sha256(payload)
```

Quy tắc:

* Checkpoint **immutable** — cập nhật = checkpoint mới (sequence tăng).
* **Atomic commit** — ghi toàn bộ hoặc không ghi (tránh checkpoint cũ ghi đè checkpoint mới khi race).
* `content_hash` phát hiện corruption / tamper.
* Ghi qua `StateStore`/`ArtifactStore` (Runtime), **không** agent tự ghi FS (ARCH-001/003).
* Checkpoint lưu **references**, không sao chép memory/artifact payload (giữ Memory Isolation của M5).

### 3. Consistency Model

Chống 5 lỗi long-horizon:

1. **Re-run completed task** — `completed_tasks[]` là idempotency set; Resume bỏ qua task đã `COMPLETED`.
2. **Duplicate side effect** — mỗi external action gắn `action_id` + idempotency key; Resume không re-issue action đã acknowledged.
3. **Old checkpoint overwrites new** — `sequence` monotonic + atomic commit; write bị reject nếu `sequence ≤ current`.
4. **Resume from invalid state** — Resume Validator từ chối checkpoint không qua verify (hash + provenance + policy).
5. **Continue with obsolete plan** — Stale Detector so sánh plan-version / world-version / policy-version; nếu lỗi thời → re-plan (§5), không tiếp tục mù.

### 4. Crash / Interruption Semantics

Phân biệt rõ từng nguyên nhân (`interruption_cause`) để chọn chiến lược resume:

| Cause | Resume strategy |
|-------|-----------------|
| `graceful_pause` | Resume trực tiếp từ checkpoint gần nhất |
| `session_interrupt` | Resume + re-validate policy/autonomy |
| `dependency_unavailable` | Resume sau khi dependency recover (TASK-055 fallback) |
| `process_crash` | Resume từ checkpoint cuối; bỏ qua in-flight step chưa commit |
| `machine_restart` | Resume từ durable checkpoint; rebuild Runtime context từ refs |
| `runtime_failure` | Resume + Recovery (TASK-055) trước khi continue |

Quy tắc chung: **không bao giờ resume từ in-flight step chưa được checkpoint** (tránh half-state).

### 5. Tích hợp TASK-055 (Recovery) và Re-plan

```text
Failure / Interruption
   ↓
TASK-055 Recovery (circuit breaker, classify)
   ↓
Restore Durable Checkpoint (TASK-056)
   ↓
Resume Validator (verify)
   ↓
Stale Detector
   ├── fresh ──→ Resume → Continue
   └── stale ──→ Re-plan (TASK-051) → Continue
```

* TASK-055 trả lời: *"Khi execution/agent thất bại thì recovery thế nào?"*
* TASK-056 trả lời: *"Sau khi hệ thống biến mất/restart/interruption, goal còn nguyên và tiếp tục chính xác thế nào?"*
* Hai task **tách rõ**: Recovery khôi phục execution; Durable Resume khôi phục goal-state và quyết định re-plan nếu stale.

### 6. Ranh giới với TASK-057 (Autonomous Memory)

* Checkpoint **KHÔNG** phải memory store. Nó lưu **authoritative execution state + references**.
* Experience/failure đáng nhớ → qua **Memory Coordinator** (TASK-023/007), không nằm trong checkpoint.
* Checkpoint có `memory_refs[]` chỉ để **trỏ lại** memory cần thiết khi resume, không sao chép.
* Giữ đúng **Memory Isolation** của M5: durability layer và memory layer là hai concern riêng biệt.

### 7. Verification / Evidence (M6)

* Resume phải **chứng minh checkpoint hợp lệ trước khi tiếp tục** (Verification Before Verdict).
* `content_hash` khớp + `evidence_refs[]` tồn tại + policy re-validate thành công → mới Resume.
* Thiếu evidence → `INCONCLUSIVE` → **SAFE-STOP** (fail-closed, không auto-promote).
* Mọi resume attempt có provenance (`Checkpoint → Resume → Verify → Verdict`).

### 10. Acceptance Criteria

TASK-056 chỉ PASS khi:

* Goal kéo dài qua **nhiều execution/workflow/session** vẫn nguyên vẹn.
* `DurableCheckpoint` chứa đủ semantics (§2): goal/subgoal/completed/pending/graph/world/memory/artifact/policy/recovery/evidence.
* Checkpoint **atomic commit** + `sequence` monotonic (old không overwrite new).
* Resume **không** chạy lại `completed_tasks` (idempotency).
* Resume **không** duplicate side effect (idempotency key).
* Phân biệt được 6 interruption cause và chọn đúng strategy (§4).
* Resume xác minh `content_hash` + `evidence_refs` + policy trước khi continue.
* Stale Detector phát hiện plan/world/policy lỗi thời → **re-plan** (không continue mù).
* Tích hợp TASK-055: Recovery → restore checkpoint → validate → resume.
* **KHÔNG** tạo Checkpoint Service / memory store mới (dùng nền Runtime có sẵn).
* Checkpoint lưu **references**, không sao chép memory payload (Memory Isolation M5).
* Thiếu evidence → SAFE-STOP (fail-closed).
* Không tạo autonomous control plane thứ hai.
* Regression của các milestone trước PASS.
* Không vi phạm architecture invariants.
