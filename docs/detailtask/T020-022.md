# TASK-020 — Upgrade Pipeline

## 1. Metadata

* **Milestone:** M4 — Platform Edition
* **Task ID:** TASK-020
* **Tên:** Upgrade Pipeline
* **Mục tiêu canonical:** Xây upgrade/migration an toàn (resolve→backup→migrate→validate→rollback; dry-run).
* **Dependency trực tiếp:** TASK-019 — VS Code Extension
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


### 1. Mục tiêu

Xây pipeline nâng cấp/migration an toàn cho AIOS.

Nguồn định nghĩa chuỗi chính:

```text
Resolve
  ↓
Backup
  ↓
Migrate
  ↓
Validate
  ↓
Rollback
```

và phải có **dry-run**. Acceptance criterion quan trọng nhất: migration thất bại **không được làm mất certified state**, dry-run phải deterministic. 

### 2. Upgrade Flow

```text
Upgrade Request
      │
      ▼
Compatibility Check
      │
      ▼
Dependency Resolution
      │
      ▼
Preflight
      │
      ▼
Backup / Snapshot
      │
      ▼
Migration
      │
      ▼
Validation
      │
 ┌────┴────┐
PASS       FAIL
 │          │
 ▼          ▼
Commit    Rollback
 │          │
 ▼          ▼
Certified  Previous
State      State
```

### 3. Compatibility Check

Trước khi migration:

```text
Current Version
      ↓
Target Version
      ↓
Contract Versions
      ↓
Schema Versions
      ↓
Dependency Versions
      ↓
Compatibility Decision
```

Kết quả phải phân biệt:

```text
COMPATIBLE
MIGRATION_REQUIRED
INCOMPATIBLE
UNKNOWN
```

`UNKNOWN` không được tự động coi là compatible.

### 4. Upgrade Manifest

Mỗi upgrade phải có manifest mô tả:

```yaml
upgrade:
  id:
  source_version:
  target_version:

  contracts:
    - name:
      from:
      to:

  migrations:
    - id:
      type:
      reversible:

  dependencies:
    - component:
      required_version:

  validation:
    checks: []

  rollback:
    supported: true
```

Manifest là artifact có version và provenance.

### 5. Backup

Trước mutation phải tạo certified snapshot của những state liên quan:

```text
Configuration
Contracts
Registry
Database state
Artifacts metadata
Skill state
Prompt versions
Policy state
```

Không backup bừa toàn bộ filesystem nếu không cần.

### 6. Dry-run

Dry-run phải mô phỏng:

```text
Resolve
→ Dependency
→ Migration Plan
→ Validation Plan
```

nhưng **không tạo side effect**.

Ví dụ:

```text
Current: AIOS 0.4
Target: 0.5

[DRY-RUN]

✓ Contract compatible
✓ Dependency resolvable
✓ Schema migration required
✓ Backup required
✓ Rollback available

Result: READY
```

Hai lần chạy cùng input + state phải cho cùng migration plan.

### 7. Migration

Migration phải:

* deterministic khi có thể;
* idempotent;
* version-aware;
* có precondition;
* có postcondition;
* ghi evidence;
* có rollback strategy.

Không được migration trực tiếp nếu chưa qua Policy.

### 8. Validation

Sau migration:

```text
Contract validation
      ↓
Schema validation
      ↓
Registry validation
      ↓
Dependency validation
      ↓
Architecture validation
      ↓
Health check
      ↓
Regression
```

Chỉ khi toàn bộ gate PASS mới commit target state.

### 9. Rollback

Nếu bất kỳ hard gate nào FAIL:

```text
Migration
   ↓
Failure
   ↓
Stop mutation
   ↓
Rollback snapshot
   ↓
Validate previous state
   ↓
Restore certified state
```

Rollback cũng phải tạo evidence.

### 10. Deliverables

* Upgrade manifest schema.
* Compatibility checker.
* Dependency resolver integration.
* Backup/snapshot integration.
* Migration engine.
* Dry-run engine.
* Validation pipeline.
* Rollback engine.
* CLI/API.
* Migration evidence.
* Unit + integration + failure-injection tests.

Upgrade có preflight.
#### AC-020-02 — Compatibility được kiểm tra trước mutation.
Compatibility được kiểm tra trước mutation.
#### AC-020-03 — Dependency được resolve.
Dependency được resolve.
#### AC-020-04 — Backup/snapshot tồn tại trước migration.
Backup/snapshot tồn tại trước migration.
#### AC-020-05 — Dry-run không tạo side effect.
Dry-run không tạo side effect.
#### AC-020-06 — Dry-run deterministic.
Dry-run deterministic.
#### AC-020-07 — Migration có validation.
Migration có validation.
#### AC-020-08 — Migration failure tự động rollback khi policy yêu
Migration failure tự động rollback khi policy yêu cầu.
#### AC-020-09 — Certified state được phục hồi chính xác.
Certified state được phục hồi chính xác.
#### AC-020-10 — Không bypass Policy/Permission.
Không bypass Policy/Permission.

# TASK-021 — Observability + Architecture Health

## 1. Metadata

* **Milestone:** M4 — Platform Edition

* **Tên:** Observability + Architecture Health

* **Dependency trực tiếp:** TASK-020 — Upgrade Pipeline

* **Status:** PLANNED

### 1. Mục tiêu

Nguồn xác định phạm vi:

* Metrics
* Audit

# TASK-022 — Orchestrator v2

## 1. Metadata

* **Milestone:** M4 — Platform Edition
* **Task ID:** TASK-022
* **Tên:** Orchestrator v2
* **Mục tiêu canonical:** Nâng Orchestrator thành control plane có evaluation và improvement có kiểm soát.
* **Dependency trực tiếp:** TASK-021 — Observability + Architecture Health
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


### 1. Mục tiêu

Nâng Orchestrator từ v1 thành **control plane có khả năng giám sát execution, thu thập evaluation và đề xuất cải tiến**.

Nguồn xác định bốn trọng tâm:

```text
Execution Supervisor
Evaluation Collector
Improvement Advisor
Goal Reporting
```



### 2. Không được trở thành God Object

Đây là constraint quan trọng.

Không làm:

```text
Orchestrator
 ├── execute
 ├── evaluate
 ├── store
 ├── schedule
 ├── observe
 ├── improve
 └── everything
```

Mà:

```text
                  Orchestrator v2
                         │
       ┌─────────────────┼──────────────────┐
       ▼                 ▼                  ▼
Execution          Evaluation          Improvement
Supervisor         Collector            Advisor
       │                 │                  │
       ▼                 ▼                  ▼
 Runtime            Evaluation          Proposal
 Services           Framework
       │                 │
       └─────────┬───────┘
                 ▼
             Goal Manager
                 │
                 ▼
             Goal Report
```

### 3. Execution Supervisor

Supervisor theo dõi execution:

```text
CREATED
  ↓
QUEUED
  ↓
RUNNING
  ↓
NODE_PROGRESS
  ↓
COMPLETED / FAILED
```

Nhiệm vụ:

* observe;
* timeout detection;
* retry coordination;
* failure escalation;
* execution progress;
* state reconciliation.

Supervisor **không trực tiếp thực hiện Tool**.

### 4. Evaluation Collector

Sau execution:

```text
Execution
    ↓
Artifacts
    ↓
Events
    ↓
Test Results
    ↓
Evaluation
    ↓
Evaluation Collector
```

Thu thập:

```text
success
quality
latency
cost
tokens
failure
user feedback
```

Kết quả phải gắn với execution/workflow/version.

### 5. Improvement Advisor

Đây là bước đầu tiên để AIOS có vòng feedback:

```text
Execution
   ↓
Evaluation
   ↓
Logs / Metrics
   ↓
Improvement Advisor
   ↓
Proposal
```

Ví dụ:

```text
Observation:
workflow X retry rate = 38%

Proposal:
- optimize timeout
- add fallback capability
- update workflow template
```

**Proposal ≠ Action.**

Advisor không được tự:

```text
modify Runtime
modify Policy
install skill
change workflow
change prompt
```

nếu chưa qua authority/policy tương ứng.

### 6. Improvement Evidence

Mỗi proposal phải có:

```text
Observation
Evidence
Affected component
Expected benefit
Risk
Confidence
Proposed change
Validation plan
```

Ví dụ:

```yaml
proposal:
  id: IMP-001
  target: workflow.review
  evidence:
    executions: 127
    retry_rate: 0.38
  hypothesis:
    timeout_too_low: true
  expected:
    latency: -12%
    failure_rate: -8%
  validation:
    mode: simulation
```

### 7. Goal Reporting

Goal Manager M2 đã có long-running goals.

M4 nâng thành reporting:

```text
Goal
 ├── Tasks
 │    ├── Workflow
 │    ├── Execution

 │
 └── Progress Report
```

Report:

```text

Quality: 94%
Cost: ...

```

### 8. Improvement Loop

```text

   ↓

   ↓

   ↓

   ↓
```

Điểm quan trọng: **M4 mới chỉ xây feedback loop có kiểm soát**.

Autonomous self-modification thực sự thuộc các milestone sau.

# M4 Definition of Done

```text
Upgrade
✓ Compatibility
✓ Backup
✓ Migration
✓ Validation
✓ Rollback
✓ Dry-run

Observability
✓ Metrics
✓ Audit
✓ Prompt History
✓ Profiler
✓ Doctor
✓ Architecture Health

Orchestrator v2
✓ Execution Supervisor
✓ Evaluation Collector
✓ Improvement Advisor
✓ Goal Reporting
```

Hard gate:

* [ ] Upgrade failure không làm mất certified state.
* [ ] Dry-run deterministic.
* [ ] Architecture Health phát hiện violation.
* [ ] Audit/evidence có provenance.
* [ ] `UNKNOWN` không thành `PASS`.
* [ ] Improvement chỉ tạo proposal, không tự bypass Policy.
* [ ] Orchestrator không trở thành God Object.
* [ ] Unit + Contract + Integration + Architecture + E2E + Regression PASS.
* [ ] M0–M3 regression PASS.
* [ ] Đủ `PLAN → SPEC → CRITIQUE×2 → BREAKDOWN → REVIEW → IMPLEMENT → TEST → EVALUATE → COMMIT`.
