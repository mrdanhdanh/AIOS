## 1. Mục tiêu

Xây dựng năng lực Benchmark cho AIOS nhằm trả lời một câu hỏi rõ ràng:

> **Phiên bản mới có tốt hơn hoặc ít nhất không tệ hơn phiên bản trước hay không?**

Benchmark không chỉ đo một `score`. Mỗi lần benchmark phải so sánh tối thiểu:

* Quality
* Cost
* Latency
* Token usage
* Failure rate
* Policy violations

Benchmark phải sử dụng kết quả từ TASK-032 Evaluation Harness và Evidence từ TASK-030, thay vì tự tạo một hệ thống evaluation riêng.

Regression Gate biến kết quả benchmark thành **quyết định có kiểm soát**:

```text
Benchmark
   ↓
Compare Baseline
   ↓
Detect Regression
   ↓
Apply Threshold / Policy
   ↓
PASS / WARNING / FAIL
   ↓
Release Gate
```

## 5. Metric Model

Benchmark phải hỗ trợ ít nhất:

| Metric            | Ý nghĩa                            |
| ----------------- | ---------------------------------- |
| Quality           | chất lượng kết quả                 |
| Cost              | chi phí execution/model/tool       |
| Latency           | thời gian thực thi                 |
| Tokens            | input/output token usage           |
| Failure Rate      | tỷ lệ execution/evaluation failure |
| Policy Violations | số lần vi phạm policy              |

Mỗi metric phải có:

```text
name
value
unit
direction
threshold
source
provenance
```

`direction` xác định metric tăng là tốt hay xấu.

Ví dụ:

```text
quality       ↑ better
cost          ↓ better
latency       ↓ better
tokens        ↓ better
failure_rate  ↓ better
policy        ↓ better
```

## 6. Baseline

Benchmark bắt buộc phải có baseline rõ ràng.

Baseline có thể là:

* release trước;
* commit trước;
* artifact đã certification;
* benchmark run đã được promote.

Không được tự động chọn một baseline không xác định.

Nếu không có baseline:

```text
Benchmark = INCONCLUSIVE
```

không được tự động coi là PASS.

## 7. Comparison

Ví dụ:

```text
Baseline:
  quality = 0.91
  cost = $0.20
  latency = 2.4s
  tokens = 8,000
  failure_rate = 0.04
  policy_violations = 0

Candidate:
  quality = 0.86
  cost = $0.18
  latency = 2.1s
  tokens = 7,500
  failure_rate = 0.06
  policy_violations = 0
```

Kết luận:

```text
quality      -5.5%   REGRESSION
cost         -10%    IMPROVED
latency      -12.5%  IMPROVED
tokens       -6.25%  IMPROVED
failure_rate +50%    REGRESSION
policy        0       PASS
```

Candidate không được PASS chỉ vì cost/latency tốt hơn.

## 8. Regression Detection

Regression phải được đánh giá theo từng metric.

Ví dụ threshold:

```yaml
thresholds:
  quality:
    max_regression: 0.03

  cost:
    max_increase: 0.20

  latency:
    max_increase: 0.15

  tokens:
    max_increase: 0.20

  failure_rate:
    max_increase: 0.05

  policy_violations:
    allowed: 0
```

### Hard regression

Các trường hợp sau mặc định phải FAIL:

```text
policy violation > 0
quality regression vượt hard threshold
critical scenario failure
missing required evidence
baseline/candidate provenance không hợp lệ
benchmark result INCONCLUSIVE nhưng gate yêu cầu certainty
```

## 9. Regression Gate

Gate phải phân biệt:

### PASS

Không có regression vượt threshold.

### WARNING

Có degradation nhưng nằm trong tolerance được policy cho phép.

Ví dụ:

```text
Quality: +2%
Cost: +8%
Latency: +4%
```

có thể WARNING nếu policy cho phép.

### FAIL

Regression vượt threshold hoặc vi phạm hard gate.

Ví dụ:

```text
Before:
success = 91%

After:
success = 86%
```

→ `FAIL`.

Một ví dụ khác:

```text
Quality +2%
Cost +80%
```

→ ít nhất `WARNING`, và có thể `FAIL` tùy policy.

## 10. Policy Boundary

Regression Gate không được tự định nghĩa authority ngoài contract.

Luồng:

```text
Benchmark Result
      ↓
Regression Detector
      ↓
Policy / Gate Rules
      ↓
Verdict
```

Policy phải có thể quy định:

* metric nào là hard gate;
* metric nào được warning;
* regression tolerance;
* critical scenario;
* policy violation handling;
* missing evidence handling.

Fail-closed:

```text
UNKNOWN ≠ PASS
INCONCLUSIVE ≠ PASS
MISSING EVIDENCE ≠ PASS
```

## 18. Mandatory Test Cases

### Case 1 — No regression

```text
baseline quality = 0.90
candidate quality = 0.91
```

Expected:

```text
PASS
```

### Case 2 — Quality regression

```text
baseline = 0.91
candidate = 0.86
threshold = 0.03
```

Expected:

```text
FAIL
```

### Case 3 — Cost increase within tolerance

```text
cost +8%
allowed +20%
```

Expected:

```text
PASS
```

hoặc WARNING nếu policy yêu cầu cảnh báo.

### Case 4 — Excessive cost

```text
cost +80%
allowed +20%
```

Expected:

```text
REGRESSION
```

Gate:

```text
WARNING/FAIL
```

theo policy.

### Case 5 — Policy violation

```text
policy_violations = 1
allowed = 0
```

Expected:

```text
FAIL
```

### Case 6 — Missing baseline

Expected:

```text
INCONCLUSIVE
```

Không được PASS.

### Case 7 — Missing evidence

Expected:

```text
FAIL
```

nếu gate yêu cầu evidence đầy đủ.

### Case 8 — Critical scenario regression

Aggregate score tốt nhưng critical scenario fail.

Expected:

```text
FAIL
```

### Case 9 — False improvement

Candidate:

```text
quality +5%
cost +200%
```

Expected:

```text
WARNING/FAIL
```

tùy policy; không được PASS mù quáng.

### Case 10 — Deterministic repeat

Cùng:

```text
baseline
candidate
suite
policy
evidence
```

phải cho cùng gate decision.
