### 1. Mục tiêu

Xây **AIOS Developer Kit (ADK)** để developer có thể tạo và phát triển extension theo đúng public contracts của AIOS, thay vì tự dựng cấu trúc project, manifest, contract, test harness và lifecycle.

Luồng mục tiêu:

```text
Developer
   ↓
aios dev
   ├── create
   ├── validate
   ├── test
   ├── simulate
   ├── package
   └── inspect
        ↓
Extension Contracts
        ↓
Plugin Runtime
        ↓
AIOS Harness
```

Developer Kit **không trở thành runtime mới**. Nó chỉ là developer-facing tooling sử dụng các contract/API đã được định nghĩa ở TASK-043–046.

### 2. Phạm vi

#### 2.1 Extension project generator

CLI có khả năng tạo skeleton extension chuẩn:

```text
my-extension/
├── aios.extension.yaml
├── pyproject.toml
├── src/
│   └── my_extension/
│       ├── __init__.py
│       └── extension.py
├── tests/
│   ├── test_contract.py
│   └── test_extension.py
└── README.md
```

Generator phải lấy contract/schema hiện hành làm nguồn chuẩn, không hard-code một format riêng.

Các loại extension tối thiểu:

* Tool extension
* Capability extension
* Skill extension
* Workflow extension
* Agent extension

---

#### 2.2 Extension Manifest

Developer Kit phải hỗ trợ tạo và validate manifest, bao gồm tối thiểu:

```yaml
id: example.extension
name: Example Extension
version: 0.1.0
type: skill

aios:
  contract_version: "1.x"

dependencies: []

capabilities: []

permissions: []

resources: {}

entrypoint: my_extension.extension:Extension
```

Manifest phải được kiểm tra trước khi package/install.

Các lỗi như:

* thiếu `id`
* version không hợp lệ
* dependency sai
* contract không tương thích
* capability không tồn tại
* permission không hợp lệ

→ **FAIL-CLOSED**.

### 2.3 CLI

CLI đề xuất:

```text
aios dev create <name>
aios dev validate
aios dev test
aios dev simulate
aios dev package
aios dev inspect
```

Ý nghĩa:

| Command    | Trách nhiệm                                 |
| ---------- | ------------------------------------------- |
| `create`   | tạo extension skeleton                      |
| `validate` | validate manifest/contracts                 |
| `test`     | chạy extension tests                        |
| `simulate` | chạy qua Harness simulation                 |
| `package`  | tạo artifact phân phối                      |
| `inspect`  | hiển thị metadata/dependencies/capabilities |

Không thêm command thực hiện bypass Runtime/Policy.

### 2.5 Contract validation

Developer Kit phải kiểm tra:

```text
Extension
 ├── Metadata
 ├── Contract Version
 ├── Schema
 ├── Dependencies
 ├── Capabilities
 ├── Permissions
 ├── Resources
 └── Entrypoint
```

Contract không tương thích → không được package thành artifact hợp lệ.

---

### 2.6 Test integration

Developer Kit không thay thế pytest/vitest.

Nó chỉ đóng vai trò orchestration layer:

```text
aios dev test
      ↓
Test Runner
      ↓
pytest / vitest
      ↓
Harness
      ↓
Evidence
```

Test result phải có provenance để Harness có thể sử dụng trong certification ở TASK-049.

---

### 2.7 Simulation

Ví dụ:

```bash
aios dev simulate
```

phải cho phép extension được kiểm tra mà không tạo side effect thật.

Tối thiểu phải kiểm tra:

* contract validity
* capability resolution
* permission request
* policy decision
* lifecycle
* execution result
* evidence generation

---

### 2.8 Packaging

`aios dev package` tạo artifact immutable có metadata:

```text
Extension Artifact
├── manifest
├── source/package
├── contract metadata
├── dependency metadata
├── capability declarations
├── permission declarations
├── checksum
└── build evidence
```

Artifact phải sẵn sàng để TASK-048 sử dụng cho distribution và TASK-049 sử dụng cho certification.

### 5. Acceptance Criteria

#### AC-047-01 — Create

```text
aios dev create example
```

tạo được extension skeleton hợp lệ và có thể validate ngay.

#### AC-047-02 — Manifest validation

Manifest hợp lệ → `PASS`.

Manifest thiếu field bắt buộc / sai schema / incompatible contract → `FAIL`.

Không có trạng thái mơ hồ được coi là hợp lệ.

#### AC-047-03 — Contract compatibility

Extension chỉ được build/package nếu contract compatibility check PASS.

#### AC-047-04 — Test

```text
aios dev test
```

chạy được test suite của extension và trả kết quả có provenance.

#### AC-047-05 — Simulation

```text
aios dev simulate
```

chạy được extension qua Harness simulation mà không tạo side effect thật.

#### AC-047-06 — Packaging

Package thành công phải tạo artifact có:

* manifest
* version
* checksum
* dependency metadata
* capability metadata
* permission metadata
* evidence

#### AC-047-07 — Fail-closed

Các trường hợp:

```text
invalid manifest
incompatible contract
unknown capability
invalid permission
broken dependency
failed validation
```

→ package/install candidate **không được coi là valid**.

#### AC-047-08 — Runtime boundary

Architecture test phải chứng minh Developer Kit không bypass:

```text
Policy
Permission
Capability
Runtime
Harness
```

#### AC-047-09 — Deterministic path

Các validation có thể quyết định bằng rule/schema phải chạy deterministic, không gọi LLM.

#### AC-047-10 — Regression

Toàn bộ regression của M0–M7 phải PASS; đặc biệt không phá:

* Runtime contracts
* Policy/Permission
* Harness
* Identity/Tenant boundary
* Plugin Runtime
* Extension Contracts
* Ecosystem Registry
