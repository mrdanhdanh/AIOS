# TASK-053 — Autonomous Loop

## 1. Mục tiêu

Xây dựng vòng lặp autonomous khép kín cho AIOS:

```text
Goal
  ↓
Plan
  ↓
Act
  ↓
Observe
  ↓
Evaluate
  ↓
Learn
  ↓
Re-plan / Continue / Stop
```

TASK-053 không tạo một Orchestrator mới. Nó là **control loop** sử dụng các primitive đã có:

* TASK-050 — Autonomous Goal Engine
* TASK-051 — Autonomous Planner
* TASK-052 — World Model
* M5 — Planning / Execution Graph / Scheduler
* M6 — Harness / Evidence / Evaluation
* Runtime Policy / Permission / State / Event / Artifact

Nguyên tắc cốt lõi:

> Autonomous không đồng nghĩa với unrestricted. Mọi action vẫn phải đi qua Policy, Permission, Runtime và Evidence.

## 2. Phạm vi

### 2.1 Loop Controller

Tạo controller điều phối lifecycle của một autonomous cycle:

```text
OBSERVE
  ↓
ASSESS
  ↓
PLAN
  ↓
VALIDATE
  ↓
ACT
  ↓
OBSERVE
  ↓
EVALUATE
  ↓
LEARN
  ↓
DECIDE
  ├── CONTINUE
  ├── REPLAN
  ├── WAIT
  └── STOP
```

Controller chỉ điều phối; không trực tiếp thực thi tool hoặc runtime operation.

### 2.2 Cycle Contract

Mỗi cycle phải có định danh và trạng thái độc lập:

```text
AutonomousCycle
├── cycle_id
├── goal_id
├── parent_cycle_id
├── world_state_ref
├── plan_ref
├── execution_ref
├── observation_ref
├── evaluation_ref
├── learning_ref
├── iteration
├── started_at
├── completed_at
└── status
```

Status tối thiểu:

```text
CREATED
OBSERVING
PLANNING
VALIDATING
ACTING
EVALUATING
LEARNING
DECIDING
COMPLETED
REPLANNING
WAITING
STOPPED
FAILED
```

### 2.3 Observe

Sau mỗi execution, loop phải thu thập world-state delta:

```text
Previous World State
        +
Execution Evidence
        +
Runtime Events
        +
Artifacts
        +
Verification/Evaluation
        ↓
New World State
```

Không được coi final response của Agent là source of truth duy nhất.

### 2.4 Evaluate

Mỗi cycle phải xác định:

* Goal progress
* Action success/failure
* World-state change
* Policy violations
* Verification result
* Resource/cost usage
* Evidence completeness
* Whether replanning is required

Evaluation phải ưu tiên deterministic evidence và Harness; không dùng LLM làm verdict mặc định.

### 2.5 Learn

Learning trong TASK-053 chỉ tạo **candidate learning**, không tự động promote thành trusted system knowledge.

```text
Observation
    ↓
Candidate Learning
    ↓
Validation
    ↓
Evidence
    ↓
Eligible for promotion
```

Việc autonomous memory/promotion chuyên sâu thuộc TASK-057.

### 2.6 Re-plan

Loop có thể quay lại TASK-051 khi:

* plan không còn phù hợp world state;
* dependency thay đổi;
* action thất bại;
* resource không còn đủ;
* goal progress không đạt expectation;
* observation phát hiện state khác prediction.

Re-plan phải tạo version mới của plan, không overwrite plan history.

### 2.7 Stop Conditions

Loop bắt buộc có deterministic stop conditions:

```text
GOAL_COMPLETED
POLICY_DENIED
SAFETY_BLOCK
MAX_ITERATIONS
MAX_COST
MAX_RUNTIME
NO_PROGRESS
REPEATED_FAILURE
WORLD_STATE_INVALID
DEPENDENCY_BLOCKED
USER_STOP
```

Không được chạy vô hạn.

## 5. Loop State Machine

```text
CREATED
  ↓
OBSERVING
  ↓
PLANNING
  ↓
VALIDATING
  ├── DENIED → STOPPED
  └── PASS
       ↓
     ACTING
       ↓
    EVALUATING
       ↓
     LEARNING
       ↓
     DECIDING
       ├── CONTINUE → OBSERVING
       ├── REPLAN   → PLANNING
       ├── WAIT     → WAITING
       └── STOP     → STOPPED
```

Mọi transition phải tạo event và có evidence/reference tương ứng.

## 7. Deterministic Decision Policy

Thứ tự quyết định:

```text
1. Safety / Policy
2. Goal completion
3. Hard failure
4. Resource limits
5. Progress / stuck condition
6. Existing valid plan
7. Re-plan
8. Continue
```

LLM không được quyết định override các hard gate.

Ví dụ:

```text
Policy DENY
→ STOP

Goal complete
→ STOP

Budget exhausted
→ STOP

Plan invalid
→ REPLAN

Execution failed but retry policy allows
→ REPLAN / RETRY

Execution successful + goal incomplete
→ CONTINUE
```

## 9. Persistence

Cycle state phải persist để process restart không làm mất lifecycle.

Tối thiểu persist:

* cycle state;
* iteration;
* goal reference;
* plan version;
* execution reference;
* world-state reference;
* evidence reference;
* evaluation;
* decision;
* stop reason.

Snapshot/resume sử dụng State Service hiện có; không tạo persistence subsystem riêng.

## 11. Failure Semantics

Fail-closed:

```text
Unknown world state
        → không tự hành động nguy hiểm

Missing evidence
        → không coi action thành công

Invalid plan
        → không execute

Policy uncertainty
        → ASK / STOP tùy policy

Evaluation inconclusive
        → không promote thành success

State corruption
        → STOP
```

Recovery tự động chuyên sâu để TASK-055 xử lý.

* cycle state machine;
* transition validation;

* cycle persistence;
* plan version handling.

### Integration

Kiểm tra:

```text
Goal Engine
```

### Scenario

**Scenario A — Goal hoàn thành**

```text
Plan → Act → Observe → Evaluate
→ Goal complete
→ STOP
```

**Scenario B — Plan stale**

```text
Plan → Act
→ World state changed
→ Observation
→ REPLAN
```

**Scenario C — Policy denied**

```text
Plan → Validate
→ Policy DENY
→ STOP
→ no execution
```

**Scenario D — No progress**

```text
Cycle 1 → no progress
Cycle 2 → no progress
...
threshold
→ STOP
```

**Scenario E — Restart**

```text
Cycle RUNNING
→ process restart
→ load persisted state
→ resume safely
```

### Regression

Phải chạy regression của toàn bộ dependency closure trước khi PASS.

## 13. Acceptance Criteria

1. Autonomous cycle chạy được đầy đủ:

```text
plan → act → observe → evaluate → learn → decide
```

2. Cycle có persistent state và lifecycle rõ ràng.

3. Loop có thể `CONTINUE`, `REPLAN`, `WAIT` hoặc `STOP`.

4. Mọi execution vẫn đi qua Runtime + Policy + Permission + Capability.

5. Mọi autonomous decision quan trọng có evidence/provenance.

6. Goal completion phải dựa trên evaluation/verification, không chỉ Agent assertion.

7. Loop có deterministic stop conditions và không thể chạy vô hạn.

8. Re-plan tạo plan version mới, không phá audit history.

9. Process restart không làm mất cycle state.

10. Regression của các milestone trước PASS.

11. Không tạo control plane hoặc execution subsystem song song.

12. Architecture invariant của M9 không bị vi phạm.

## 14. Dependency / Gate

**Dependencies:**

```text
TASK-050 Autonomous Goal Engine
        ↓
TASK-051 Autonomous Planner
        ↓
TASK-052 World Model
        ↓
TASK-053 Autonomous Loop
```

Đồng thời phụ thuộc vào:

```text
M5 Planning / Execution Graph
M6 Harness / Evidence / Evaluation
Runtime Policy / Permission / State / Event
```

**Gate:**

```text
PLAN
→ SPEC
→ CRITIQUE ×2
→ BREAKDOWN
→ REVIEW
→ IMPLEMENT
→ TEST
→ EVALUATE
→ REGRESSION
→ COMMIT
```

Chỉ được đánh dấu `DONE` khi toàn bộ gate PASS; nếu thiếu evidence, regression hoặc verification → `BLOCKED`.

## 15. Definition of Done

TASK-053 hoàn thành khi AIOS có thể thực hiện tối thiểu một autonomous goal qua nhiều cycle:

```text
Goal
 ↓
Plan
 ↓
Act
 ↓
Observe
 ↓
Evaluate
 ↓
Learn
 ↓
Re-plan
 ↓
Act
 ↓
Observe
 ↓
Goal Complete
 ↓
STOP
```

và toàn bộ trajectory có thể truy xuất qua:

```text
Goal → Cycle(s) → Plan(s) → Execution(s)
     → Evidence → Evaluation → Decision(s)
```

Không có autonomous action nào bypass Policy/Permission/Runtime, và loop phải **fail-closed khi không đủ evidence hoặc không xác định được trạng thái an toàn**.
