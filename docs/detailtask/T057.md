## TASK-057 — Autonomous Memory

**Mục tiêu**

Xây dựng **Autonomous Memory có kiểm soát** — mở rộng capability trên Memory nền có sẵn (TASK-007) để hệ thống tự chủ lưu trữ **failure memory** (failure đã classify từ TASK-055 kèm recovery outcome) và **goal memory** (lịch sử goal, plan, outcome, observation) với **trust/verification guard, controlled retention và scoped access**.

> **TASK-057 không xây một "Memory System v2".** Canonical master spec chỉ yêu cầu *"Lưu failure/goal memory có kiểm soát"*. Do đó bản spec này **thu nhỏ về controlled persistence + trust + retention + scoped access**, không sở hữu embedding/retrieval architecture, không tạo security subsystem, không tạo control plane thứ hai.

TASK-057 thuộc **M9 – Autonomous**, nằm sau TASK-055 (Autonomous Recovery) và trước TASK-058 (Autonomous Experimentation). Liên quan chặt chẽ đến invariant **INV-034 (Autonomous Memory No Unverified Promote)** và **INV-024 (Credential Isolation)**.

### 1. Phạm vi — thu hẹp đúng canonical

**Memory Controller** là một capability trên Runtime, **consumer** của các contract hiện có:

```text
          Autonomous Loop
                 │
        Failure / Goal Event
                 │
                 ▼
        Memory Controller
          │          │
          │          └── Provenance Validator
          │
          ├── Safety / Redaction (consume T040 contract)
          │
          ├── Trust / Verification Guard (INV-034)
          │
          └── Retention Policy (deterministic)
                 │
                 ▼
        Autonomy Governor (T054)  ← decision, không do Memory Controller tự quyết
                 │
          Policy / Runtime
                 │
                 ▼
          Existing Memory (T007)
```

**Không có** (để giữ invariant no-parallel-control-plane):

```text
AutonomousMemoryStore
AutonomousVectorDB
AutonomousKnowledgeDB
AutonomousRetriever
```

Các thành phần (tất cả là capability/interface, không phải subsystem mới):

* **Failure Memory** — lưu failure đã classify + recovery outcome (từ T055) để tránh lặp lại.
* **Goal Memory** — lưu goal history, plan, outcome, observation.
* **Provenance Validator** — xác minh `evidence_ref` trỏ tới Evidence Store hợp lệ (chain `Evidence → Run → Artifact → Task → Requirement`).
* **Safety/Redaction** — consume security/redaction contract của T040 (Credential Isolation), **không** tự xây Credential Manager/PII detector.
* **Trust/Verification Guard** — `lesson_candidate` chỉ thành trusted sau verify; enforce INV-034.
* **Retention Policy** — TTL + deterministic eviction.

### 2. Memory Model (đã sửa theo review)

```text
FailureMemoryEntry
├── entry_id
├── goal_id / execution_id
├── failure_class        # từ TASK-055 (TRANSIENT/RESOURCE/...)
├── classification
├── recovery_strategy
├── outcome              # recovered / safe_stopped
├── evidence_ref         # phải valid (xem §4)
├── retrieval_metadata   # tags / scope hints — KHÔNG phải embedding_key
└── created_at

GoalMemoryEntry
├── entry_id
├── goal_id
├── execution_id
├── plan_ref
├── outcome              # completed / failed / paused
├── observation          # raw observation (không trusted)
├── lesson_candidate     # derived lesson, CHƯA trusted
├── evidence_ref         # phải valid (xem §4)
├── verification_status  # UNVERIFIED | VERIFIED
├── trust_status         # UNTRUSTED | TRUSTED
└── created_at
```

Quy tắc:

* **Không có `embedding_key`** trong core contract — embedding/retrieval là consumer concern (T007 knowledge pipeline / T023 Memory Coordinator), không thuộc core responsibility của T057.
* `lesson_candidate` **không mặc định trusted**:
  ```text
  lesson_candidate → verification → trusted lesson
  ```
  Chỉ `verification_status == VERIFIED` và `trust_status == TRUSTED` mới được Planner/Loop consume. Điều này bám sát INV-034 (không promote unverified memory) và chống memory poisoning.
* Mọi entry có `evidence_ref` **và** provenance phải valid (§4).
* Memory read/write qua Runtime/Capability, không agent tự truy cập FS (ARCH-003).

### 3. Controlled Retention (deterministic)

* **TTL** — entry hết hạn → archive/expire (tương thích `MemoryStore` lifecycle của TASK-007).
* **Max size** — giới hạn dung lượng; eviction theo **RetentionPriority xác định**:
  ```text
  RetentionPriority:
    TRUSTED  > VERIFIED > UNVERIFIED
    newer    > older
  ```
  Eviction deterministic: khi vượt size, evict entry có priority thấp nhất; nếu bằng priority, evict `created_at` cũ nhất. **Không** dùng semantic/LLM ranking.
* **Scope isolation** — memory namespace theo boundary hiện có (§6), không tự định nghĩa enterprise tenancy.
* **Deduplicate** — failure/goal trùng lặp (cùng goal_id + cùng signature) → update entry hiện có, không tạo vô hạn entry.

### 4. Provenance Validation (không chỉ reference)

`evidence_ref` phải **valid**, không chỉ là string tồn tại:

```text
MemoryEntry
   ↓
evidence_ref
   ↓
Evidence Store
   ↓
Run / Artifact / Task / Requirement   (provenance chain hoàn chỉnh)
```

* Memory entry **không có evidence hợp lệ → REJECT** (không phải "có một string là PASS").
* Evidence không tồn tại trong store → REJECT.
* Provenance chain đứt (thiếu Run/Artifact) → REJECT.

### 5. Memory Safety

* **No raw secret** — Safety/Redaction **consume** contract của T040 (Credential Isolation / Secret Isolation); nếu redaction fail → **không persist raw payload**.
* **Poisoning guard** — `lesson_candidate` chưa verify → `UNTRUSTED`, không được Planner dùng để ra quyết định.
* **Governor decision, not owner** — Memory Controller **không sở hữu autonomy policy**. Flow:
  ```text
  Memory Controller → Autonomy Governor (T054) → Policy/Runtime → MemoryStore
  ```
  T057 chỉ **consume** quyết định của Governor (budget/autonomy); ghi bị deny → **không persist**.
* **No parallel control plane** — Autonomous Memory là capability trên Runtime/Memory hiện có, không tạo store song song.

### 6. Scope Isolation (trên boundary hiện có)

* `scope = execution | goal | session | tenant (if available)`.
* TASK-057 **preserve** isolation boundary do Runtime/Memory layer cung cấp; **không tự định nghĩa enterprise tenancy model** (vì nằm trước M7/T036 đầy đủ).
* Cross-scope read (ví dụ Memory A đọc scope B) → **DENY**.

### 7. Integration với Planner/Loop (thu hẹp)

TASK-057 **chỉ chứng minh khả năng consume memory**, không chứng minh learning effectiveness:

```text
Autonomous Loop
      ↓
Memory Write (controlled)
      ↓
Memory Read (scoped, trusted only)
      ↓
Planner/Loop can consume scoped trusted memory
```

Chất lượng learning/effectiveness thuộc TASK-058 (Experimentation) và TASK-060 (Autonomous Evaluation) — không nằm trong AC của T057.

### 8. Deliverables

* Memory Controller (failure + goal memory) — capability trên T007.
* `FailureMemoryEntry` / `GoalMemoryEntry` contracts (đã sửa: không `embedding_key`, `lesson_candidate` + trust/verification).
* Provenance Validator (evidence valid, không chỉ reference).
* Safety/Redaction (consume T040 contract).
* Trust/Verification Guard (INV-034).
* Retention Policy (TTL + deterministic eviction).
* Deduplicate policy.
* Autonomy-gated write path (consume T054 decision).
* Unit + Contract + Integration + Architecture + E2E + Regression tests.
* ADR/docs nếu implementation tạo architectural decision mới.

### 9. Acceptance Criteria

TASK-057 chỉ PASS khi:

* Failure memory persist kèm `evidence_ref` **valid** (provenance chain hoàn chỉnh).
* Goal memory persist kèm `observation` + `lesson_candidate` (không lưu `lessons` trusted trực tiếp).
* `lesson_candidate` chưa verify → `UNTRUSTED`, Planner **không** dùng.
* Retention policy (TTL/size/scope) được enforce; eviction **deterministic**.
* Dữ liệu nhạy cảm bị redact qua T040 contract; redaction fail → không persist raw.
* Memory read tôn trọng scope (cross-scope → DENY).
* Entry unverified/poisoned không được trust/promote (INV-034).
* Ghi memory bị **Governor deny → không persist** (T057 không tự quyết autonomy).
* Memory entry thiếu/invalid evidence → **REJECT**.
* Duplicate failure/goal → deduplicate, không tạo vô hạn entry.
* T057 **không** tạo AutonomousMemoryStore/VectorDB/KnowledgeDB/Retriever.
* Regression của các milestone trước PASS.
* Không vi phạm architecture invariants.

### 12. Definition of Done

```text
PLAN
→ SPEC
→ CRITIQUE ×2
→ BREAKDOWN
→ REVIEW
→ IMPLEMENT
→ TEST
→ EVALUATE
→ REGRESSION
→ READY_TO_CLOSE

```

Không được đánh dấu `DONE` nếu thiếu artifact của lifecycle hoặc regression gate. Governance của AIOS quy định task chỉ được chuyển sang `DONE` khi toàn bộ Registry, Dependency, Architecture, Lifecycle, Evidence, Test/Evaluate và Regression gates đều PASS.

**Kết quả cuối TASK-057:** AIOS có **bộ nhớ tự chủ có kiểm soát** — lưu failure/goal memory trên nền Memory hiện có, trust/verify trước khi promote (INV-034), retention deterministic, scoped access, redact qua T040, và fail-closed khi thiếu provenance — **không tạo subsystem song song**.
