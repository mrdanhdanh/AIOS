## TASK-037 — Distributed Runtime + Runtime Node

## 1. Metadata

* **Milestone:** M7 — Enterprise
* **Task ID:** TASK-037
* **Tên:** Distributed Runtime + Runtime Node
* **Mục tiêu canonical:** Distributed Runtime + Runtime Node (single→multi instance).
* **Dependency trực tiếp:** TASK-036 — Multi-Tenancy + Tenant Boundary
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


### 1. PLAN

**Mục tiêu**

Tách Runtime Kernel hiện tại khỏi giả định “một process duy nhất”, tạo abstraction **Runtime Node** và **Runtime Router**, nhưng **không biến AIOS thành Kubernetes/cloud orchestrator**.

Luồng mục tiêu:

```text
User
  ↓
Identity / Tenant
  ↓
AIOS Orchestrator
  ↓
Runtime Router
  ↓
Runtime Node
  ├── Runtime Kernel
  ├── Worker
  ├── Capability
  └── Tool / Sandbox
```

Runtime Router chịu trách nhiệm chọn node; Orchestrator không được hard-code hoặc tự chọn server.

### 2. SPEC

#### 2.1 Runtime Node Contract

Mỗi node phải expose tối thiểu:

```yaml
node:
  id: runtime-vn-01
  version: "1.0"
  region: ap-southeast
  capabilities:
    - python
    - docker
    - ollama
  capacity:
    cpu: 32
    memory: 64GB
  health: healthy
  tenant_classes:
    - standard
    - secure
```

Contract cần có:

* `node_id`
* `version`
* `region`
* `capabilities`
* `capacity`
* `health`
* `tenant_classes`
* metadata/runtime identity
* contract/schema version

#### 2.2 Runtime Node Lifecycle

```text
REGISTERED
    ↓
HEALTHY
    ↓
DRAINING
    ↓
UNAVAILABLE
    ↓
REMOVED
```

Không được coi node `UNKNOWN` là healthy.

Node chỉ được nhận execution khi:

```text
health == HEALTHY
AND capacity_available
AND capability_match
AND tenant_allowed
AND policy_allowed
```

#### 2.3 Runtime Registry

Registry quản lý:

```text
RuntimeNodeRegistry
├── register()
├── unregister()
├── get()
├── list()
├── heartbeat()
├── mark_unhealthy()
└── find_candidates()
```

Registry **không thực thi execution**.

#### 2.4 Runtime Router

Router nhận:

```text
ExecutionRequirements
```

và trả:

```text
RuntimeNodeSelection
```

Các tiêu chí:

1. Tenant
2. Region
3. Capability
4. Capacity
5. Health
6. Latency
7. Policy
8. Cost

Không được chọn node chỉ dựa trên round-robin nếu selection đó vi phạm Policy/Tenant boundary.

#### 2.5 Runtime Kernel Boundary

Runtime Node chứa Runtime Kernel hiện tại:

```text
Runtime Node
└── RuntimeKernel
    ├── ExecutionService
    ├── ContextService
    ├── EventService
    ├── ArtifactService
    ├── PermissionService
    ├── PolicyService
    ├── SchedulerService
    ├── StateService
    └── ResourceService
```

TASK-037 **không tạo Runtime Service thứ hai**.

Nó chỉ thêm distributed boundary:

```text
Control Plane
      │
      ▼
Runtime Router
      │
      ├── Runtime Node A
      ├── Runtime Node B
      └── Runtime Node C
```

### 3. CRITIQUE ×2

#### Critique 1 — các rủi ro chính

**Rủi ro A — Runtime Router thành God Object**

Router không được quản lý:

* execution
* resource allocation
* tenant database
* policy implementation
* node lifecycle implementation.

Nó chỉ làm **candidate selection**.

**Resolution:** tách:

```text
RuntimeRouter
├── NodeCandidateResolver
├── NodeHealthFilter
├── CapabilityMatcher
├── CapacityFilter
└── NodeSelector
```

**Rủi ro B — Cross-tenant node selection**

Tenant A không được chọn node/class chỉ dành cho Tenant B.

**Resolution:** selection input bắt buộc chứa tenant context và policy decision.

**Rủi ro C — Node health không đáng tin**

`UNKNOWN` không được fallback thành `HEALTHY`.

**Resolution:** fail-closed.

**Rủi ro D — TASK-037 lấn sang TASK-038**

Lease, heartbeat-driven failover và rescheduling thuộc TASK-038.

**Resolution:** TASK-037 chỉ cung cấp node abstraction, registry, routing và health primitives cần thiết; **không triển khai distributed scheduler/lease/failover hoàn chỉnh**.

---

#### Critique 2 — Architecture

Kiểm tra các boundary:

```text
Orchestrator
    ↓
Runtime Router
    ↓
Runtime Node Contract
    ↓
Runtime Kernel
```

Không cho phép:

```text
Orchestrator → RuntimeNode.internal_service
Orchestrator → Docker host
Orchestrator → Runtime database
Worker → Runtime Registry
Worker → Runtime Router
```

Mọi execution vẫn phải đi qua Runtime contract, Policy và Permission.

**Kết luận critique:** scope hợp lệ nếu giữ Runtime Router là routing abstraction, không biến nó thành distributed execution engine.
