## TASK-061 — Advanced Stuck Detection

**Mục tiêu**

Xây dựng **stuck detection layer** cho Autonomous Loop — phát hiện các trạng thái tự chủ bị kẹt (stuck / loop / oscillation / plateau) mà không tiến triển, từ đó kích hoạt escalation / safe-stop / recovery một cách **fail-closed**. TASK-061 là **detection layer, không phải recovery engine, governor hay scheduler**.

TASK-061 thuộc **M9 – Autonomous**, nằm ngay sau TASK-060 (Autonomous Evaluation) và trước TASK-062 (Autonomous Scheduler). Tiếp nối TASK-053 (Autonomous Loop) + TASK-055 (Recovery) + TASK-060 (Evaluation). Trọng tâm canonical: **Phát hiện loop / oscillation / stuck**.

### 1. Phạm vi — 3 tầng riêng biệt (Detect ≠ Decide ≠ Recover)

```text
             TASK-053 Autonomous Loop
                       │
                       ▼
                  Execute Step
                       │
                       ▼
              TASK-060 Evaluation
                       │
                       ▼
              Progress / Trajectory
                       │
                       ▼
              Stuck Detector
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
     NO_PROGRESS   OSCILLATION   PLATEAU
          │            │            │
          └────────────┼────────────┘
                       ▼
                 Stuck Policy
                       │
                       ▼
              TASK-054 Governor
                       │
             ┌─────────┼─────────┐
             ▼         ▼         ▼
        ESCALATE   SAFE_STOP   RECOVER(T055)
```

Phân tầng trách nhiệm (tránh TASK-061 thành Recovery/Governor thứ hai):

* **Detector** trả lời: *Execution có đang kẹt không?* (qua metrics / trajectory).
* **Stuck Policy** trả lời: *Với stuck signal này, hành động logic là gì?* (policy-driven).
* **Governor / Recovery** trả lời: *Có được phép thực hiện hành động đó không?* (T054 / T055).

Các thành phần (capability trên Runtime, không phải subsystem mới):

* **Progress Monitor** — theo dõi `progress` qua các iteration của loop.
* **Oscillation Detector** — phát hiện lặp lại cùng state/action (cycle) qua trajectory hash.
* **Plateau Detector** — `progress` tăng < threshold qua N iteration liên tiếp.
* **Resource-Burn Detector** — cost/resource tăng mà progress không đổi.
* **Stuck Policy** — ánh xạ `StuckSignal` → candidate action (escalate / safe-stop / recover / revise).
* **Stuck Gate** — chỉ trigger action khi Governor (T054) authorize + autonomy đủ.

### 2. Stuck Signal Model

```text
StuckSignal
├── kind: NO_PROGRESS | OSCILLATION | PLATEAU | RESOURCE_BURN | DEADLOCK
├── severity: minor | major | critical
├── iteration_first_seen
├── confidence        # dựa trên evidence, không đoán
└── evidence_ref      # provenance tới trajectory/metrics
```

Quy tắc:

* Mỗi iteration phải được monitor (không bỏ qua).
* `confidence` thấp / thiếu evidence → **KHÔNG** kết luận stuck; fail-closed → escalate (không tự tiếp tục).
* Không bao giờ auto-promote "đang chạy" thành "đang tiến triển".
* Oscillation phải dựa trên trajectory hash ổn định, không đoán từ 1 điểm.

### 3. Detection Safety (fail-closed)

* **No silent continue** — stuck detected → không tiếp tục vòng lặp như bình thường.
* **Governor authority** — action (safe-stop / escalate / recover) phải qua Governor (T054).
* **Evidence required** — mọi stuck signal cần evidence; thiếu → escalate (không ignore).
* **Deterministic** — cùng trajectory + cùng detector version/config → cùng verdict.
* **No parallel control plane** — detection là capability trên Runtime, không tạo control plane thứ hai.

### 4. Deliverables

* Stuck Detection layer (không phải recovery/governor/scheduler).
* Progress Monitor + Oscillation / Plateau / Resource-Burn / Deadlock detectors.
* `StuckSignal` model + `StuckPolicy` (policy-driven mapping).
* Stuck Gate (trigger action chỉ khi Governor authorize + autonomy đủ).
* Fail-closed rule (thiếu evidence / confidence thấp → escalate, không ignore).
* Integration với Autonomous Loop (T053) + Evaluation (T060) + Governor (T054) + Recovery (T055).
* Unit + Contract + Integration + Architecture + Regression tests.
* ADR/docs nếu tạo architectural decision mới.

### 5. Acceptance Criteria

TASK-061 chỉ PASS khi:

* Mỗi iteration được monitor; không có "khoảng trống" không được kiểm tra.
* **Detect ≠ Decide ≠ Recover**: Detector trả signal, Stuck Policy trả candidate, Governor quyết định *có được phép*.
* `OSCILLATION` phát hiện được từ trajectory hash lặp lại (không đoán từ 1 điểm).
* `PLATEAU` phát hiện được khi progress < threshold qua N iteration.
* `RESOURCE_BURN` phát hiện được khi cost tăng mà progress không đổi.
* `confidence` thấp / thiếu evidence → escalate (fail-closed), **không** tự tiếp tục.
* Stuck signal không bao giờ auto-promote thành "tiến triển bình thường".
* Action tôn trọng autonomy level (vượt budget → BLOCK qua Governor).
* Stuck signal có evidence (provenance đầy đủ).
* Detection deterministic (cùng trajectory + detector version/config → cùng verdict).
* Tích hợp được với Autonomous Loop (T053) + Evaluation (T060).
* Không tạo autonomous control plane thứ hai.
* Regression của các milestone trước PASS; không vi phạm architecture invariants.

### 7. Test Matrix

| Scenario | Expected |
| -------- | -------- |
| loop lặp lại cùng state (trajectory hash) | OSCILLATION → escalate/safe-stop |
| progress < threshold qua N iteration | PLATEAU → candidate recover/revise |
| cost tăng, progress đứng yên | RESOURCE_BURN → escalate |
| iteration đầu, chưa đủ evidence | KHÔNG kết luận; monitor tiếp |
| confidence thấp | escalate (fail-closed), không ignore |
| thiếu evidence | escalate, không auto-continue |
| action vượt autonomy budget | BLOCK (Governor) |
| Governor ALLOW | thực thi action |
| cùng trajectory + detector version | cùng verdict (deterministic) |
| stuck signal lưu evidence | provenance đầy đủ |
