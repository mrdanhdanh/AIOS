## 1. Mục tiêu

Đưa AIOS từ mô hình distributed runtime có lease/quota/security sang trạng thái **production-resilient**:

```text
Runtime Failure
      ↓
Health Detection
      ↓
Drain / Lease Handling
      ↓
Failover
      ↓
Snapshot / Checkpoint
      ↓
Resume
      ↓
Evidence + Audit
```

TASK-041 phải bảo đảm:

* Không có Runtime Node đơn lẻ trở thành SPOF.
* Execution đang chạy không bị mất trạng thái khi node chết.
* Lease cũ không thể tiếp tục thực thi sau failover.
* Recovery phải dựa trên checkpoint/snapshot có evidence.
* Security-sensitive actions đều để lại audit trail.
* Audit có thể trả lời: **Who / What / When / Tenant / Agent / Workflow / Tool / Credential Scope / Policy / Result**.
* Health/failover/recovery không bypass Policy, Permission hoặc Runtime contracts.
* Harness có thể kiểm chứng toàn bộ failure/recovery path.

## 2. Phạm vi

### 2.1 High Availability Runtime

Mô hình tối thiểu:

```text
                 Control Plane
                      │
              Runtime Router
                 ┌────┼────┐
                 ▼    ▼    ▼
              Node A Node B Node C
```

Runtime pool phải hỗ trợ:

* heartbeat;
* health status;
* node registration;
* node drain;
* unhealthy detection;
* execution reassignment;
* lease expiration;
* resume từ checkpoint;
* graceful shutdown.

**Không** xây một distributed orchestrator mới. Control Plane hiện tại vẫn là authority.

### 2.2 Health State

Runtime Node cần state machine rõ ràng:

```text
UNKNOWN
  ↓
HEALTHY
  ↓
DEGRADED
  ↓
UNHEALTHY
  ↓
DRAINING
  ↓
DRAINED
```

Không được chuyển trực tiếp:

```text
HEALTHY → DEAD → kill execution
```

mà phải ưu tiên:

```text
UNHEALTHY
   ↓
DRAIN
   ↓
LEASE EXPIRED
   ↓
RECOVER
```

### 2.3 Execution Lease Safety

Một execution chỉ được có **một active lease**.

```text
Execution E1
    │
    └── Lease L1 → Runtime A

Runtime A fails
    ↓
L1 expires
    ↓
Scheduler verifies expiration
    ↓
Lease L2 → Runtime B
    ↓
Resume snapshot
```

Runtime B **không được resume** nếu lease L1 vẫn còn hợp lệ.

Đây là phần trực tiếp bảo vệ `INV-026 Distributed Execution Safety`.

### 2.4 Recovery

Recovery phải phân biệt:

| Failure                        | Action                                               |
| ------------------------------ | ---------------------------------------------------- |
| Node transient failure         | retry/health recovery                                |
| Node unavailable               | drain + failover                                     |
| Lease expired                  | acquire new lease                                    |
| Execution checkpoint available | resume                                               |
| Checkpoint corrupt             | fail-closed                                          |
| No valid checkpoint            | recovery không được giả vờ thành công                |
| Duplicate execution detected   | block                                                |
| Policy state unavailable       | block                                                |
| Audit unavailable              | tùy policy; security-sensitive path phải fail-closed |

Recovery result:

```text
RECOVERED
RECOVERED_WITH_WARNING
FAILED
INCONCLUSIVE
```

Không được biến `UNKNOWN` thành `RECOVERED`.

## 4. Recovery + Evidence

Mỗi recovery attempt tạo evidence:

```text
Failure Evidence
    ↓
Health Evidence
    ↓
Lease Evidence
    ↓
Checkpoint Evidence
    ↓
Failover Evidence
    ↓
Resume Evidence
    ↓
Final Verdict
```

Ví dụ:

```yaml
recovery:
  execution_id: exec-123
  failed_node: runtime-01
  failed_at: ...
  lease_id: lease-001
  lease_expired: true
  replacement_node: runtime-03
  snapshot_id: snap-123
  resume_result: success
```

Không được chỉ ghi:

```text
"Execution recovered successfully"
```

mà không có provenance.

## 5. Failure Scenarios bắt buộc

### Scenario A — Runtime node chết

```text
Node A
  ↓ failure
Health Monitor
  ↓
Drain
  ↓
Lease expired
  ↓
Node B
  ↓
Resume
  ↓
PASS
```

### Scenario B — Node chết giữa execution

Phải chứng minh:

* execution không chạy đồng thời trên A và B;
* snapshot cuối cùng được xác định;
* B resume đúng state;
* artifact không duplicate ngoài policy cho phép.

### Scenario C — Stale lease

```text
Old Node A
     │
     └── stale lease
          ↓
      DENY execution
```

Không được để node cũ tiếp tục chạy sau khi lease đã mất.

### Scenario D — Corrupt snapshot

```text
Snapshot checksum FAIL
        ↓
Recovery BLOCKED
        ↓
UNKNOWN / FAILED
```

Không được resume từ artifact không còn integrity.

### Scenario E — Audit failure

Security-sensitive operation không được silently tiếp tục nếu policy yêu cầu audit bắt buộc.

## 7. Acceptance Criteria

### AC-041-01 — HA

Có tối thiểu 3 Runtime Nodes trong test environment và một node failure không làm Control Plane mất khả năng điều phối.

### AC-041-02 — Failover

Execution có thể chuyển từ node lỗi sang node khỏe dựa trên lease + checkpoint hợp lệ.

### AC-041-03 — Single Active Lease

Không có test nào cho phép cùng một execution có hai active leases.

### AC-041-04 — Resume Integrity

Resume chỉ thành công khi snapshot/checkpoint hợp lệ và checksum/provenance PASS.

### AC-041-05 — Stale Lease Protection

Runtime sở hữu stale lease bị từ chối tiếp tục execution.

### AC-041-06 — Graceful Drain

Node chuyển `DRAINING` không nhận execution mới.

### AC-041-07 — Audit Completeness

Security-sensitive operations tạo audit event đầy đủ principal, tenant, action, resource, policy và result.

### AC-041-08 — Audit Integrity

Audit event có thể phát hiện modification/tampering.

### AC-041-09 — Recovery Evidence

Mỗi recovery attempt có evidence chain:

```text
Failure → Health → Lease → Snapshot → Failover → Resume → Result
```

### AC-041-10 — Fail-Closed

Nếu không xác minh được lease, snapshot integrity, policy hoặc required security evidence → **không được báo PASS**.

## 8. Architecture Constraints

TASK-041 **không được**:

* tạo Control Plane thứ hai;
* bypass Runtime Router;
* bypass Distributed Scheduler;
* bypass Policy Service;
* bypass Permission Service;
* bypass Credential Broker;
* tự quản lý resource thay Resource Service;
* tự tạo execution state store song song;
* cho Runtime Node tự quyết định policy;
* coi log thường là Audit Evidence.

Luồng chuẩn:

```text
Control Plane
    ↓
Health / Scheduler / Policy
    ↓
Runtime Router
    ↓
Runtime Node
    ↓
Execution
```
