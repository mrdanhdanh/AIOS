# TASK-039 — Quota + Cost + Resource Governance

## 1. Metadata

* **Milestone:** M7 — Enterprise
* **Task ID:** TASK-039
* **Tên:** Quota + Cost + Resource Governance
* **Mục tiêu canonical:** Quota + Cost + Resource Governance.
* **Dependency trực tiếp:** TASK-038 — Distributed Scheduler + Lease + Failover
* **Priority:** High

* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


TASK-039 thuộc **M7 – Enterprise**, đứng sau TASK-038 (Distributed Scheduler + Lease + Failover) và trước TASK-040 (Credential + Network + Sandbox Isolation). Master specification xác định mục tiêu là **giới hạn tài nguyên và chi phí theo tenant**. 

## 1. Mục tiêu

Xây lớp **Enterprise Resource Governance** để AIOS kiểm soát:

* quota theo tenant;
* resource consumption;
* execution concurrency;
* LLM token/cost;
* tool calls;
* storage;
* sandbox time;
* execution time;
* model cost;
* budget theo request/execution/tenant.

Nguyên tắc: **không để một tenant chiếm tài nguyên của toàn hệ thống**.

## 2. Phạm vi

### 2.1 Tenant Quota

Quota tối thiểu:

```yaml
tenant:
  quota:
    concurrent_executions: 20
    cpu: 8
    memory: 16GB
    llm_tokens_per_day: 5000000
    storage: 100GB
```

Ngoài các quota cơ bản, AIOS cần hỗ trợ:

```text
LLM calls
Tokens
Model cost
Tool calls
Execution time
Memory retrieval
Storage
Sandbox time
```

Quota phải được đánh giá theo **tenant context**, không chỉ theo process/runtime hiện tại.

### 2.2 Cost Governance

Luồng chuẩn:

```text
Request
  ↓
Cost Estimator
  ↓
Budget Policy
  ↓
Execution
  ↓
Actual Cost
  ↓
Usage / Billing Record
```

Ví dụ:

```text
Estimated cost = $0.20
Tenant budget  = $0.10
→ DENY
```

Hoặc:

```text
GPT estimate = $0.25
Ollama estimate = $0.01
→ Model Router có thể chọn Ollama
```

Việc đổi model vẫn phải tuân thủ **Model Routing Policy + Enterprise Policy**; TASK-039 không được bypass TASK-025.

## 3. Kiến trúc đề xuất

TASK-039 không được biến Resource Service thành God Object.

```text
                Governance Layer
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
    Quota Manager            Cost Governance
          │                       │
          ▼                       ▼
   Usage Collector          Cost Estimator
          │                       │
          └───────────┬───────────┘
                      ▼
                Budget Policy
                      │
             ┌────────┴────────┐
             ▼                 ▼
          ALLOW              DENY
             │
             ▼
        Runtime / Scheduler
```

Phân tách:

| Component            | Trách nhiệm                      |
| -------------------- | -------------------------------- |
| `QuotaManager`       | kiểm tra quota                   |
| `UsageCollector`     | ghi nhận usage                   |
| `CostEstimator`      | ước lượng cost                   |
| `BudgetPolicy`       | quyết định budget                |
| `GovernanceDecision` | kết quả allow/deny/ask           |
| `UsageLedger`        | lưu usage/cost                   |
| `ResourceGovernance` | orchestration giữa các component |

**Resource Service** vẫn sở hữu resource thực tế; Governance quyết định **tenant có được phép tiêu thụ resource đó hay không**.

## 4. Governance Decision

Nên chuẩn hóa contract:

```text
GovernanceRequest
├── principal
├── tenant
├── project
├── execution
├── requested_resources
├── estimated_cost
├── current_usage
└── policy_context
```

Kết quả:

```text
GovernanceDecision
├── decision: ALLOW | DENY | ASK
├── reasons[]
├── quota_status
├── budget_status
├── estimated_cost
├── remaining_budget
├── remaining_quota
└── evidence_ref
```

Không được trả về `ALLOW` nếu dữ liệu quota/cost cần thiết đang `UNKNOWN` mà policy yêu cầu fail-closed.

## 5. Quota Evaluation

Thứ tự:

```text
Identity
 ↓
Tenant
 ↓
Quota Lookup
 ↓
Current Usage
 ↓
Requested Resource
 ↓
Quota Evaluation
 ↓
ALLOW / DENY
```

Ví dụ:

```text
Concurrent executions:
current = 19
requested = 2
quota = 20

19 + 2 > 20
→ DENY
```

CPU:

```text
current = 6 CPU
requested = 4 CPU
quota = 8 CPU

6 + 4 > 8
→ DENY
```

Quota check phải là **atomic/reservation-aware**, tránh race condition:

```text
Request A → thấy còn 2 CPU
Request B → thấy còn 2 CPU
A + B cùng allocate
→ vượt quota
```

Do đó cần cơ chế:

```text
check → reserve → execute → settle/release
```

## 6. Cost Evaluation

Cost estimator phải hỗ trợ ít nhất:

```text
LLM input tokens
LLM output tokens
model price
tool invocation
execution duration
sandbox duration
resource consumption
storage
memory retrieval
```

Tách:

```text
EstimatedCost
ActualCost
```

Không được dùng `estimated_cost` để giả định `actual_cost`.

Ví dụ:

```text
Estimated:
$0.08

Actual:
$0.11
```

Ledger phải giữ cả hai để Harness/Evaluation có thể phân tích sai lệch.

## 7. Budget Policy

Ví dụ:

```yaml
budget:
  daily: 10.00
  per_execution: 0.50
  per_request: 0.20
  action_on_exceed:
    - deny
```

Các policy có thể:

```text
ALLOW
DENY
ASK
DOWNGRADE
QUEUE
```

`DOWNGRADE` chỉ là đề xuất governance; việc chọn model cụ thể vẫn thuộc Model Router.

## 10. Acceptance Criteria chi tiết

Ngoài AC tổng quát của master specification, TASK-039 nên được coi là đạt khi chứng minh được:

### Quota

* [ ] Tenant vượt `concurrent_executions` → `DENY`.
* [ ] Tenant vượt CPU/RAM quota → `DENY`.
* [ ] Tenant trong quota → `ALLOW`.
* [ ] Concurrent requests không tạo race vượt quota.
* [ ] Reservation được release khi execution fail/cancel.
* [ ] Quota được tính đúng theo tenant/project boundary.

### Cost

* [ ] Estimate được tính trước execution.
* [ ] Budget vượt ngưỡng → `DENY` hoặc policy-defined action.
* [ ] Actual cost được ghi nhận sau execution.
* [ ] Estimated và actual cost không bị đánh đồng.
* [ ] Cost record có provenance.

### Model integration

* [ ] Cost constraint được truyền tới Model Router.
* [ ] Model Router không chọn model vượt policy/budget.
* [ ] Fallback model vẫn phải qua governance.

### Fail-closed

* [ ] Không xác định được quota/budget bắt buộc → không tự động `ALLOW`.
* [ ] Không có tenant context hợp lệ → không thực hiện governance như tenant hợp lệ.
* [ ] Governance failure không được bypass bằng cách gọi trực tiếp Runtime.

### Architecture

* [ ] Không sửa Resource Service thành God Object.
* [ ] Governance không trực tiếp execute tool.
* [ ] Không bypass Policy/Permission.
* [ ] Không tạo control plane song song.
* [ ] Không vi phạm `INV-022..029`.

Master specification yêu cầu task đạt AC, regression của các milestone trước PASS và không vi phạm invariant.
