### TASK-029 — Phase 1: SPEC

## 1. Metadata

* **Milestone:** M6 — AIOS Harness
* **Task ID:** TASK-029
* **Tên:** Harness Kernel + Contract + Registry + Run
* **Mục tiêu canonical:** Kernel Harness độc lập với Runtime (contract/registry/run/lifecycle).
* **Dependency trực tiếp:** TASK-028 — Parallel Scheduler
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


**Mục tiêu**

Xây `aios/harness/` thành một subsystem có contract và lifecycle thống nhất, cho phép mọi Harness Run:

`Create → Prepare → Validate → Run → Verify → Complete/Fail → Diagnose`

Mỗi run phải có định danh và metadata đủ để truy nguyên:

`Release → Harness Run → Execution Trace → Evaluation → Failure`.

Thiết kế này phù hợp với H1 trong Master Plan: Harness Kernel cung cấp chung `Context · Run · Event · Result · Artifact · Report`, thay vì mỗi H2–H5 tự xây một bộ hạ tầng riêng.

**Phạm vi**

1. **Harness Contracts**

   * `Harness`
   * `HarnessRun`
   * `HarnessContext`
   * `HarnessEvent`
   * `HarnessResult`
   * `HarnessArtifact`
   * `HarnessReport`

2. **Harness Registry**

   * đăng ký Harness theo `id + version`
   * lookup deterministic
   * kiểm tra duplicate ID/version
   * lifecycle enable/disable nếu cần
   * không cho Registry tự thực thi Harness

3. **Harness Runner**

   * tạo `HarnessRun`
   * chuẩn bị context
   * validate input/config
   * invoke Harness
   * capture lifecycle events
   * tạo result/report
   * chuyển trạng thái fail-closed khi exception hoặc validation failure

4. **Lifecycle**

   ```text
   CREATED
      ↓
   PREPARING
      ↓
   VALIDATING
      ↓
   RUNNING
      ↓
   VERIFYING
      ↓
   COMPLETED
   ```

   Failure path:

   ```text
   RUNNING → FAILED → DIAGNOSED
   ```

5. **Run Persistence / Traceability**
   `HarnessRun` tối thiểu phải chứa:

   * `run_id`
   * `harness`
   * `target`
   * `version`
   * `environment`
   * `started_at`
   * `status`

6. **Integration Boundary**
   Harness chỉ gọi Runtime/Orchestrator thông qua API/contract được phép; **không import hoặc truy cập implementation nội bộ của Runtime**. Đây là tiền đề trực tiếp của `INV-017 Harness Isolation`. Master Plan xác định M6 bổ sung `INV-017..021`.

### Acceptance Criteria

**AC-029-01 — Contract**

Harness và HarnessRun có schema ổn định, versionable và validate được.

**AC-029-02 — Registry**

```text
register(Harness)
        ↓
duplicate → REJECT
valid     → REGISTERED
```

Lookup cùng một identifier/version luôn cho cùng một Harness.

**AC-029-03 — Lifecycle**

Một run hợp lệ phải đi đúng lifecycle:

```text
CREATED
→ PREPARING
→ VALIDATING
→ RUNNING
→ VERIFYING
→ COMPLETED
```

Không được skip transition bất hợp lệ.

**AC-029-04 — Failure**

Exception trong execution không được biến thành `COMPLETED`.

Kết quả phải:

```text
RUNNING → FAILED → DIAGNOSED
```

hoặc trạng thái fail tương ứng theo contract.

**AC-029-05 — Run Identity**

Mỗi lần chạy tạo `run_id` duy nhất và không reuse.

**AC-029-06 — Traceability**

Từ `run_id` phải truy được Harness, target, version, environment, lifecycle events và final result.

**AC-029-07 — Isolation**

Architecture test phải fail nếu Harness import trực tiếp Runtime Service implementation.

**AC-029-08 — Deterministic**

Registry lookup và lifecycle transition không cần LLM.

**AC-029-09 — Test**

Phải có tối thiểu:

```text
Unit
Contract
Lifecycle
Registry
Failure
Architecture
Integration
Regression
```

**AC-029-10 — M6 compatibility**

Thiết kế phải cho phép TASK-030 sử dụng lại Kernel để bổ sung:

```text
Execution Verification
Evidence Package
Replay
```

mà **không sửa lại Harness Core**.

**4. Registry**

Registry phải quản lý Harness theo `id + version`, hỗ trợ:

* register
* lookup
* list
* version resolution
* duplicate detection
* lifecycle compatibility

Không được để từng loại Harness tự tạo registry riêng.

**5. Context**

`HarnessContext` là boundary truyền dữ liệu vào một Harness Run.

Nó phải phân biệt tối thiểu:

```text
target
configuration
environment
run metadata
runtime references
artifacts/evidence references
```

Không copy implementation state của Runtime vào Harness.

**6. Result**

Result phải phân biệt:

```text
PASS
PASS_WITH_WARNING
FAIL
INCONCLUSIVE
```

Đặc biệt:

> `execution completed` **không đồng nghĩa** `Harness PASS`.

Việc xác minh post-condition thuộc TASK-030; TASK-029 chỉ cung cấp contract/kernel để TASK-030 sử dụng.

**7. Acceptance Criteria**

Theo roadmap, TASK-029 chỉ được PASS khi AC của task đạt và regression của các milestone trước vẫn PASS, không vi phạm invariant. 

Cụ thể nên kiểm chứng:

* Harness đăng ký và lookup được.
* Duplicate `harness_id + version` bị reject.
* Lifecycle transition hợp lệ được enforce.
* Transition bất hợp lệ bị reject.
* Mỗi run có `run_id` duy nhất.
* Run có trạng thái cuối rõ ràng.
* Context không truy cập trực tiếp Runtime implementation.
* Result hỗ trợ 4 verdict chuẩn.
* Registry không phụ thuộc implementation của từng Harness.
* Kernel chạy được với fake/mock target hoàn toàn offline.
* Unit + contract + architecture tests PASS.
* Regression M0–M5 PASS.
