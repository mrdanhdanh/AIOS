## TASK-109 — Model Contracts

**Mục tiêu**

Triển khai **Model Contracts** như một năng lực có contract, evidence và harness riêng — định nghĩa API/schema chuẩn cho model (request/response, capabilities, metadata, usage) mà không khóa AIOS vào một vendor. TASK-109 là **foundation của M17, không phải provider mới** (dựa trên Model Contract + Provider Registry T006 + Model Router T025).

TASK-109 thuộc **M17**, ngay sau T108 (M16). Trọng tâm canonical: **Model Contracts**. Đây là task mở M17.

### 1. Phạm vi — Contract chuẩn, không vendor lock

```text
Model Contracts
├── Model Schema          (request/response, capabilities, metadata)
├── Capability Declaration (model có thể làm gì)
├── Usage Schema          (token/cost/latency)
└── Policy Boundary       (contract không bypass policy)
```

* **Model Schema** — định nghĩa cấu trúc request/response chuẩn cho mọi model.
* **Capability Declaration** — model khai báo capability (chat/embed/vision…).
* **Usage Schema** — chuẩn hóa usage (token, cost, latency) để T115 dùng.
* **Policy Boundary** — contract không bypass permission/policy (T113).

### 2. Model Contract

```text
ModelContract
├── model_id
├── provider_ref
├── capabilities          (chat/embed/vision/...)
├── request_schema
├── response_schema
├── usage_schema          (token/cost/latency)
└── policy_ref            (T113)
```

Quy tắc:

* Mọi model phải implement `ModelContract` để được dùng trong AIOS.
* Contract không chứa logic vendor; adapter (T110) mới implement.
* Mọi call có provenance (T001 Rule 5).
* Cùng contract + cùng input → cùng schema validation (deterministic).

### 3. Model Contract Safety

* **Fail-closed** — contract không hợp lệ → reject, không promote PASS (T078).
* **Evidence required** — mọi call có provenance (T001 Rule 5).
* **Deterministic** — cùng input → cùng validation.
* **No vendor lock** — contract độc lập provider; adapter (T110) thay thế được.
* **Policy boundary** — dùng Permission/Policy (T113) + Provider Registry (T110).

### 4. Deliverables

* Model Contract (API/schema chuẩn: request/response/capabilities/usage).
* Capability Declaration schema.
* Usage Schema (cho T115).
* Policy Boundary (T113).
* Integration với Provider Registry (T110) + Model Router (T025) + Evidence (T001).
* Unit + Contract + Integration + Architecture + Regression tests.
* ADR/docs (bắt buộc — contract chuẩn).

### 5. Acceptance Criteria

TASK-109 chỉ PASS khi:

* Model Contract định nghĩa rõ request/response/capabilities/usage schema.
* Contract không khóa vendor; adapter (T110) thay thế được.
* Contract không hợp lệ → reject (fail-closed, T078).
* Mọi call có provenance (T001 Rule 5).
* Cùng input → cùng validation (deterministic).
* Tích hợp được với Provider Registry + Model Router + Evidence.
* Regression của các milestone trước PASS; không vi phạm invariants.
