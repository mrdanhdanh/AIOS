# TASK-023 — Memory Coordinator

## 1. Metadata

* **Milestone:** M5 — Core Intelligence
* **Task ID:** TASK-023
* **Tên:** Memory Coordinator
* **Mục tiêu canonical:** Điều phối 4 loại memory và isolation; tích hợp Runtime/Harness hiện có.
* **Dependency trực tiếp:** TASK-022 — Orchestrator v2
* **Priority:** High
* **Status:** PLANNED
* **Execution model:** Runtime-first · Policy-first · Evidence-first · Fail-closed


## 1. Mục tiêu

Xây dựng **Memory Coordinator** làm tầng điều phối trung tâm giữa các Memory Store và Context Service.

M5 không tạo thêm một hệ memory mới. TASK-023 nâng cấp tầng quyết định để AIOS trả lời được:

> Trong toàn bộ memory hiện có, thông tin nào thực sự cần cho execution hiện tại?

Bốn nguồn memory hiện hữu gồm:

* Conversation Memory
* Session Memory
* Knowledge Memory
* Artifact Memory

TASK-023 phải biến các nguồn này thành một pipeline thống nhất:

```text
Memory Stores
    ↓
Memory Coordinator
    ↓
Retrieve
    ↓
Filter
    ↓
Rank
    ↓
Deduplicate
    ↓
Compress
    ↓
Prioritize
    ↓
Memory Context
    ↓
Context Service
```

Roadmap xác định TASK-023 là task đầu tiên của M5 và là nền tảng trực tiếp cho TASK-024 Context Optimizer.

## 3. Architecture Boundary

Kiến trúc bắt buộc:

```text
Agent
  │
  ▼
Orchestrator
  │
  ▼
Memory Coordinator
  │
  ├── Conversation Memory
  ├── Session Memory
  ├── Knowledge Memory
  └── Artifact Memory

  ▼

```

Agent **không được**:

```text

Agent → SessionStore
Agent → VectorStore
Agent → KnowledgeStore
Agent → ArtifactStore
```

Thay vào đó:

```text
Agent
  ↓

  ↓
Memory Coordinator
  ↓
Memory Store
```

Đây là yêu cầu cốt lõi của **INV-011 — Memory Isolation**.

## 5. MemoryQuery

Tạo contract `MemoryQuery`.

Các trường tối thiểu:

```text
query
memory_types
execution_id
workflow_id
agent_id
scope
filters
max_candidates
token_budget
ranking_policy
required_provenance
```

Ví dụ:

```yaml
query:
  text: "tiếp tục sửa lỗi Oracle hôm qua"
  memory_types:
    - conversation
    - session
    - knowledge
    - artifact
  token_budget: 4000
  required_provenance: true
```

`MemoryQuery` không phụ thuộc implementation cụ thể của vector database hoặc storage engine.

## 6. MemoryCandidate

Mọi kết quả retrieval phải được chuẩn hóa thành `MemoryCandidate`.

Tối thiểu:

```text
candidate_id
memory_type
content
source
metadata
timestamp
importance
relevance
provenance
checksum
scope
```

Ví dụ:

```yaml
candidate:
  candidate_id: mem-001
  memory_type: conversation
  content: "Oracle TIMESTAMP issue..."
  source: conversation-2026-08-20
  timestamp: ...
  importance: 0.8
  provenance:
    source_id: conversation-2026-08-20
    artifact_id: null
```

Không được đưa memory không có provenance vào final selection khi query yêu cầu provenance.

## 7. Retrieval Strategy

Coordinator phải hỗ trợ các strategy:

```text
Exact
Keyword
Semantic
Metadata
Recency
Importance
Hybrid
```

Không được giả định semantic search luôn tốt nhất.

Ví dụ:

```text
"Oracle TIMESTAMP issue"
```

có thể tìm:

```text
Conversation → Oracle TIMESTAMP issue
Session      → debugging Oracle
Knowledge    → Oracle timezone documentation
Artifact     → previous code patch
```

Hybrid retrieval nên được ưu tiên khi request không đủ rõ để dùng một strategy duy nhất.

---

## 8. Deterministic Ranking

Ranking phải hoạt động mà **không cần LLM**.

Điểm tổng quát:

```text
MemoryScore =
    semantic_score
  + relevance_score
  + recency_score
  + importance_score
  + source_priority
```

Các thành phần phải được chuẩn hóa về cùng miền điểm trước khi combine.

Ví dụ policy:

```yaml
ranking:
  semantic: 0.30
  relevance: 0.30
  recency: 0.15
  importance: 0.15
  source_priority: 0.10
```

LLM không được trở thành ranking engine mặc định.

Nếu ranking deterministic đủ khả năng → không gọi LLM.

---

## 9. Source Priority

Memory type có thể có priority khác nhau tùy execution.

Ví dụ mặc định:

```text
Current Session
    >
Current Conversation
    >
Relevant Artifact
    >
Knowledge
    >
Historical Conversation
```

Priority phải là policy/configurable, không hard-code vào Agent.

---

## 10. Filtering

Sau retrieval phải filter trước ranking cuối.

Filter có thể gồm:

* memory type;
* execution scope;
* workflow scope;
* agent scope;
* timestamp;
* metadata;
* relevance threshold;
* provenance requirement;
* lifecycle state;
* access permission.

Memory không phù hợp scope phải bị loại bỏ trước khi được inject.

---

## 11. Deduplication

Các Memory Store có thể chứa cùng một thông tin.

Ví dụ:

```text
Conversation:
"Oracle timezone bug fixed"

Artifact:
commit abc123:
"Fix Oracle timezone bug"
```

Coordinator phải phát hiện nội dung trùng hoặc gần trùng và tránh đưa cả hai bản đầy đủ vào final context.

Deduplication phải bảo toàn provenance.

Không được xóa candidate chỉ vì trùng content nếu bản còn lại không có provenance tương đương.

---

## 12. Memory Budget

Coordinator phải hỗ trợ budget.

Ví dụ:

```text
Total memory budget = 4,000 tokens

Conversation = 1,000
Session      =   800
Knowledge    = 1,200
Artifact     =   800
Reserve      =   200
```

Nếu tổng candidate vượt budget:

```text
Priority
→ Score
→ Budget
→ Selection
```

Không được truncate ngẫu nhiên.

Memory Coordinator chịu trách nhiệm tạo selection phù hợp; Context Optimizer của TASK-024 sẽ thực hiện tối ưu context sâu hơn.

## 15. Isolation

Memory Coordinator phải enforce boundary giữa:

```text
Conversation
Session
Knowledge
Artifact
```

Không được phép:

```text
Agent → Memory Store
```

và không được phép Coordinator bỏ qua scope/access rules.

Mọi memory selection phải có scope.

Nếu scope không xác định hoặc access không được xác nhận:

```text
DENY / EXCLUDE
```

Không mặc định `ALLOW`.

## 16. Provenance

Mọi selected memory cần truy ngược được:

```text
MemoryCandidate
    ↓
Memory Source
    ↓
Artifact / Document / Conversation / Session
```

Tối thiểu cần:

```text
source_id
memory_type
created_at
content_hash/checksum nếu có
parent_artifact nếu có
```

Không biến:

```text
UNKNOWN
```

thành:

```text
TRUSTED MEMORY
```

nếu provenance không xác định.

## 21. Error Handling

Các lỗi chính:

```text
Provider unavailable
Invalid query
Permission denied
Scope missing
Ranking failure
Budget calculation failure
Provenance missing
```

Nguyên tắc:

```text
Không chắc memory có hợp lệ
→ không inject memory đó
```

Provider lỗi không được khiến Coordinator tự động truy cập implementation khác ngoài policy.

Fallback chỉ được thực hiện qua contract/provider configuration.
