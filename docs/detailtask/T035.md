Tiếp tục **TASK-035 — Identity + Principal + RBAC/ABAC**.

Theo roadmap, TASK-035 thuộc **M7 Enterprise**, là nền tảng bắt buộc trước TASK-036 Multi-Tenancy. Master specification hiện chỉ định nghĩa mục tiêu ở mức ngắn; vì vậy phần dưới là **structured expansion**, không phải lịch sử implementation.

## 2. Mục tiêu

Xây **Identity & Authorization Foundation** cho AIOS để mọi execution có thể xác định:

`Who → Tenant → Role/Attributes → Action → Resource → Policy → Decision`

Không thay thế `Permission Service` hoặc `Policy Service`; TASK-035 bổ sung **identity context** làm input cho chúng.

Invariant mới của M7:

* **INV-022 — Identity First:** mọi execution phải có `Principal`.
* Authorization phải **fail-closed** khi identity/authorization context không đầy đủ.

## 3. Scope

### 3.1 Principal Contract

Chuẩn hóa 5 loại principal:

```text
User
Service
Agent
Workflow
System
```

Contract tối thiểu:

```yaml
principal:
  id: user-123
  type: user
  tenant_id: company-a
  roles:
    - developer
  attributes:
    department: IT
    environment: development
```

Các field chính:

| Field         | Ý nghĩa            |
| ------------- | ------------------ |
| `id`          | định danh duy nhất |
| `type`        | loại principal     |
| `tenant_id`   | tenant sở hữu      |
| `roles`       | RBAC roles         |
| `attributes`  | dữ liệu cho ABAC   |
| `metadata`    | thông tin mở rộng  |
| `auth_source` | nguồn xác thực     |

`tenant_id` được thiết kế ngay từ TASK-035 để TASK-036 có thể mở rộng tenant boundary mà không phải thay đổi Principal Contract.

## 4. Identity Context

Mỗi request/execution phải mang identity context:

```text
Request
  ↓
Identity Resolver
  ↓
Principal
  ↓
Authorization Context
  ↓
Policy / Permission
  ↓
Execution
```

Không cho phép component tự suy đoán identity từ request payload.

### Authorization Context

Nên chứa tối thiểu:

```text
principal
tenant
roles
attributes
resource
action
environment
delegation
requested_capabilities
```

Ví dụ:

```yaml
authorization:
  principal: user-123
  tenant: company-a
  action: filesystem.write
  resource: project-x/src/main.py
  environment: development
```

## 5. RBAC

RBAC xử lý quyền theo role.

Ví dụ:

```yaml
roles:
  developer:
    permissions:
      - filesystem.read
      - filesystem.write
      - git.read
      - git.write

  reviewer:
    permissions:
      - filesystem.read
      - git.read
      - review.execute
```

Không hard-code role vào Agent hoặc Tool.

Luồng:

```text
Principal
 → Role Resolver
 → Permission Set
 → Policy Engine
```

---

## 6. ABAC

RBAC không đủ cho enterprise.

ABAC phải hỗ trợ ít nhất:

```text
Subject
Resource
Action
Environment
```

Ví dụ:

```text
subject.department == "IT"
AND
resource.environment == "development"
AND
action == "filesystem.write"
```

→ `ALLOW`

Trong production:

```text
subject.department == "IT"
AND
resource.environment == "production"
AND
action == "filesystem.write"
```

→ có thể `DENY` hoặc `ASK` tùy Policy.

Điểm quan trọng: **ABAC evaluation thuộc authorization/policy layer**, không nằm trong Agent.

---

## 7. Delegation

AIOS có Agent và Workflow identity, nên cần hỗ trợ chuỗi:

```text
User
 ↓ delegates
Orchestrator
 ↓ delegates
Coder Agent
 ↓ requests
Capability
 ↓
Tool
```

Authorization phải giữ được **provenance của delegation**.

Ví dụ:

```yaml
delegation:
  actor: user-123
  delegate: agent-coder
  scope:
    - filesystem.read
    - git.read
  expires_at: ...
```

### Capability attenuation

Agent **không được nhận nhiều quyền hơn principal đã cấp**.

```text
User permissions
        ↓
Delegation
        ↓
Agent permissions
        ↓
Capability permissions
        ↓
Tool execution
```

Luôn:

`effective_permissions ⊆ delegated_permissions ⊆ principal_permissions`

---

## 8. Authorization Decision

Chuẩn hóa decision:

```text
ALLOW
DENY
ASK
```

Decision phải có reason và provenance:

```yaml
decision:
  result: DENY
  reason: role_missing
  principal: user-123
  action: filesystem.write
  resource: production/repo
  policy_version: policy-1.4
```

`UNKNOWN` không được tự động chuyển thành `ALLOW`.

## 9. Architecture Boundary

TASK-035 phải giữ nguyên architecture hiện tại:

```text
User / Service / Agent
        ↓
     Identity
        ↓
 Authorization
        ↓
 Policy / Permission
        ↓
 Orchestrator
        ↓
 Runtime
        ↓
 Capability
        ↓
 Tool
```

Không cho:

```text
Agent → Identity DB
Agent → Role DB
Agent → Policy DB
Agent → Credential
```

Agent chỉ nhận **authorization context/effective capability**, không tự thực hiện authorization.

# 12. Acceptance Criteria

TASK-035 chỉ PASS khi:

### AC-035-01 — Principal bắt buộc
Mọi execution hợp lệ đều có `Principal`.

### AC-035-02 — Principal types
Principal hỗ trợ `User / Service / Agent / Workflow / System`.

### AC-035-03 — RBAC deterministic
RBAC resolve permission deterministic.

### AC-035-04 — ABAC evaluate
ABAC evaluate được Subject/Resource/Action/Environment.

### AC-035-05 — Default deny
Authorization mặc định **deny** khi thiếu thông tin cần thiết.

### AC-035-06 — Delegation bound
Delegation không thể cấp quyền vượt principal.

### AC-035-07 — No direct storage access
Agent không truy cập trực tiếp Identity/Role/Policy storage.

### AC-035-08 — Decision provenance
Authorization decision có reason + provenance.

### AC-035-09 — INV-022 enforce
INV-022 được architecture test enforce.

### AC-035-10 — Regression M0–M6
Regression của M0–M6 PASS.

### AC-035-11 — No parallel control plane
Không tạo control plane song song.

### AC-035-12 — Evidence retrievable
Evidence của các authorization decision có thể truy xuất.

Roadmap xác định TASK-035 phải đi **trước TASK-036**, vì Identity + Tenant cần được đặt trước khi mở rộng execution boundary sang distributed/enterprise runtime.
