### 1. Mục tiêu chi tiết

TASK-043 xây **Public AIOS SDK** làm lớp developer-facing chính thức, giúp developer xây và tích hợp với AIOS mà **không phải truy cập trực tiếp implementation nội bộ của Runtime/Orchestrator**.

SDK phải dựa trên các contract public đã có, giữ nguyên nguyên tắc:

`Developer → SDK → Public Contract → AIOS API/Runtime`

Không được biến SDK thành một control plane mới.

### 2. Phạm vi

#### 2.1 Python SDK

Cung cấp API ổn định để developer tạo và sử dụng:

* Agent
* Tool
* Capability
* Skill
* Workflow
* Prompt
* Execution
* Artifact
* Event

Ưu tiên API declarative/decorator và type-safe contract.

Ví dụ định hướng:

```python
@aios.tool(...)
def run_python(...):
    ...

@aios.agent(...)
class CoderAgent(...):
    ...

@aios.workflow(...)
def code_review(...):
    ...
```

SDK chỉ mô tả/đăng ký component; việc execution vẫn thuộc Runtime.

#### 2.2 TypeScript SDK

Cung cấp client dùng chung cho:

* Dashboard
* VS Code Extension
* external integrations
* developer tooling

Không tạo một contract riêng khác với backend.

#### 2.3 Contract synchronization

SDK phải sử dụng cùng contract/schema canonical với backend.

Không cho phép:

```text
Backend Contract
      ↓
SDK tự định nghĩa schema khác
```

Mà phải là:

```text
Canonical Contracts
       ├── Python SDK
       ├── TypeScript SDK
       ├── REST API
       └── Extension
```

#### 2.4 Versioning

Public SDK phải có:

* SDK version
* contract version
* schema version
* compatibility metadata
* deprecation policy

Breaking change phải được phát hiện trước khi release.

### 3. Public API boundary

SDK **được phép**:

* tạo component theo public contract;
* register component;
* discover capability;
* submit workflow/execution;
* đọc execution state;
* lấy artifact;
* subscribe event;
* truy vấn health/evaluation.

SDK **không được phép**:

* truy cập trực tiếp Runtime Service implementation;
* bypass Policy;
* bypass Permission;
* gọi Tool implementation trực tiếp;
* truy cập database nội bộ;
* thao tác registry/storage nội bộ ngoài public API.

Điểm này kế thừa trực tiếp nguyên tắc architecture của AIOS: Worker/Agent không truy cập Runtime/Tool trực tiếp và mọi execution phải đi qua boundary được kiểm soát.

### 9. Acceptance Criteria

**AC-043-01 — Public boundary**

Developer có thể sử dụng AIOS qua SDK mà không import internal Runtime/Orchestrator implementation.

**AC-043-02 — Contract compatibility**

SDK sử dụng canonical AIOS contracts; contract mismatch bị reject.

**AC-043-03 — Python SDK**

Có thể define/register và execute một component hợp lệ qua public SDK.

**AC-043-04 — TypeScript SDK**

Có thể kết nối API và thực hiện các operation public cơ bản.

**AC-043-05 — Policy enforcement**

SDK request bị Policy deny phải nhận `PolicyDeniedError`; SDK không có đường bypass.

**AC-043-06 — Permission enforcement**

Permission-sensitive operation phải đi qua permission boundary.

**AC-043-07 — Offline**

Mock/local execution chạy được không cần external LLM/provider.

**AC-043-08 — Versioning**

Incompatible contract/version bị phát hiện deterministic trước execution.

**AC-043-09 — Error model**

Internal implementation errors không leak thành public API không kiểm soát.

**AC-043-10 — Regression**

Toàn bộ regression của M0–M7 PASS và không vi phạm architecture invariants.

Master specification quy định acceptance chung của TASK-043 là task AC PASS, regression các milestone trước PASS và không vi phạm invariant.
