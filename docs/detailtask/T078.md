## TASK-078 — Verification Integrity / Fail-Closed Gate

**Mục tiêu**

Hoàn thiện **Verification Integrity** — đảm bảo mọi verification (T030) và evaluation (T032) có tính toàn vẹn (integrity) và luôn vận hành **fail-closed**: verdict không xác định / không thể verify → KHÔNG promote thành PASS. TASK-078 là **integrity + fail-closed gate, không phải verification engine mới** (dựa trên Harness T030/T032).

TASK-078 thuộc **M11**, ngay sau T077 (reserved). Trọng tâm canonical: **Verification Integrity / Fail-Closed Gate**.

### 1. Phạm vi — Integrity gate, không replace harness

```text
Verification Integrity
├── Evidence integrity    (hash / signature, T001 Rule 5)
├── Verifier integrity    (verifier version + config locked)
├── Fail-closed verdict   (UNKNOWN/INCONCLUSIVE -> not PASS)
├── Tamper detection      (evidence altered -> reject)
└── Provenance lock       (chain complete)
```

* **Integrity Check** — mọi evidence/verdict có content_hash; thay đổi → reject.
* **Verifier Lock** — verifier version + config được khóa cho mỗi evaluation run.
* **Fail-closed** — không verify được → INCONCLUSIVE → không promote.

### 2. Integrity Contract

```text
IntegrityReport
├── evidence_id
├── content_hash (sha256)
├── verifier_version
├── verifier_config_hash
├── tampered: bool
└── evidence_ref
```

Quy tắc:

* Evidence bị sửa (hash không khớp) → reject (fail-closed).
* Verifier version/config thay đổi giữa run → đánh dấu, không so sánh sai.
* UNKNOWN/INCONCLUSIVE → KHÔNG promote thành PASS (Rule 5, T060).

### 3. Integrity Safety

* **Fail-closed** — không verify được → không PASS.
* **Tamper reject** — evidence sửa → reject.
* **Verifier lock** — version/config khóa per run.
* **Deterministic** — cùng evidence + cùng verifier → cùng verdict.
* **No parallel integrity system** — dùng Harness (T030/T032) + Evidence (T001).

### 4. Deliverables

* Integrity Check (hash/signature) cho evidence + verdict.
* Verifier Lock (version + config per run).
* Fail-closed gate (UNKNOWN/INCONCLUSIVE → not PASS).
* Tamper detection + provenance lock.
* Integration với Harness (T030/T032) + Evidence (T001) + Evaluation (T060).
* Unit + Contract + Integration + Architecture + Regression tests.
* ADR/docs khi task yêu cầu.

### 5. Acceptance Criteria

TASK-078 chỉ PASS khi:

* Mọi evidence/verdict có content_hash; thay đổi → reject (fail-closed).
* Verifier version + config khóa per run.
* UNKNOWN/INCONCLUSIVE → KHÔNG promote thành PASS.
* Evidence bị sửa → reject (tamper detection).
* Cùng evidence + verifier → cùng verdict (deterministic).
* Provenance chain complete (T001 Rule 5).
* Tích hợp được với Harness + Evidence + Evaluation.
* Regression của các milestone trước PASS; không vi phạm invariants.
