**Vai trò:** Registry discovery trung tâm cho toàn bộ extension ecosystem.
Nguồn roadmap xác định TASK-046 là **“Registry discovery cho extension”**, với yêu cầu triển khai theo contract/invariant hiện có, có test và không tạo control plane song song. 

### 1. Mục tiêu

Xây **Ecosystem Registry** làm lớp registry chuẩn để AIOS có thể:

* Discover extension/plugin/skill/component bên ngoài Core.
* Đọc metadata và public extension contract.
* Search/filter theo capability, version, compatibility, platform và trust.
* Resolve extension version phù hợp.
* Kiểm tra compatibility trước khi extension được đưa vào runtime.
* Không cho registry trở thành nơi bypass Runtime, Policy, Permission hoặc Capability.

Kiến trúc:

```text
Extension
    ↓
Extension Contract
    ↓
Ecosystem Registry
    ├── Metadata Index
    ├── Version Index
    ├── Capability Index
    ├── Compatibility Index
    └── Trust/Certification Metadata
    ↓
Discovery / Resolution
    ↓
Plugin Runtime (TASK-044)
    ↓
Policy → Permission → Runtime
```

### 2. Phạm vi

#### 2.1 Registry Contract

Định nghĩa contract version hóa cho registry entry:

```yaml
extension:
  id: example.extension
  name: Example Extension
  version: 1.2.0
  type: skill
  description: ...
  author: ...
  license: ...
  capabilities:
    - example.capability
  dependencies: []
  compatibility:
    aios: ">=1.0,<2.0"
    contract: "1.x"
  platforms:
    - linux
    - windows
  trust:
    certification: certified
  artifact:
    checksum: ...
```

Các field phải có schema validation và versioning.

#### 2.2 Registration

Registry hỗ trợ:

```text
register()
update()
unregister()
get()
list()
search()
resolve()
```

Registration phải reject:

* ID trùng.
* Metadata không hợp lệ.
* Version không hợp lệ.
* Contract không tương thích.
* Artifact checksum không khớp.
* Extension vi phạm schema bắt buộc.

#### 2.3 Discovery

Cho phép discovery theo:

```text
extension_id
type
capability
version
AIOS compatibility
platform
trust/certification
author
tag
```

Ví dụ:

```text
search capability=database
→ postgres.skill
→ mysql.skill
→ sqlite.skill
```

Registry chỉ trả về **metadata/discovery result**, không tự execute extension.

#### 2.4 Version Resolution

Resolver phải hỗ trợ semantic version:

```text
requested: ^1.2.0

available:
1.0.0
1.2.0
1.3.0
2.0.0

→ resolve 1.3.0
```

Nếu không có version tương thích:

```text
RESOLUTION_FAILED
```

Không tự động downgrade/upgrade ngoài constraint.

#### 2.5 Compatibility

Registry phải kiểm tra tối thiểu:

```text
Extension version
AIOS version
Contract version
Schema version
Platform
Dependency constraints
```

Kết quả phải deterministic:

```text
COMPATIBLE
INCOMPATIBLE
UNKNOWN
```

`UNKNOWN` không được tự nâng thành `COMPATIBLE`.

#### 2.6 Trust Metadata

Registry lưu trạng thái trust/certification nhưng **không tự cấp quyền execution**.

Ví dụ:

```text
UNVERIFIED
VERIFIED
CERTIFIED
REVOKED
```

Trust metadata chỉ là input cho Policy/Certification pipeline.

### 5. Acceptance Criteria

#### AC-01 — Registration

Extension hợp lệ có thể đăng ký và retrieve bằng immutable ID.

```text
register → PASS
get(id) → same extension
```

#### AC-02 — Duplicate ID

```text
register(extension_id="x")
register(extension_id="x")
→ REJECT
```

Không overwrite âm thầm.

#### AC-03 — Discovery

Search theo capability/type/version phải trả về đúng extension phù hợp.

#### AC-04 — Deterministic Resolution

Cùng input + cùng registry state phải cho cùng resolution result.

#### AC-05 — Compatibility

Extension không tương thích AIOS/contract phải bị đánh dấu:

```text
INCOMPATIBLE
```

và không được resolution thành executable candidate.

#### AC-06 — Unknown ≠ Pass

Compatibility/trust thiếu evidence:

```text
UNKNOWN
```

không được tự động chuyển thành:

```text
PASS / CERTIFIED / COMPATIBLE
```

#### AC-07 — Checksum

Artifact metadata có checksum thì registry phải phát hiện checksum mismatch.

#### AC-08 — Policy Boundary

Registry không được bypass:

```text
Policy
Permission
Capability
Runtime
```

Registry discovery thành công **không đồng nghĩa extension được phép execute**.

#### AC-09 — Version Resolution

Resolver phải:

* tôn trọng version constraint;
* reject incompatible version;
* không tự ý chọn major version breaking.

#### AC-10 — Architecture

Architecture test phải đảm bảo Registry không trở thành execution/control-plane song song và không import trực tiếp implementation của Runtime/Tool.

#### AC-11 — Regression

Toàn bộ regression closure của:

```text
TASK-043
TASK-044
TASK-045
```

phải PASS trước khi TASK-046 được DONE.

### 8. Kết quả cuối TASK-046

Sau TASK-046, AIOS có:

```text
Extension
   ↓
Public Contract
   ↓
Ecosystem Registry
   ↓
Discover
   ↓
Validate
   ↓
Resolve
   ↓
Policy / Certification
   ↓
Plugin Runtime
```

**Registry trả lời “extension nào tồn tại và có tương thích không”; không trả lời “extension được phép chạy hay không”.** Quyết định execution vẫn thuộc Policy/Runtime boundary của AIOS. This preserves Runtime-First, Policy-First và Evidence-First.
